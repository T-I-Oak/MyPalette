# My Palette 開発環境

## 前提

- Node.js 22.12.0以上とnpm 10以上。初期確認環境はNode.js 25.6.1、npm 11.9.0。
- 共通リポジトリ `T-I-Oak/GameWorksOAK` を、このゲームと隣接する `../GameWorksOAK/` に配置する。
- 共通規約は[新規ゲームの環境構築手順](../../GameWorksOAK/docs/common/09.game_setup.md)から参照する。ゲーム側から共通部は編集しない。

## コマンド

ゲームのリポジトリ直下で、一つずつ実行する。

- 依存復元: `npm.cmd ci`
- 開発起動: `npm.cmd run dev`
- 全テスト: `npm.cmd test`
- 本番ビルド: `npm.cmd run build`
- ビルド確認: `npm.cmd run preview`

Viteのbaseは `/MyPalette/`、出力先は `dist/`。
ゲーム本体の入口は `/MyPalette/`。「ゲーム開始」で保存済み設定を読み込んで検証する。初日の仕事開始待ちになったら「今日の仕事を始める」を押してドローと開始処理を進める。一日の開始／終了はプレイエリア上端中央、ダイス更新はパレット下部の固定倍率層で操作する。捨て札は表向きの山として表示し、見えているカードだけ詳細を確認できる。信用が0になると、その日の日末処理後に仮のゲーム終了画面が表示される。「タイトルへ戻る」から新しいゲームを始められる。開発者用ツールはローカル開発サーバーの `http://127.0.0.1:3000/MyPalette/dev.html` から開く。
3000番ポートが使用中の場合は次の空きポートへ移り、その実URLを開く。
保存APIは同一Originの `/api/card-settings` を使うため、ホストは `127.0.0.1` を使用する。
プレビューではターミナルに表示されたURLの `/MyPalette/` を開く。既存素材は `public/assets/` に保持する。
バージョンは `package.json` を唯一の設定元とし、共通Env Utilityを通して確認画面に表示する。

## 構成

- `docs/requirements/`: オーナーが管理するゲーム要求仕様。オーナーの許可がある場合だけ変更する。
- `docs/spec/`: 実装仕様・データ構造・開発ツールの仕様。
- `docs/planning/`: バックログと開発フェーズの成果物。
- `src/`: 起動入口、スタイル、共通ライブラリ接続。
- `public/`: 既存画像などの静的素材。
- `scripts/`: 補助スクリプト。
- `tests/spec/`: ゲーム要求仕様の章に対応する受入テスト。
- `tests/implementation/`: 実装に対応するテスト。

## Gitと作業範囲

バージョンは `package.json` で管理し、正系ブランチは `master` とする。
ダイスとイーゼルはゲーム本体のパレット・プレイエリアで確認する。旧 `dev.html#dice`・`#easel` と開発者入口のゲーム開始ボタンは廃止済み。ダイスの単体・群APIは[ダイスコンポーネント仕様](spec/10.dice_component.md)を参照する。
開発者用入口にはカード設定（`#settings`）と共通アイコン確認（`#icons`）だけを置く。ゲームの操作・状態は[ゲームの実装仕様](spec/09.playable_game.md)、設定操作とJSON形式は[カード設定の実装仕様](spec/08.card_editor.md)を参照する。
編集後は「ゲーム設定を保存」でpublic/data/cards.jsonへ保存する。起動時はこの保存済み設定を読み込む。
効果評価のメタデータはdev-data/effect-evaluation.jsonへ別保存する。同じ保存操作で両ファイルを書き込み、設定画面だけが評価メタデータを読み込む。評価設定の取得・保存APIは `/api/effect-evaluation`。本番ビルドにはindex.htmlとdev.htmlの両方を含める。評価メタデータは静的配信対象に含めず、設定取得・保存APIはローカル開発サーバーでのみ利用できる。
JSONダウンロードは行わない。保存操作は127.0.0.1のローカル開発サーバーで利用する。
本番ビルドには保存済みの設定データが含まれる。設定を外部から取り替える場合はpublic/data/cards.jsonを差し替え、ページを再読込する。エディターはPC向けとする。
開発ブランチは計画フェーズでスコープ・バージョン・ブランチ名に合意してから作成する。
フェーズの開始合意・引継ぎ・終了コミットは[フェーズ作業手順](../../GameWorksOAK/docs/common/03.phase_workflow.md)に従う。Minor の下1桁が0になる新規開発では、[共通ワークフロー](../../GameWorksOAK/docs/common/03.workflow_guide.md#定期見直し)に従って定期見直しを行う。
公開設定、ポータル登録、CIは未設定。Gitのリモート設定は `git remote -v` で確認する。

## 検証

ストック表示は`checkStockArea.cjs`、初日・朝・日末演出は`checkStockMotion.cjs`、取得・返却操作は`checkStockAcquisition.cjs`、空ストック・連続交換は`checkStockEdgeCases.cjs`で検証する。各スクリプトに開発URLを渡す。取得・空ストック検証は環境変数`MYPALETTE_STOCK_MOTION=1`で演出あり、それ以外は動きを減らす設定を使用する。

オーナー確認で手札交換をすぐ試す場合は`node scripts/createStockReview.cjs`を実行し、開発URLの`tmp_stock_review.html`を開く。ページ内だけですべてのカードの着手時効果を手札交換1回に変える。仕事開始→任意の手札で着手→返却→取得の順に操作する。保存済み設定は変更しない。生成ページはGit追跡・本番ビルド対象外で、再生成できる。導線の確認は`checkStockReview.cjs <確認ページURL>`。

実装の終了草案を提示する前に、全テストと本番ビルドを実行し、コマンドと結果を実装報告に記録する。
ブラウザ確認用の補助スクリプトは `scripts/` に置く。Playwright はこのリポジトリの必須依存に含めない。
本番プレビューでは `node scripts/checkProductionStartup.cjs <プレビューURL>` でタイトル表示、設定エラー後の再試行、レイアウトA/Bでの翌日・ゲーム終了・再開始を確認する。
開発サーバーでは `node scripts/checkTitleMenu.cjs <開発URL>` でタイトルメニューが1・2・3項目のときの配置と、幅の拡大・縮小への追従を確認する。

`checkPaletteArea.cjs` は、初日の開始前とドロー後の両方で、効果説明アイコンを含む操作ボタン・タブがTab対象外であることを確認する。`checkEffectCommonUi.cjs` は説明のホバー・タップ操作と、Enter／Space／Escapeで開閉しないことを確認する。翌日の開始はストック演出終了とボタンの有効化を待つ。

### テストの責務と未検証範囲

`tests/implementation/` の単体テストは原則として対応ソースと同じディレクトリ・ファイル名とする。`game/` は進行・各エリアの配置、`game/easel/` は絵画投影、`ui/screenLayout/` は画面配置、`ui/areaTransition/` は移動基盤を扱う。複数モジュールの結合検証（ロール要求・日次開始・多ダイス等）は検証目的の名前を維持する。`devServer.test.js` はViteと保存APIの結合、`paintingImageSizes.test.js` は素材の寸法検証である。

| 要求仕様 | 現在の主な検証経路 | 残る検証範囲 |
| --- | --- | --- |
| `01.game_rules.md` | `tests/spec/rules_01_game_flow.test.js`、`tests/implementation/game/` | 固定seedの操作列は全操作順・全入力の網羅ではない。 |
| `02.visual.md` | ダイス・カード・ストック・達成演出の `scripts/check*.cjs`、素材寸法テスト | 見た目の全要求に対応する章別受入テストはない。各正式UIのオーナー確認を併用する。 |
| `03.information_and_interaction.md` | ゲーム接続・手札・ダイス選択・ストック取得のブラウザー検証 | 全公開情報・操作に対応する章別受入テストはない。所持ダイスの長押し6面確認、過去記録比較などの未実装範囲はバックログと照合する。 |
| `04.effect_conventions.md`、`05.icon_presentation.md` | `tests/implementation/icons/`、共通アイコン・効果説明のブラウザー検証 | 全効果・全パラメータの視覚要求を自動検証していない。 |
| `06.dice_effects.md`、`07.other_effects.md` | `tests/spec/effects_06_*.test.js`、`effects_07_game_other.test.js` | 論理と保存形式が中心。効果ごとの正式UIはEUI項目で扱う。 |

文書単位の表だけでは個々の要求の検証箇所を追跡できないため、バックログの `QA-01` で対象4文書の要求と検証の対応を確定する。章別テストファイルがないことだけを不足とは判断しない。固定seedの全操作順の網羅や未実装機能の開発はQA-01に含めない。検証スクリプトの成功を要求仕様全体の適合確認とは扱わない。

## 共通UIの実装仕様

ゲーム本体のレイアウトA/B、エリア倍率とCanvas解像度は[画面レイアウト制御](spec/14.screen_layout.md)を参照する。

配色変数・質感クラス・形状クラスの意味と利用契約は [ゲーム共通UIスタイル](spec/11.shared_ui_style.md) を参照する。

## 共通アイコンの確認

効果の共通通知・カード説明の本文、ホバー／タップ操作と通知キューは[効果の共通通知と説明](spec/16.effect_common_ui.md)を参照する。ブラウザ検証は `scripts/checkEffectCommonUi.cjs` と `scripts/checkEffectGameConnection.cjs` を使用する。

`/MyPalette/dev.html#icons` で、効果・目標アイコンを1件ずつ比較する。描画APIとレビューIDは [ゲーム共通アイコン](spec/12.shared_icons.md) を参照する。

ゲーム接続のブラウザ確認は `node scripts/checkGameConnection.cjs <開発URL>`。外部Playwrightのパスを `MYPALETTE_PLAYWRIGHT_MODULE`、ブラウザーを `MYPALETTE_BROWSER_CHANNEL` で指定する。レイアウト・開発者用2画面の回帰確認には `scripts/checkScreenLayout.cjs` を使用する。多ダイスの獲得・表示・ロール・破棄は `scripts/checkLargePalette.cjs` で確認する。

捨て札の表示・参照は`checkDiscardArea.cjs`、達成後・日末移動は`checkDiscardMotion.cjs`、デッキ不足時の3段階再構成は`checkRecycleMotion.cjs`で確認する。各スクリプトに開発URLを渡す。
ストックから捨て札への取得、補充との順序、発注後の日末回収は`checkStockDiscardMotion.cjs`で確認する。

実カード45枚の共通管理は[全エリア共通カード表示](spec/18.card_scene.md)を参照する。カード経路の通し検証は`checkCardScene.cjs`、枚数上限・空・固定倍率は`checkCardSceneLimits.cjs`。動きを減らす設定を維持した配置確定・撤去・日末・翌朝・出荷は`checkCardSceneReduced.cjs`。旧移動演出の確認コマンドは共通検証へ統合した。
