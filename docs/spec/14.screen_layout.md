# 画面レイアウト制御

## 責務と入口

`/MyPalette/` で保存済みカード設定を検証してゲームを起動し、7つのエリアへ配置する。パレットには3Dダイスを組み込む。
`src/ui/screenLayout/ScreenLayout.js` の `ScreenLayout.calculate(width, height, panelProgress)` は、正の表示寸法と0〜1のパネル進捗を受け取り、配置を計算する。幅が高さ以上ならA、縦長ならBとする。

各エリアは同じインスタンスを維持する。`CanvasArea` は `MoveArea` を継承し、正の標準寸法、受け取った論理寸法と背景のCanvas描画、および提供された固定倍率層への名前表示を担当する。エリアには標準でボーダーを付けない。位置・倍率・表示可否はレイアウトから受け取る。presentationを省略した評価用配置でも、同じGame・セッション・表示部品・操作処理を使用する。

## 分割とパネル

固定倍率の基準となる表示枠は540×540 CSS pxとする。レイアウトが実際の表示枠の幅・高さから `min(1, 幅 / 540, 高さ / 540)` を算出し、全エリアの固定倍率層と描画オフセットに共通で適用する。リサイズのたびに再計算する。

A/Bは実際の表示枠の縦横で選ぶ。高さの割り当て計算には表示枠の高さと `240 × 固定倍率` CSS pxの大きい方を使う。自動調整時は表示枠の高さに収まり、明示指定時には最低高さを確保する。低い画面でも手札の操作ボタン用オフセットを除いた有効な描画領域、正の倍率・論理寸法・カード配置枠を保持する。

`.LayoutScreen`を`overflow: auto`の表示枠とし、内部の`.LayoutContent`へ最低高さを保証したレイアウトを配置する。最低高さを下回った場合だけレイアウト全体をスクロール可能にする。各エリア内の配置をスクロールへ任せるものではない。背景・固定倍率層・拡縮層は同じ描画ルートに所属する。スクロール中も画面外のエリアは非表示や論理寸法0にせず、通常どおり配置・座標計算する。

画面基準座標は描画ルート内の座標とし、ビューポート変換の原点は描画ルートの現在の`getBoundingClientRect()`から取得する。スクロールイベントの反映を待たずに現在の座標を計算できる。所属層と移動層のDOM配置はビューポート座標を描画ルート内座標へ戻して行う。全体画面のポップアップは従来どおりdialogのトップレイヤーへ表示する。

| 配置 | 分割 |
| --- | --- |
| Aの左半分 | 情報表示・プレイ・パレットを上から1:3:2 |
| Aの右半分 | ストック・中央段・手札を上から2:2:2。中央段は捨て札・デッキを左右1:1 |
| Bのメイン | 情報表示・プレイ・パレット・手札を上から1:3:2:2 |
| Bのパネル | 上段にストック、下段に捨て札・デッキを左右1:1 |

描画ルート全体にアトリエの背景を敷き、Aでは中央、Bでは窓がある左側を基準にトリミングする。壁と床の境目はプレイエリアの描画枠の上から57%に合わせる。情報表示・プレイ・パレット・手札の背後にこの背景が見える。ストック・捨て札・デッキには3エリアを覆う1枚のコルクボードを正面から表示し、木枠と壁に落ちる影を付ける。Bではコルクボードが3エリアと同じ位置・進捗でスライドし、閉状態では非表示になる。コルクボードの範囲は背面への入力を遮る。背景に直接重なるラベルには質感クラス `texture-text-outline` を適用する。コルクボード上のエリア名とグレード・枚数は、質感クラス `texture-sticky-note` で付箋として表示する。「今日の仕事を終える」はプレイエリアのカードより手前、コルクボードより奥に表示する。

Bのパネルは幅85%、高さ60%で上端をプレイエリア上端に揃えて配置する。初期状態は閉じており、右端の32×64pxのタブで開閉する。タブの上端はストック上端に揃え、パネル左端に接してスライドし、閉状態は左矢印、開状態は右矢印を表示する。260msの線形スライドでメイン4エリアへ重なる。メインの位置・寸法は変わらない。動きを減らす端末設定では即時切り替える。Aへの切り替え中も開閉状態は保持する。

## 論理寸法と座標

エリアは`getLayoutRequirements()`で標準描画寸法`W × H`、左上オフセット`topLeftOffset`、右下オフセット`bottomRightOffset`をレイアウトへ渡す。オフセットは固定倍率適用前の非負の寸法とし、省略時は両軸0。標準寸法はプレイ600×300、パレット536×232（12個まで。13個以上では画像と物理範囲を√(個数/12)倍に広げた投影寸法から動的算出）、ストック993×546、捨て札300×200、デッキ351×557。手札はカード4枚と回転の余裕から求める1307×468とする。

情報表示はレイアウトA/B共通で、ロゴ、日数と名声値の二段、信用とチラシの二段、右寄せの出荷済みカンバスの順に横一列とする。名声値はアイコンの内側に表示する。ロゴは元画像の縦横比を保ち、カンバスの左辺とともに二段分の高さに揃える。標準寸法はゲーム状態に依存しない。信用行の基準は `[信用] x N`、チラシ行の基準は `[チラシ] x N [作成中] [未作成] x N` とし、各 `N` を3桁分確保して広い方を二段の標準幅に使う。表示形式は割り当てられた論理幅に合わせて選ぶ。4桁以上を集約する場合は文字サイズを下げて収める。

日数と名声値は幅66pxの生成りの作業日誌にまとめる。上段は `Day N` と表示し、`Day` を13px、数字を20pxとする。下段は共通の名声アイコン全体を34×34で描き、上段と同じ横中心に揃える。日数が進んだときは480ms、名声値が増えたときは320msで拡大して戻す。

信用は枚数分のアイコンを並べ、収まらなければ `x N` に集約する。チラシは完成済み、作成中、次回発注までの未作成の順に並べる。進捗があるときだけ作成中を1個表示し、その1枚分を未作成から差し引く。幅が不足したときは未作成のみ、完成済みのみ、両方の順で集約を試す。

チラシには `public/assets/` の `flyer-completed.png`、`flyer-in-progress.png`、`flyer-blank.png` を使う。元の880×1240のPNGを保持し、アイコン表示では縦横比を保って高さ24に縮小する。

日末のチラシ制作では、白紙または作成中のアイコンを情報エリアからプレイエリア中央へ運んで拡大する。画材ダイスのフロートアイコンを1個ずつ6時の位置へ飛ばし、時計回りに一周する間に絵柄を1段階進める。アイコンがダイスへ帰って吸収された時点でダイスを消費する。完成したチラシ、または最後のダイスで作成途中まで進んだチラシは、その画像のまま情報エリアに戻す。白紙から2個使って1枚を完成させるときは、1個目の処理後も同じチラシをプレイエリアに置く。

発注の準備では、消費対象の完成済みチラシアイコンを1回320msで拡大して戻す動きを3回繰り返し、消費後の枚数と新しい必要枚数を反映する。ダイスが残っていれば、反映後の白紙アイコンをプレイエリアへ運ぶ。ストック取得はチラシ制作、信用更新、ゲーム継続判定の後に行う。動きを減らす設定では、同じ処理順で表示を即時に更新する。

仕事を終了できる状態では、特殊面以外の未使用ダイスからチラシ用の2個を引き、その数だけ右端の信用アイコンを明滅させる。信用が0になる見込みでは赤い縁取りも付ける。`x N` 表記では信用が0になる見込みのときだけアイコンを明滅させる。日末はチラシ制作後に残ったダイスのフロートアイコンを170msで右端の信用アイコンから順に飛ばす。`x N` 表記では文字を着弾先にする。着弾時にフロートアイコンと対象を消し、破片を散らしてから信用を減算する。信用が増えたときは新しいアイコンを拡大して戻す。`x N` 表記では文字を拡大して戻す。動きを減らす設定では明滅を静的な薄い表示に替え、増減は即時に表示する。

出荷済みには透視投影したカンバス2枚分の幅を確保する。正面は左辺が右辺より長い台形とし、左側面に厚みを表示する。最新の作品を右端の手前に置き、2枚は横に並べ、3枚以上は同じ幅に均等にずらして重ねる。共通カードシーンの出荷先でステップ3の絵を表示し、カンバスから対応するカード詳細を開ける。

割り当て矩形`rect`の寸法を`w × h`、固定倍率を`f`とすると、描画矩形`drawRect`は原点`(rect.x + topLeftOffset.x × f, rect.y + topLeftOffset.y × f)`、幅`dw = max(0, w - (topLeftOffset.x + bottomRightOffset.x) × f)`、高さ`dh = max(0, h - (topLeftOffset.y + bottomRightOffset.y) × f)`となる。描画可能な場合、拡縮倍率はその後に`s = min(dw / W, dh / H)`、論理寸法は`dw / s × dh / s`として計算する。画面縮小などでどちらかの描画可能寸法が0になる場合は`drawable: false`とし、拡縮層の表示・操作・Canvas描画を停止する。この間の論理寸法は0、変換用倍率は1とし、0除算を行わない。固定倍率層は割り当て範囲で表示を継続し、描画領域が戻れば拡縮層を再表示する。

手札の左上オフセットは(0, 0)とし、右下オフセット(0, 40)で操作ボタン用の下部領域を確保する。捨て札とデッキは上部に36の名前用領域を確保する。ストックは上部36（エリア名32・余裕4。グレード・枚数表示は拡縮層の標準描画寸法に含め、固定オフセットに含めない）、下部40（後続のボタン36・余裕4）を確保する。情報エリアの外周余白は標準描画寸法に含める。固定倍率層は割り当て矩形全体を使い、Canvasと拡縮する内容ホストは描画矩形を使う。これにより上部の名前・下部の固定ボタンなどの領域を拡縮内容から分離できる。

### ストックの内容配置

エリア名は「ストック」。`stockLayout.js`は各グレード最大15枚を基準に、カード294×414、回転±1.5度、並進X±1・Y±0.45、厚み1.5、上部の持ち上げ余白24、グレード表示48と間隔4、上・左右の余白4、下端の影用余白22、山間隔32から標準寸法993×546を求める。標準寸法は現在枚数・公開状態では変えない。実際の論理幅では横の余裕に応じて山間隔を32〜64の範囲で広げ、上限に達した後は3つの山全体を中央寄せし、上下も最大15枚の山を中央寄せする。背景Canvasと内容ホストは透明とする。

ストックのカードは[全エリア共通カード表示](18.card_scene.md)が保持し、`stockLayout.js`の配置先で最下段から1枚ごとに1.5上へ積む。`stockPresentation.js`はラベルと操作を配置する。最上段もゲームの公開状態に従って表裏を決める。公開カードは既存の詳細画面を開ける。0枚ではそのグレードの山を描かず、列位置と枚数表示を維持する。「公開カードなし」は表示しない。

固定倍率層にはエリア名と、取得待ちのときの取得ボタンを表示する。「グレードA ○枚」形式のグレード・枚数（公開カードを含む）は拡縮層で各山の上に表示し、カードと同じ倍率で描く。文字は36px/48px、付箋はカード幅294の中央揃え。表示領域48と間隔4を標準描画寸法に含め、持ち上げ用余白24と分離する。下部40は取得ボタン用に確保する。表示更新はレイアウト購読へ接続し、A/B・パネル開閉・固定倍率・リサイズに追従する。検証は`node --test tests/implementation/game/stockLayout.test.js`と`scripts/checkStockArea.cjs <開発URL>`。

### ストックの状態変化と演出

手札交換の返却待ちはpending.kind=handReturnとする。プレイヤー向けではダイアログを使わず、手札下部固定倍率層の「着手」を「返却」に差し替える。返却後はストックの「取得」へ進む。ゲーム進行を止める選択待ちでは、操作可能な返却・取得ボタンにstate-attentionを付ける。通知・移動中の無効ボタンには付けない。

カードの移動・裏返し・残る手札の再配置は`cardSceneTimeline.js`で共通管理する。手札交換では返却カードを持ち上げて裏返し、ストックの左側へ運び、最下段へ下げて差し込む。裏返った後にステップ0へ更新する。取得後に次の公開カードをめくる。実カードは同じ要素を維持し、移動元と移動先を別に隠さない。

取得待ちはpending.kind=stockで識別する。プレイヤー向け表示では選択ダイアログを出さず、取得可能な山の下部固定倍率層に「取得」ボタン（24px/32px、高さ36）を置く。位置だけを山の中心へ合わせ、レイアウトの共通固定倍率に従う。ボタンは1枚選択を既存Game.chooseへ渡す。取得待ちへの遷移時はBパネルを開く。カードのタップは詳細確認として維持する。通知中・演出中・破棄後の操作は受け付けない。評価用表示は従来の選択ダイアログを維持する。

取得後に公開IDが変わった場合も補充カードの公開演出を行う。最後の発注後にそのまま日末へ進む場合は、補充の公開後に裏返し・最下段挿入を行う。初日の7枚を抜く際、残るカードは最下段を基準に位置を維持する。取得・手札交換の接続確認は`scripts/checkStockAcquisition.cjs <開発URL>`。環境変数MYPALETTE_STOCK_MOTION=1で演出ありを検証する。

ストック公開・日末更新も[共通カード表示](18.card_scene.md)の時間進行で実行する。朝は24持ち上げて裏返し、元の高さへ戻す。日末は裏返し・左への移動・最下段への下降・差し込みを進める。A/B/Cは120ms差、初日の7枚は90ms差で運ぶ。日末の手札回収中はストックの表示を保持する。

### デッキの内容配置と初日ドロー

共通カード表示は固定倍率層に「デッキ N枚」を表示し、背景Canvasと内容ホストを透明にする。裏面は既存の`Card`、カード寸法294×414、厚み1.5、回転±1.5度、並進X±1・Y±0.45をストックと揃える。捨て札と共通の標準描画寸法454×609は全45枚の厚み・持ち上げ24・周囲の余裕を含む。現在枚数では倍率を変えず、山を水平中央に置く。0枚では山を描かない。

初日はストックから90ms間隔で7枚を運び、到着ごとに最下段へ追加する。後から来るカードは先着カードの下に重なり、先着カード全体が1.5上がる。7枚の受け入れと既存のストック公開演出が完了した後、デッキから4枚を手札へ運ぶ。

`cardSceneTimeline.js`はゲームの`deckEvents`から受け入れ・再構成・ドロー順を読み、最上段を180msで24持ち上げ、360msで表返ししてから420msで手札の配置位置へ移す。開始間隔は660msとし、次の表返しが前の表返しと重ならないようにする。時間はオーナー確認で調整する。山の枚数表示は受け入れ時・最上段の取り出し時に更新する。デッキ不足時は、空のデッキから次の1枚を引く時点で再構成を待機する。捨て札の展開・中央への集約・デッキへの移動は[捨て札エリア](17.discard_area.md#デッキへの再構成)に従い、その完了後に残りのドローへ接続する。

日次・効果ドローにも同じ処理を使用する。持ち上げ・表返し中はデッキ内で保持しているカードごとの微小な位置ずれ・回転を維持し、飛行中に手札の位置ずれ・回転へ補間する。ストックからデッキへの到着時には、デッキ側の新しい値へ切り替えてよい。着手など先行演出を待つ間も、これから引く実カードはデッキ内に存在する。元と先のカードを複製・非表示にせず、同じカードを順番に運ぶ。残る手札の再配置も補間する。現在のエリア座標を毎フレーム読み、A/B・リサイズ・固定倍率・パネル開閉へ追従する。動きを減らす設定では最終状態を即時表示する。入口への復帰では移動表示と監視を解放する。ブラウザー検証は`scripts/checkDeckMotion.cjs <開発URL>`。

デッキのドロー時にBパネルが閉じている場合は自動で開かない。移動元は閉じたパネル内の現在のデッキ位置とし、カードは画面外から手札へ入る。パネルを開閉した場合は現在の移動元座標に追従する。

### 手札の内容配置

プレイエリアの正式表示は[プレイエリアの作品表現](15.play_area.md)に従い、標準寸法を作品数Nに応じた400N×640へ更新する。下部オフセットは(0, 40)、上部は0とし、固定倍率層には下部の達成ボタンと上端中央の「今日の仕事を終える」を置く。プレイエリア名と背景は表示しない。

プレイヤー向け手札は`handLayout.js`の配置先へ共通カード表示が描く。`handPresentation.js`は操作を配置する。手札のCanvas背景と内容ホストの背景は透明とし、既存の仮セクション背景も除く。評価用ゲームは従来の表示を維持する。

カード本体294×414、回転±1.5度、並進各軸±1の外接寸法を使い、周囲22、外接矩形間12の余裕を設けて4枚分の標準描画寸法を算出する。実際のカードの揺らぎは既存の配置状態を再利用する。論理幅に横並びで収まる場合は枚数にかかわらず同じ間隔で並べて手札全体を横方向に中央寄せし、収まらない場合だけ両端の余白を保って均等間隔で重ねる。0枚ではカードもボタンも表示しない。

プレイボタンは固定倍率層の下部に、日本語では「着手」、英語では`Start`と共通i18nを通して表示する。カードの論理中心Xを`cx`、拡縮倍率を`s`、固定倍率を`f`とすると、固定層での中心Xは`topLeftOffset.x + cx × s / f`となる。文字は24px/32px、ボタン高さは固定層の単位で36、paddingは上下0・左右12、幅は文字幅に合わせる。最大幅は隣のカード中心間隔から4を除いた幅に制限する。狭い場合は文言を省略表示するが、ボタンのアクセシブル名は維持する。リサイズ・固定倍率変更・カード枚数変更に追従し、既存の操作イベントと詳細表示へ渡す操作要素を再利用する。

画面基準座標は描画ルート内のCSSピクセル。共通倍率は1、ビューポートへの共通原点は描画ルートの現在位置とする。エリア内の矩形は `readScreenRect(localRect)` または `MoveArea.readTransform()` と共通変換関数で画面基準座標へ変換し、必要に応じて`surface.readViewportTransform()`でビューポート座標へ変換する。エリア倍率を親DOMへ重ねて適用しない。

パネル原点のX座標は `画面幅 - パネル幅 × 進捗`。閉じたエリアも画面右外の原点・寸法・倍率・配置枠を保持する。各アニメーションフレームでCanvasの表示位置とMoveAreaの変換を同期する。非表示時は表示・操作を無効にする。

## Canvasと画面追従

### 固定倍率層と拡縮層

プレイヤー向けの手札エリアではエリア名と枚数を表示せず、上端からカードの描画領域に使う。

レイアウト側は各エリアへ固定倍率のDOM層を提供し、`CanvasArea.fixedLayer`としてエリア側へ渡す。エリア側はこの要素に子要素を追加・更新でき、内部情報を表示できる。固定倍率は表示枠から自動算出し、`createLayoutScreen`の`setFixedScale(f)`で明示指定できる。変更時は各エリアのオフセット・描画矩形・拡縮倍率も再計算する。固定層の内部寸法は割り当て寸法を`f`で割り、表示時に`f`を一度適用する。エリア固有倍率やDPRは固定層の倍率へ重ねない。エリア名はCanvasからこの層へ移し、左上に表示する。エリア名は24pxとし、配置の余白・文字サイズなどの詳細はエリアごとに定義する。

固定倍率層は対応する拡縮層より上位に置く。メイン側の固定倍率層はパネル背景より下位、パネル側の固定倍率層はパネル内容より上位・移動層より下位とする。位置・表示寸法・表示可否は割り当て矩形と同期し、パネル開閉・A/B切替・リサイズに追従する。層の内容はエリア範囲でクリップし、層全体はスクロールしない。入力は既定で透過する。

固定倍率層には手札の着手ボタンを配置する。他エリアの操作ボタンは各エリアの正式実装時に定義する。ポップアップはこの層ではなく全体画面へ表示する。エリア自身の背景・内容は与えられたサイズ内へ描画する責務を持ち、機能としてスクロールが必要な場合はエリア内部に専用領域を設ける。

### 重なり順

メイン背景Canvas、メイン所属コンポーネント（z-index 1）、パネル背景Canvas（2）、パネル所属コンポーネント（3）、移動中コンポーネント（4）、つまみ（6）の順で重ねる。Aでもストック・捨て札・デッキはパネル側の層を使う。同じ共有描画面が所属エリアごとに描画ホストを選び、すべてのエリア間移動を共通の移動層で描く。層自体は入力を透過し、所属中で操作可能なコンポーネントだけが入力を受ける。パネル背景は背面のメインコンポーネントへの入力を遮る。

`createLayoutScreen` は `areas`、`surface`、`render`、`subscribe(listener)` を返す。subscribeはレイアウト適用後に通知し、返り値で購読解除する。エリア内へ配置したオブジェクトは、そのエリアの所属層で描かれる。

### 解像度

CanvasのCSS寸法はオフセットを除いた描画寸法とする。バッファー寸法は各CSS寸法×端末ピクセル比を整数に丸める。描画コンテキストへバッファー寸法÷論理寸法の変換を設定し、背景を論理座標で描く。名前は固定倍率層で表示する。

`ResizeObserver` で表示領域を監視し、描画フレームでDPRの変化を検出する。論理寸法またはバッファー寸法が変わったときに再描画する。位置だけの更新でも変換・表示位置を反映する。画面は100dvhに追従しページスクロールを発生させない。固定操作部はsafe areaを考慮する。ゲーム中の画面にバージョン表示は設けない。

## ゲームへの接続

- `src/main.js` がloadSettingsとgameIssuesで取得・構造・制作途中の不備を検証する。取得中、拒否理由、再読み込みを表示し、自動補完・設定の書換えはしない。
- `src/game/session.js` がGameインスタンスと操作受付・更新通知を担当する。評価用・プレイヤー向けのどちらも同じセッションを使用し、ゲームルールを表示側へ複製しない。
- `src/game/view.js` がセッションへ操作を渡し、現在状態から既存の表示部品と選択UIを更新する。描画先のpresentationを省略すれば従来の評価用配置になる。
- `src/game/layoutPresentation.js` がエリア別ホストをMoveObjectとして各CanvasAreaへ所属させる。進行情報はinfo、制作中と仕事の開始／終了操作はplay、画材ダイスはpalette、公開ストックはstock、山札枚数はdeck、捨て札カードはdiscard、手札はhandへ割り当てる。手札・プレイ・パレット・ストックの描画は各presentationへ委譲する。
- エリアの論理寸法を配置枠へ渡し、共有描画面が等方倍率を一度だけ適用する。内容ホストはpaddingを含めて割り当てサイズ内に収め、ホスト全体はスクロールさせず範囲外の描画をクリップする。各エリアは内容を与えられたサイズ内へ配置する。機能として必要なスクロールはエリア自身が内部の専用領域へ設定する。パネル非表示時は所属DOMを画面から除外するが、オブジェクト・選択は保持する。
- カード詳細と効果選択はルート側のダイアログとし、パネルやエリア倍率の影響を受けず表示する。
- 状態変更時は7エリアを同じGameの状態で更新する。配置・DPR・パネル開閉では表示だけを更新し、Gameの操作や選択リセットを行わない。選択待ちの制約はGameに従う。
- エリア別ホストの内容を破棄する際は、ホストを所有するpresentation.clearがアイコン監視を解放してからDOMを削除する。閉じたパネルのホストはルートDOMから外れるため、ルートに対する解放だけでは代用できない。再描画・presentation.disposeに共通適用する。
- プレイヤー向け表示は、手札からプレイエリアへの着手と達成時のエリア内演出を実装している。仮エリアとの間の移動は即時反映し、移動演出は対象外とする。評価用ゲームの既存の移動演出は維持する。正式エリア同士の移動と正式エリア内の演出を全7エリア完成後へ一律に延期しない。詳細は[プレイエリアの作品表現](15.play_area.md)を参照する。

追加のブラウザ検証は `scripts/checkGameConnection.cjs`。保存済み設定での進行と終了、通信を差し替えた検証用設定での連続候補選択・対象選択・達成・出荷・捨て札詳細を確認する。保存済みファイルは変更しない。

`scripts/checkIconCleanup.cjs` はGC-R01の回帰検証。縦長Bでパネルを閉じたまま12回更新し、ゲーム終了時の表示も確認する。ResizeObserverの登録対象を現在のDOMと非表示ホストの所有内容へ照合し、破棄済み対象の残存と現行対象の監視漏れがないこと、およびパネル再表示時のアイコン描画を検証する。

`scripts/checkHandArea.cjs`は本番と同じ表示・セッション・レイアウトのモジュールを使う検証ページで、手札0・4・6枚、重なった全カードのタップと拡大、状態を変更しないステップ参照、現在ステップ、A/B・タブレット・パネル、ダイス消費・リロール・面変更・破棄・再利用・獲得後の達成可能表示、選択待ちと仕事終了を確認する。検証用設定とセッションの参照は検証ページ内だけで保持し、本番のテスト用APIや保存済み設定の変更は追加しない。
