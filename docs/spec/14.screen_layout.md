# 画面レイアウト制御

## 責務と入口

`/MyPalette/` で保存済みカード設定を検証してゲームを起動し、7つのエリアへ評価用UIを仮配置する。正式なエリアデザインと3Dダイスは後続の開発で組み込む。
`src/ui/screenLayout/ScreenLayout.js` の `ScreenLayout.calculate(width, height, panelProgress)` は、正の表示寸法と0〜1のパネル進捗を受け取り、配置を計算する。幅が高さ以上ならA、縦長ならBとする。

各エリアは同じインスタンスを維持する。`CanvasArea` は `MoveArea` を継承し、正の標準寸法、受け取った論理寸法とフレーム・名前のCanvas描画を担当する。位置・倍率・表示可否はレイアウトから受け取る。既存の評価用ゲームは独立した入口と配置を維持し、同じGame・セッション・表示部品・操作処理を使用する。

## 分割とパネル

| 配置 | 分割 |
| --- | --- |
| Aの左半分 | 情報表示・プレイ・パレットを上から1:3:2 |
| Aの右半分 | ストック・中央段・手札を上から2:2:2。中央段は捨て札・デッキを左右1:1 |
| Bのメイン | 情報表示・プレイ・パレット・手札を上から1:3:2:2 |
| Bのパネル | 上段にストック、下段に捨て札・デッキを左右1:1 |

Bのパネルは幅85%、高さ60%で上端をプレイエリア上端に揃えて配置する。初期状態は閉じており、右端の32×64pxのタブで開閉する。タブの上端はストック上端に揃え、パネル左端に接してスライドし、閉状態は左矢印、開状態は右矢印を表示する。260msの線形スライドでメイン4エリアへ重なる。メインの位置・寸法は変わらない。動きを減らす端末設定では即時切り替える。Aへの切り替え中も開閉状態は保持する。

## 論理寸法と座標

割り当て寸法 `w × h`、標準寸法 `W × H` に対し、倍率は `s = min(w / W, h / H)`、論理寸法は `w / s × h / s`。標準寸法は情報表示600×100、プレイ600×300、パレット・ストック・手札600×200、捨て札・デッキ300×200。

画面基準座標はCSSピクセル。全画面ルートの左上がビューポート原点となり、共通原点は(0, 0)、共通倍率は1。エリア内の矩形は `readScreenRect(localRect)` または `MoveArea.readTransform()` と共通変換関数で画面座標へ変換する。エリア倍率を親DOMへ重ねて適用しない。

パネル原点のX座標は `画面幅 - パネル幅 × 進捗`。閉じたエリアも画面右外の原点・寸法・倍率・配置枠を保持する。各アニメーションフレームでCanvasの表示位置とMoveAreaの変換を同期する。非表示時は表示・操作を無効にする。

## Canvasと画面追従

### 重なり順

メイン背景Canvas、メイン所属コンポーネント（z-index 1）、パネル背景Canvas（2）、パネル所属コンポーネント（3）、移動中コンポーネント（4）、つまみ（5）の順で重ねる。Aでもストック・捨て札・デッキはパネル側の層を使う。同じ共有描画面が所属エリアごとに描画ホストを選び、すべてのエリア間移動を共通の移動層で描く。層自体は入力を透過し、所属中で操作可能なコンポーネントだけが入力を受ける。パネル背景は背面のメインコンポーネントへの入力を遮る。

`createLayoutScreen` は `areas`、`surface`、`render`、`subscribe(listener)` を返す。subscribeはレイアウト適用後に通知し、返り値で購読解除する。エリア内へ配置したオブジェクトは、そのエリアの所属層で描かれる。

### 解像度

CanvasのCSS寸法は割り当て寸法とする。バッファー寸法は各CSS寸法×端末ピクセル比を整数に丸める。描画コンテキストへバッファー寸法÷論理寸法の変換を設定し、フレームと名前を論理座標で描く。

`ResizeObserver` で表示領域を監視し、描画フレームでDPRの変化を検出する。論理寸法またはバッファー寸法が変わったときに再描画する。位置だけの更新でも変換・表示位置を反映する。画面は100dvhに追従しページスクロールを発生させない。固定操作部とバージョン表示はsafe areaを考慮する。

## 検証

- `node --test tests/implementation/ui/screenLayout.test.js tests/implementation/ui/canvasArea.test.js tests/implementation/ui/areaTransition.test.js`
- `scripts/checkScreenLayout.cjs` は外部のPlaywrightを利用し、A/B、境界、パネル途中位置、メインの固定、DPR 2、ページスクロールと開発者入口を確認する。モジュールパスは `MYPALETTE_PLAYWRIGHT_MODULE`、ブラウザーは `MYPALETTE_BROWSER_CHANNEL` で指定できる。
- `node --test tests/implementation/ui/*.test.js` は既定の描画層順序と所属先別ホストへの配置・除去・移動も確認する。
- `scripts/checkLayoutLayers.cjs` は仮ボタンの表示・クリック、パネルによるメイン部品の遮蔽、移動層、パネル開閉・リサイズ中の座標と到着先を確認する。

## ゲームへの接続

- `src/main.js` がloadSettingsとgameIssuesで取得・構造・制作途中の不備を検証する。取得中、拒否理由、再読み込みを表示し、自動補完・設定の書換えはしない。
- `src/game/session.js` がGameインスタンスと操作受付・更新通知を担当する。評価用・プレイヤー向けのどちらも同じセッションを使用し、ゲームルールを表示側へ複製しない。
- `src/game/view.js` がセッションへ操作を渡し、現在状態から既存の表示部品と選択UIを更新する。描画先のpresentationを省略すれば従来の評価用配置になる。
- `src/game/layoutPresentation.js` がエリア別ホストをMoveObjectとして各CanvasAreaへ所属させる。情報と仕事の進行はinfo、制作中はplay、画材ダイスはpalette、公開ストックはstock、山札枚数はdeck、捨て札カードはdiscard、手札はhandへ割り当てる。エリア別ホスト内の描画を後続で順に差し替える。
- エリアの論理寸法を配置枠へ渡し、共有描画面が等方倍率を一度だけ適用する。収まりきらない内容はエリア内部でスクロールする。パネル非表示時は所属DOMを画面から除外するが、オブジェクト・選択・スクロールは保持する。
- 出荷済み作品と進行記録は情報エリアのボタンから既存部品を使うダイアログで確認する。カード詳細と効果選択もルート側のダイアログとし、パネルやエリア倍率の影響を受けず表示する。
- 状態変更時は7エリアを同じGameの状態で更新する。配置・DPR・パネル開閉では表示だけを更新し、Gameの操作や選択リセットを行わない。選択待ちの制約はGameに従う。
- エリア別ホストの内容を破棄する際は、ホストを所有するpresentation.clearがアイコン監視を解放してからDOMを削除する。閉じたパネルのホストはルートDOMから外れるため、ルートに対する解放だけでは代用できない。再描画・再プレイ・presentation.disposeに共通適用する。
- 再プレイは旧表示のアイコン監視・移動処理・ダイアログ・イベント付きDOMを破棄し、新しいGameと選択状態で起動する。レイアウトとエリア別ホストは維持する。
- プレイヤー向け仮表示ではカード移動演出を省略して即時反映する。評価用ゲームの移動演出は維持する。正式な演出は各エリアの後続実装で扱う。

追加のブラウザ検証は `scripts/checkGameConnection.cjs`。保存済み設定での進行・終了・再プレイと、通信を差し替えた検証用設定での連続候補選択・対象選択・達成・出荷・捨て札詳細を確認する。保存済みファイルは変更しない。

`scripts/checkIconCleanup.cjs` はGC-R01の回帰検証。縦長Bでパネルを閉じたまま12回更新し、再プレイ・入口復帰と再起動も確認する。ResizeObserverの登録対象を現在のDOMと非表示ホストの所有内容へ照合し、破棄済み対象の残存と現行対象の監視漏れがないこと、およびパネル再表示時のアイコン描画を検証する。
