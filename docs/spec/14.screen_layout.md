# 画面レイアウト制御

## 責務と入口

`/MyPalette/` に7つの仮エリアを表示する。ゲーム進行・カード設定には接続しない。
`src/ui/screenLayout/ScreenLayout.js` の `ScreenLayout.calculate(width, height, panelProgress)` は、正の表示寸法と0〜1のパネル進捗を受け取り、配置を計算する。幅が高さ以上ならA、縦長ならBとする。

各エリアは同じインスタンスを維持する。`CanvasArea` は `MoveArea` を継承し、正の標準寸法、受け取った論理寸法とフレーム・名前のCanvas描画を担当する。位置・倍率・表示可否はレイアウトから受け取る。既存の評価用ゲームは独立した入口と配置を維持する。

## 分割とパネル

| 配置 | 分割 |
| --- | --- |
| Aの左半分 | 情報表示・プレイ・パレットを上から1:3:2 |
| Aの右半分 | ストック・中央段・手札を上から2:2:2。中央段は捨て札・デッキを左右1:1 |
| Bのメイン | 情報表示・プレイ・パレット・手札を上から1:3:2:2 |
| Bのパネル | 上段にストック、下段に捨て札・デッキを左右1:1 |

Bのパネルは幅85%、高さ60%で上端をプレイエリア上端に揃えて配置する。初期状態は閉じており、右端の32×64pxのタブで開閉する。タブの上端はストック上端に揃え、パネル左端に接してスライドし、閉状態は左矢印、開状態は右矢印を表示する。260msの線形スライドでメイン4エリアへ重なる。メインの位置・寸法は変わらない。動きを減らす端末設定では即時切り替える。Aへの切り替え中も開閉状態は保持する。

## 論理寸法と座標

割り当て寸法 `w × h`、標準寸法 `W × H` に対し、倍率は `s = min(w / W, h / H)`、論理寸法は `w / s × h / s`。標準寸法は情報表示600×100、プレイ600×300、パレット・ストック・手札600×200、捨て札・デッキ300×200。

画面基準座標はCSSピクセル。全画面ルートの左上がビューポート原点となり、共通原点は(0, 0)、共通倍率は1。エリア内の矩形は `readScreenRect(localRect)` または `MoveArea.readTransform()` と共通変換関数で画面座標へ変換する。エリア倍率を親DOMへ重ねて適用しない。

パネル原点のX座標は `画面幅 - パネル幅 × 進捗`。閉じたエリアも画面右外の原点・寸法・倍率・配置枠を保持する。各アニメーションフレームでCanvasの表示位置とMoveAreaの変換を同期する。非表示時は表示・操作を無効にする。

## Canvasと画面追従

CanvasのCSS寸法は割り当て寸法とする。バッファー寸法は各CSS寸法×端末ピクセル比を整数に丸める。描画コンテキストへバッファー寸法÷論理寸法の変換を設定し、フレームと名前を論理座標で描く。

`ResizeObserver` で表示領域を監視し、描画フレームでDPRの変化を検出する。論理寸法またはバッファー寸法が変わったときに再描画する。位置だけの更新でも変換・表示位置を反映する。画面は100dvhに追従しページスクロールを発生させない。固定操作部とバージョン表示はsafe areaを考慮する。
