# カード設定の実装仕様

## 1. 対象と基本情報

45枚のカード定義を編集し、ゲーム実装・バランス調整に利用する。
ゲーム進行、達成判定、効果の実行は本画面の対象外。

- IDはA01～A15、B01～B15、C01～C15で固定。先頭文字がグレードを表す。
- カード名は編集可能。初期値はオーナー提供の45作品のタイトル。
- メタ情報は絵筆・パステル・エアブラシと、橙・黄・緑・青・紫・赤の使用有無。
- メタ情報の初期値はオーナー提供の一覧に従う。目標と効果の画材・色の選択肢はメタ情報で使用ありの項目に限る。効果の補色は2色とも使用ありの組だけを選択できる。
- 初期値の定義はsrc/initialCards.js。画像の編集項目は設けない。

## 2. ステップと目標

ステップ0・1・2それぞれに達成目標、プレイ時効果、達成時効果を設定する。
ステップ3は出荷済みであり、設定対象外。

達成目標はダイス1個に対する条件を並べた配列で表す。
各条件は画材のみ、色のみ、画材と色の両方のいずれか。
両方を指定すると、その画材と色の組合せを持つダイスが必要となる。
画材・色を併記する入力欄と一覧は、画材→色の順に統一する（例：パステル＋青）。
目標の画材・色セレクターには、メタ情報で使用ありの項目と「未指定」だけを選択可能として表示する。
メタ情報の変更は目標の候補へ即時反映する。メタに含まれなくなった既存目標の値は勝手に削除しない。
対象外の既存値は「メタ対象外」として選択不可の表示を残し、該当欄の警告と要確認件数から修正箇所を確認できる。
効果の画材・単色・補色にもメタ情報による候補制限を適用する。候補外になった既存の効果値は自動変更せず、「メタ対象外」として選択不可の表示で残す。
ANDでつないだ条件は別々の未使用ダイスで満たす。同じ条件を複数並べることもできる。
「目標を追加」で目標設定ダイアログを開き、画材・色を設定して「確定」で追加する。
AND／ORは追加・編集ダイアログの「直前の目標との結合」で指定し、OR専用の追加ボタンは設けない。
既存の目標アイコンをクリック、またはEnter・Spaceで開くと現在の値を編集できる。
2件目以降はダイアログ内で直前とのAND／ORを切り替えられる。先頭にORは設定しない。
削除は編集ダイアログ内で行う。ORから始まる組の先頭を削除すると次の目標へORを引き継ぐ。
キャンセルとEscapeは変更を反映せず閉じる。末尾の区切りだけを追加する操作は設けない。
例えば「目標1 目標2 | 目標3 目標4」は、(目標1 AND 目標2) OR (目標3 AND 目標4)を意味する。
ORで区切った組のうち、いずれか1組を満たせば達成する。一覧・編集画面の式は共通アイコンで示し、ANDの表記は入れず、ORを縦棒「|」で表示する。
1～4個程度を想定するが、個数の上限は設けない。

## 3. 効果

プレイ時・達成時とも複数の効果を指定できる。配列の先頭から順に処理する。
追加・削除・上下への並べ替えができる。
初期状態の効果配列は空（効果なし）。

ダイス関連効果仕様・その他の効果仕様に定義された全種類を指定できる。
フォームの項目と検証規則はsrc/effectCatalog.jsで共有する。
「効果を追加」でダイアログを開き、種類・パラメータを選んで「確定」で追加する。
通常画面には設定済みの効果をアイコンで並べ、入力欄を常設しない。
アイコンをクリック、またはEnter・Spaceで開くと現在値を編集できる。
種類変更時は以前のパラメータを除去し、新しい種類の入力欄を表示する。
回数・個数・枚数・名声の増減値の初期値は1、選択項目は未設定とする。既存設定の値は補完しない。
削除と実行順の上下移動は編集ダイアログ内で行う。順序変更と入力内容は「確定」でまとめて反映する。
キャンセルとEscapeは追加・入力・順序の変更を反映せず閉じる。

- ダイス獲得：通常／色指定／画材指定、永続／一時、個数。
- 使用済みダイスの再利用：追加パラメータなし。所持する全使用済みダイスを出目を維持して使用可能へ戻す。
- リロール権獲得：回数。即時リロール：追加パラメータなし（実行時に未使用ダイスを1個以上、任意の数選ぶ）。
- 面変更：6色のうち1色、画材、または特殊面10種類のいずれか。色変更はcolorで単色を保存する。
- ダイス破棄：1以上の整数の個数。特殊面の即時適用：追加パラメータなし。
- 名声値変更：0以外の整数。ドロー、ストック獲得、手札交換：1以上の整数。
- 手札のステップ変更：0・1・2の絶対値。

手札交換のcountは交換回数。1回ごとに手札1枚を同グレードのストックの一番下へステップ0で戻し、公開カード1枚を手札へ取得する。

## 4. 保存・読込と未設定

JSONのルートはcards配列だけを持つ。cardsは固定ID45件を過不足なく含む。
カードのキーはid、name、metadata、steps。
metadataはmaterialsとcolorsに、対応する画材・色をキーとする真偽値を持つ。
stepsは3件。各要素はgoals、playEffects、achievementEffectsの配列を持つ。
goalsの要素はcolor、material（未指定はnull）。
2件目以降は直前の目標との結合をjoin: "and"／"or"で指定できる。joinの省略はANDを意味する。
先頭の目標にはORを指定しない。先頭の目標を削除した際は、新しい先頭からjoinを除去する。
効果の要素はtypeと、その種類のパラメータを持つ。

ゲームの処理に使う識別子と、日本語の表示ラベルを分離する。
カード名は作品タイトルとして日本語を保持するが、以下の属性はコードで保存する。

| 対象 | 保存するコード |
| --- | --- |
| 画材 | brush / pastel / airbrush |
| 色 | orange / yellow / green / blue / purple / red |
| 補色 | red_green / orange_blue / yellow_purple |
| 所持期間 | permanent / temporary |
| 特殊面 | fame1 / draw1 / reroll1 / temporaryNormal1 / temporaryRedGreen1 / temporaryOrangeBlue1 / temporaryYellowPurple1 / temporaryBrush1 / temporaryPastel1 / temporaryAirbrush1 |

metadataのキー、目標のcolor・material、効果のcolor・colors・material・lifetime・faceはいずれも上記コードを用いる。
画面はeffectCatalog.jsのLABELS・displayLabelで日本語に変換する。ゲームの判定に表示ラベルを用いない。
補色の具体的な2色はCOLOR_PAIR_COLORS、特殊面の効果定義はSPECIAL_FACE_EFFECTSから構造化データとして参照する。
ゲームと設定データは同じプロジェクトで管理する。形式番号や旧形式の互換変換は設けず、現在のデータ構造を直接検証する。

制作途中でも保存できる。空の名前、空の目標配列、両属性未指定の目標、
効果パラメータのnullを未設定として保持し、画面で制作途中として示す。
既存ファイルの種類未設定効果は{"type":null}で保持する。ダイアログから新規追加するときは、成立する設定だけを確定できる。
空の効果配列は効果なしとして扱う。
入力済みの値が仕様に反する場合は、カードID・ステップ・項目と理由を表示する。
未知のキー、未知の効果、項目欠落、ID重複も拒否する。
整数はJavaScriptで精度を保てる安全な整数に限る。

JSON内のカード順は任意。設定の外部からの取替えは、設定ファイルを差し替えてページを再読込する。
ゲーム用設定ファイルはpublic/data/cards.jsonを正本とする。
保存時は各ANDブロック内の目標を、第1キー画材（brush、pastel、airbrush、null）、第2キー色（orange、yellow、green、blue、purple、red、null）の昇順で並べ替える。
その後、ORブロック同士を並べ替え済みの目標列の辞書順で比較して並べる。同じ接頭辞で長さだけ異なる場合は短いブロックを先にする。
OR境界・重複目標・未設定値は保持する。効果の実行順やカードの並び順はこのソートの対象に含めない。
保存に成功すると編集画面・一覧にもソート結果を反映する。保存失敗時は編集状態を変更しない。
起動時はこのファイルを検証して読み込む。読込失敗時は初期値で上書きせず、理由と再読込操作を表示する。
ローカル開発サーバーで「ゲーム設定を保存」を押すと、検証後に同ファイルへ45枚を一括保存する。
書込みは一時ファイルからの置換で行い、失敗時は編集内容と既存設定を保持する。
別画面が保存した後の古い版による上書きは競合として拒否する。
保存APIは127.0.0.1の同一Originからだけ利用でき、公開ビルド・previewには書込み機能を提供しない。
本番ビルドには保存済みcards.jsonを含める。ゲーム進行の実装でもこの設定ファイルを利用する。
JSONダウンロード・取込機能は設けない。
未保存の変更がある場合はページ離脱時にブラウザ標準の確認を要求する。

## 5. 表示と操作

画面上部にバージョン、ゲーム設定保存・検証操作を表示する。
起動時は45枚を比較できる全体一覧を表示する。
一覧にはID、名前・メタ情報、ステップ0～2の目標・プレイ時効果・達成時効果を表示し、
各効果の補色・画材・個数などの詳細条件も併記する。表の内部で縦横にスクロールできる。
一覧は1カード1行。各ステップの目標・プレイ時・達成時を別々の列とし、繰り返しの項目名は列見出しに集約する。
初期表示では長いセルを省略し、マウスを重ねると全文を表示する。
「詳細を折り返す」で全セルの全文を折り返して表示できる。空配列は「目標なし」「効果なし」と表示する。
タイトル・ファイル操作・表示切替・件数をコンパクトにまとめる。状態メッセージは必要なときだけ画面右下に重ね、一覧や編集領域の高さを変えず、閉じる操作を付ける。
IDを押すとそのカードの編集へ移り、「全体一覧」で最新の編集内容を一覧へ反映して戻る。
PCではカード一覧と詳細を左右に配置し、それぞれ内部スクロールする。
右ペインはID・カード名・未設定件数を1行にまとめ、画材と色のメタ情報を横並びにする。
横にステップ0・1・2、縦に目標・プレイ時効果・達成時効果を並べる3×3のグリッドとする。
同じ種類の入力領域は行の高さをそろえる。狭いペインでも3列を維持し、内部の横スクロールで編集する。
説明文は常時表示せず必要な補足はツールチップにまとめる。未設定の詳細は未設定件数のツールチップから確認する。
目標の画材・色・削除を1行に置き、繰り返しのラベルと余白を抑える。
エディターはPC向けとし、狭い画面幅への対応は対象外とする。
ページ全体はスクロールせず、詳細内部でステップ0～2を編集できる。

## 6. 目標の達成確率

各ステップの目標について、通常ダイスN個とリロール権1回で達成できる確率を一覧・編集画面に表示する。
Nはグレード別に指定し、初期値A=4、B=5、C=6。画面内だけの設定であり、ゲーム用JSON・ブラウザ保存には含めない。
ダイス数の入力範囲は1～12個。空欄・範囲外はN未設定と表示する。

オーナー合意の近似モデルを用いる。

- 各ダイスの出目は画材3種×色6種の18通りが独立・等確率。
- 実際の6面構成の偏りと、カード効果は計算に含めない。
- 最初のロールで達成できれば成功。未達成時は任意の1個または全個を1回リロールし、成功率が最大となる選択を行う。
- ANDでつないだ目標を異なるダイスへ割り当て、ORで区切った組のいずれかが達成可能なら成功とする。同じ組内でダイスの重複使用は不可。
- 目標なし・未設定条件ありは「—」、すべての組で目標数がダイス数を超える場合は0%。小数点以下1桁で表示する。

目標に対する適合パターンで出目を集約し、多項分布の重みで初回ロールを列挙する。
各状態でリロールなしの成功、1個のリロール、全個のリロールを評価する。ORの成功率は組ごとの確率の単純加算ではなく、重複を含む同時達成も1回の成功として扱う。乱数試行は使わない。
計算はWeb Workerで実行し、同じ目標・Nの結果を共有する。N変更や目標編集後は新しい条件の結果だけを表示する。
列挙状態が50万を超える場合は「計算不可」と表示し、説明にダイス数を減らすよう示す。

## 6. アイコン表示

一覧の目標・プレイ時効果・達成時効果、編集画面の目標と各効果を `src/cardIcons.js` で表示する。
描画は `src/icons/render.js` の共通APIを使い、効果は設定順にアイコンを並べ、番号と矢印は付けない。
説明は `cardSummary.js` の表現を使い、ホバーとキーボードフォーカスで同じツールチップを表示する。
各アイコンのアクセシブル名からも説明を読める。Escapeで説明を閉じる。
キャンバスは縦横比を維持し、一覧では横スクロールまたは「詳細を折り返す」で内容へ到達する。
空配列は「目標なし」「効果なし」とする。
設定の完成状態を再検証する処理や、既定値・代替アイコンでの補完は設けない。
設定が不十分な場合はアイコン描画の失敗を許容する。描画をフォーム生成から分離し、入力・削除・修正を続けられるようにする。
ダイアログで確定すると該当アイコン・説明・目標確率を更新し、一覧へ戻る際にも現在の設定を表示する。

一覧は複数カードのステップ0～2を同時に比較することを優先する。
表は画面幅に合わせて配置し、最小幅960px、一覧内アイコン高22px、セル余白2px×3pxとする。
カード名・メタ情報の列幅を抑え、入口へ戻る操作を見出し行へ置いて一覧の表示領域を確保する。

編集画面はステップ0～2の各列に目標・プレイ時・達成時を並べる。各区画にはアイコンと追加操作だけを置く。
カード名・メタ情報は画面上で編集し、目標・効果の詳細入力はモーダルダイアログで行う。

## 7. ダイアログの確定条件

確定ボタンはフォームが入力条件を満たした場合だけ有効にする。
目標は画材・色の少なくとも一方を指定し、指定した属性がカードのメタ情報に含まれること。
効果は種類と全必須パラメータを指定する。画材・単色・補色はメタ情報で許可された候補から選ぶ。
数量は1以上、名声の増減は0以外の安全な整数とし、小数・空欄・安全な整数範囲外では確定できない。
追加パラメータのない効果は種類の選択だけで確定できる。
制御は編集フォームのrequired・min・max・stepとカスタム妥当性メッセージで行い、ゲーム本体に完成状態判定を追加しない。
既存の制作途中設定は読み込み可能とし、編集ダイアログ内で修正できる。削除とキャンセルは無効化しない。

## 8. カード難易度

各ステップの目標達成確率p0・p1・p2を使い、難易度を`1/p0 + 1/p1 + 1/p2`で計算する。
値は目標条件だけから見た期待試行回数の合計であり、低いほど容易。カード効果や実際の完成ターン数は含まない。
既存の確率計算と同じグレード別ダイス数を使い、別のダイス数へ揃える処理は設けない。
計算には表示用に丸める前の確率を使い、難易度は小数点以下2桁で表示する。
編集画面はカード名の右、一覧は色列とステップ0の間の「難易度」列へ表示する。
目標編集の確定・カード切替・一覧復帰・計算用ダイス数変更で表示を更新し、既存のWorkerと計算結果キャッシュを共有する。
未設定の目標があれば「—」、確率0を含む場合は「達成不可」、処理中は「計算中」と表示する。
ダイス数不正・計算規模超過・Workerの失敗は既存の達成率と同じ状態表示を使う。
難易度は表示専用で、カード設定JSONへ保存しない。

## 9. 効果の評価設定

「効果の評価設定」画面で、効果の種類ごとにプレイ時・達成時の評価点を独立に編集する。
特殊面への変更だけは特殊面10種類ごとに分ける。評価点の初期値は0。
通常・色指定・画材指定のダイス獲得は一時／永続ごとに分け、各時機で独立の評価点を設定する。キーはgainNormalDice.temporaryなどとし、カード効果のlifetimeで参照する。評価項目は計28件。
ステップ0～2の倍率は全カード共通で、初期値は各1。評価点・倍率は有限な小数・負数を指定できる。
数量countのある効果は数量倍、名声値変更は符号付きamount倍、その他は1回分として計算する。
カードの評価点は各ステップの「（プレイ時効果の合計点＋達成時効果の合計点）×倍率」の総和とする。
編集画面のカード名右と一覧の難易度右に小数点以下2桁で表示し、設定変更時に更新する。
必要な計算値が未設定なら「—」とし、0で補完しない。

評価設定は開発専用データとして `dev-data/effect-evaluation.json`へ保存する。
構造はstepMultipliers（3要素）、playEffects・achievementEffects（効果キー別評価点）。
特殊面変更のキーはchangeSpecialFace.fame1など、種類と特殊面をピリオドで結合する。
カード設定public/data/cards.jsonには混在させず、算出した評価点も保存しない。ゲーム本体では読み込まない。
「ゲーム設定を保存」で両ファイルを保存し、設定画面を開くとそれぞれ読み込む。
評価設定の不正入力は書込み前に拒否する。カード保存後に評価設定保存が失敗した場合は、カードだけ保存済みと表示して再試行可能とする。
保存では、読み込んだ値または直近の保存値から変更のあるファイルだけを書き込む。書き込むファイルが別の画面で更新されていた場合は、カード設定・評価設定ともに書込みを拒否し、画面上のメッセージで知らせる。編集中の入力は画面に残る。

操作バーは折り返さず1行とし、表示領域の高さを維持する。幅が不足する場合は横スクロールする。
独立した「入力を検証」ボタンは置かず、保存時の検証を使用する。
評価設定の効果項目は共通効果アイコンで表示し、ホバー・フォーカスで項目名を示す。
特殊面変更以外は種類を表す代表例（数量1、属性等は先頭候補）のアイコンで、評価はその種類全体に適用する。
