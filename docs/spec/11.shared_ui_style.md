# ゲーム共通UIスタイル

## 適用範囲と所有

カード・ダイス・設定画面で共通に利用するCSSの契約。共通規約 `GameWorksOAK/docs/common/06.css_design_rules.md` に従う。
`src/ui/theme.css` が色変数の唯一の定義元、`src/ui/textures.css` が共通質感クラスの定義元。
共通形状は `src/ui/layout.css`、共通状態は `src/ui/states.css` で管理する。
`src/style.css` からこれらを読み込み、遅延ロードされる特定機能には依存させない。
利用要素は `theme-atelier` の子孫に置く。CSS変数は継承される。別テーマは同じ変数群を定義する。

## クラスの意味

| クラス | 意味と使い方 |
| --- | --- |
| `theme-atelier` | ゲーム全体の配色と基本書体を指定する最外周テーマ。 |
| `Surface` | 通常の区画やカードに使う1px実線・半径8pxの形状。色を持たない。 |
| `Button` | 共通の操作ボタン形状。カプセル型（半径999px）、1px実線、内容を中央に配置する。高さ・幅・余白は利用側で調整できる。色・塗り・影は持たない。 |
| `texture-raised` | 共通の押せる面。明るい紙色の塗り、深緑の文字と枠、浅い影で通常時から押せることを示す。`Button`と組み合わせる。色は既存テーマ変数を参照し、形状や寸法を持たない。 |
| `texture-paper` | 基本の紙面と境界色。カード・区画・通知で共有する。通常は `Surface` と組み合わせる。 |
| `texture-surface-muted` | 控えめな背景の面と境界色。リスト項目などの補助面。形状は利用側が与える。 |
| `texture-label-inverse` | 暗い面に明るい文字を置く短いラベル。ID専用ではない。 |
| `texture-primary` | 主要操作の面・文字・境界色とホバー。`Button` 等の操作形状と組み合わせる。 |
| `texture-artwork` | 背景から浮かせる画像の影。画材やダイスに限定しない。 |
| `texture-ground-shadow` | 下端で接地する物体の投影。`::before`に下端から離れるほど薄くなる影色とぼかしを与える。影の形・方向・大きさは利用側が指定する。 |
| `texture-callout` | SVG吹き出しの面・境界色と影。子のpathに塗りと線色を与える。形状・線幅は別に与える。 |
| `texture-floating` | 一時的に重なる面の背景・境界色・影。バッジ・通知等に使い、配置や丸みは別に与える。 |
| `state-consumed` | 対象が消費済みである状態。子の反転ラベルは使用済みの面色になる。機能固有の非表示等は利用側が定義する。 |
| `state-attention` | そのボタンを押すまでゲームが進行しないことを示す注目状態。`Button`と組み合わせ、進行を止めている操作のボタンへ付与する。有効・無効とは独立し、前提となる対象選択などが未完了でdisabledの場合も、停止理由が分かるよう拡縮を続ける。共通states.cssで1.6秒周期・等倍〜1.1倍の拡縮を行う。色・質感・配置は変更せず、独立したscaleを使って既存transformを保つ。無効時の配色と操作不可は維持し、動きを減らす設定では停止する。 |

機能クラスは構造や配置が異なる場合には分ける。同じ質感のために機能名を含むtextureクラスを増やさない。
例：カードは `GameCard Surface texture-paper`、検索通知は `DiceSearchSummary Surface texture-paper`。
構造が違っても紙面の定義は同じであり、一方に色のコピーを置かない。
特殊面の `state-special` など、機能固有の状態や形状は各コンポーネントの仕様で扱う。

## 利用と変更

ボタン（button要素・role=button）とカードのステップタブ（role=tab）は生成時に`tabindex="-1"`を指定し、Tabキーの順次フォーカス対象から外す。ゲーム本体、詳細ダイアログ、パネル開閉、開発者画面にも適用する。クリック・タップ操作は維持し、フォームの入力欄・選択欄のTab移動には変更を加えない。CSSによる見かけ上のフォーカス非表示やTabキー全体の抑止で代用しない。

通常の操作ボタンは`Button texture-raised`を使用する。主要操作は`texture-primary`を併用して面色を切り替えられる。形状はlayout.css、通常・ホバー・押下の面と影はtextures.css、無効状態はstates.cssに集約する。ホバーはホバー可能な端末だけに適用し、押下時は影を内側へ切り替える。無効時は控えめな面と文字に変更して影を除く。オーナー指定の共通方針に従い、キーボード操作・フォーカス表示を共通ボタンの機能として追加しない。装飾を状態ごとに機能CSSへ複製しない。

ゲーム・評価用ゲーム・開発者画面の通常操作に適用する。カードのステップタブとパネル開閉のつまみは、それぞれの役割に合った専用形状を維持する。共通Buttonの基準文字サイズは24pxとする。手札・プレイ・パレットの固定ボタンは24px/32px、高さ36、下余白4で揃える。手札の着手ボタンは高さ36、上下padding0・左右12、文字幅に合わせる設定を維持し、共通のカプセル形状と質感を使用する。

色の変更はテーマ変数、共通質感の変更はtextures.css、形状や配置の変更は機能クラスで行う。
有効な通常ボタンのホバー時は`--ui-primary`の背景と`--ui-on-primary`の文字を使い、押下時は`--ui-primary-hover`の背景へ変える。無効時のグレー系の面・文字と明確に区別する。ホバーによって無効ボタンの配色を変えない。
部品単位の色調整もまず共通の意味で表現できるか判断し、同義の変数を追加しない。
変数や共通クラスを追加・改名する際は本表と全利用箇所を同時に更新する。
透明度を含む色も変数の値として定義する。座標・寸法・時間から算出する透明度だけはJSの動的style指定を認める。

このCSS変数群はHTML/SVG UI用。Canvas画像・WebGLの材質や画材の論理色はCSSを自動参照しない。
それらの配色を変える場合は画像生成側の定義とキャッシュ更新が必要で、テーマ変更だけで変わるとは扱わない。
既存のstyle.css/view.cssには機能クラス内の質感指定が残るが、色値は本変数群を参照する。
既存クラス全体の責務分離が完了したことは意味しない。新しい共通質感の定義を機能側に複製してはならない。

## 追加：共通プレビュー面

| クラス/変数 | 意味 |
| --- | --- |
| `texture-surface-warm` / `--ui-surface-warm` | 明るい暖色の面。初期値は `--ui-on-primary` の配色を参照。図形の背景比較などに使う |
| `texture-surface-cool` / `--ui-surface-cool` | 明るい寒色の面。初期値 `#98d5ed`。暖色面と対にして比較できる |

どちらも共通境界色を使い、形状はSurface等と組み合わせる。特定のゲーム部品に限定しない。

`texture-highlight-frame` は注目させるSVGフレームの共通質感。`--ui-highlight-surface`（初期値 #f4df94）の淡い金色で塗り、`--ui-highlight-border`（#846735）で輪郭を描く。形状や用途は限定せず、特殊面の星型でもこの質感を使う。
