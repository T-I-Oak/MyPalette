# 全エリア共通カード表示

## 不変条件

ゲーム中の実カード45枚は、IDごとに同じCard・DOM要素を保持する。エリア間移動や再描画のために実カードを複製・再生成・非表示にしない。山の下、画面外、裏向きのカードも現在の姿勢を保持する。非表示の例外は達成時のカンバス演出だけとする。

拡大詳細・選択ダイアログ・出荷済み一覧のカードは閲覧用の参照表示であり、実カードの管理には参加しない。実カードには`data-scene-card`、その配置要素には`data-scene-id`を付ける。

## 責務

| モジュール | 責務 |
| --- | --- |
| `cardSceneState.js` | 全IDの個体、現在姿勢、透明度、動作の所有者、補間・中断。内部状態の検証はテスト側で行う。 |
| `cardScene.js` | CardとDOMの保持、表示内容・操作・描画、移動時間の適用。実カードの描画を更新する唯一の管理者。 |
| `cardSceneLayout.js` | ゲーム状態の表示用スナップショット、各エリアのアンカーと投影行列。 |
| `cardScenePlans.js` | 表示上の所属を段階的に移す計画と、日末のストック更新対象。 |
| `cardSceneTimeline.js` | 着手・達成・取得・交換・日末・初日配分・ドロー・再構成の順序と進行。 |
| `playPresentation.js` | イーゼルとカンバスの描画、個体・現在位置・向きの保持、カード支持面の投影。 |
| `handPresentation.js`、`stockPresentation.js` | エリア固有のラベル・固定倍率の操作と配置。実カードを描画しない。 |

位置は既存のCanvasArea/MoveAreaの座標変換から取得する。実カードは共通のメイン・パネル・移動層へ配置する。移動中も同じ要素を移動層へ移すだけとし、元と先のカードを別々に隠す方式は使用しない。

カードごとの配置の揺らぎは同じ個体・エリア内で保持する。手札はX/Y各±1論理px・回転±1.5度、ストックとデッキはX±1・Y±0.45論理px・回転±1.5度。捨て札は[捨て札エリア](17.discard_area.md)の範囲を使う。制作中作品の回転は[プレイエリア](15.play_area.md)、出荷済みサムネイルの固定投影は情報エリアの配置定義に従う。

## 状態

ゲーム上の所属・ステップはengineが所有する。CardSceneは演出中の表示状態を別に持つ。後続のゲーム処理が進んでも、未開始の移動の位置へ表示を先回りさせない。

別エリアへ移動するカードは、制作ステップが同じ場合も、移動中と移動後に現在の制作ステップのタブを表示する。同じエリアで制作ステップが変わらない再描画や再配置では、選択中のタブを保持する。
ステップタブは完成状態の有無にかかわらず`white-space: nowrap`を指定し、Step N等のラベルを1行で表示する。

各カードは現在の4×4姿勢行列、表裏の回転角、重なり順、透明度、所属・グレード、動作の所有者を持つ。表示内容のステップと参照中のタブも共通管理する。位置・倍率・傾き・回転は現在の姿勢から連続して補間する。イーゼル上の既存カードは毎フレーム実際の支持面に一致させ、着手中のカードはイーゼルの到着先へ運ぶ。

山の枚数は共通管理が持つ現在の所属から計算する。デッキから取り出したカードと、捨て札からデッキへ移動中のカードは`transit`で追跡する。45枚は移動中を含めて常に一意であり、所属の不足・重複はテストで検証する。

裏向きカードは表面の情報をアクセシビリティ上も隠す。捨て札は見えている面からのみ詳細を開く。隠れた捨て札の一覧を設けない。

## 演出

- 初日配分は90ms間隔、各300ms。ストック公開は持ち上げ180ms、裏返し360ms、下降180ms。A/B/Cの開始差は120ms。
- ドローは持ち上げ180ms、表返し360ms、手札への移動420ms。開始間隔660ms。これから引くカードも、取り出すまでは同じ実カードがデッキ内に存在する。
- 着手ではカードとイーゼルの追加・再配置を420msで進める。残る手札・イーゼルも同じ時間進行で動く。
- 達成時のカンバス・画材演出を維持する。Step 3に到達したときはイーゼル上の完成画を同じ実カードの表示として受け渡し、520msで出荷済み欄へ運ぶ。移動中に出荷済みの角度へ傾け、既存のカンバスも新しい配置へ移動する。それ以外は次ステップのカードを復帰させてから520msで捨て札へ運ぶ。その後に達成時効果を解決する。
- 日末は全対象の手札・制作中カードを同時に300msで捨て札へ運ぶ。その間ストックは公開状態を保持する。
- 日末の移動とストックの入れ替えがすべて完了してから日数を進める。ダイスのロール準備は翌日の仕事開始時に行う。
- ストック→捨て札は520ms。チラシ発注では制作と信用更新を終え、ゲームが継続する場合に取得と補充カードの公開を行う。日末の裏返し・最下段挿入は日末回収後に行う。
- 手札交換は持ち上げ・裏返し、ストック左側への移動、下降、差し込みを順に進める。飛行・下降中は移動層を使い、差し込み開始時にストックと同じパネル層へ移す。差し込み中は返却先の最下段の重なり順を使い、既存カードの下へ入れる。返却カードのステップ変更は裏向きになってから反映する。ストックから手札への取得は持ち上げ180msと移動420ms。
- デッキが空のときの再構成は、[捨て札エリア](17.discard_area.md#デッキへの再構成)の3段階を使用する。シャッフルによる並び順の変更は、中央に全カードが裏向きで重なった瞬間だけ行う。

イーゼルも同じ個体を保持する。追加は画面右側の外から入り、撤去は左側の画面外へ出る。残るイーゼルの位置・大きさ・向きも補間する。退いた個体はプールに保持し、そのカードが再びプレイされたときに再利用する。資源の破棄はゲームの終了・再開始時に行う。

## 中断と再描画

操作パネルの更新は実カードとイーゼルを再生成しない。エリアのレイアウト変更はアンカーの再計算として扱う。動作の中断は現在の姿勢を保持する。表示を続けるエラー復帰では現在位置からゲーム上の状態へ移動し、入口へ戻る場合はシーン全体を解放する。中断した古い処理は後続の描画を再開しない。

動きを減らす設定でも所属変更は同じタイムラインを通し、移動時間を0としてカードとイーゼルの最終姿勢・撤去を確定する。表示用スナップショットの採用だけで処理を省略しない。カードの個体はこの場合も維持する。省略する達成時の画材演出では、その準備やダイスの操作ロックも開始しない。効果通知だけの更新は、開いている詳細を破棄せず、閉じた後に操作パネルへ反映する。

レイアウトBのボードが完全に閉じている場合（`panelState.progress === 0`）は、初日のストックAからデッキへの7枚配分、ストックの公開・切り替え・補充公開、捨て札からデッキへの再構成を省略する。閉じるスライド中は演出を維持する。各演出の開始時に判定し、ストックの裏返し・最下段挿入・次の公開や、再構成の広げる・集める・移す段階では同じ判定を保持する。途中の開閉やレイアウト切替では開始済みの判定を変えず、次の演出から現在のレイアウトを参照する。

省略時のストックは順序・公開状態をまとめて移動時間0で確定する。再構成は広げる・集める段階を省き、ゲームの再開コールバックを一度だけ呼び、シャッフル後のデッキへ時間0で移す。初日配分も時間0で同じ移動経路を通す。カードの所属・表裏・枚数・順序と後続処理は維持する。デッキから手札へのドロー、手札返却、ストック取得、手札・場から捨て札への移動はこの省略対象に含めない。AとBの開状態では従来の演出を維持し、動きを減らす設定は引き続き優先する。

## 検証

- `cardSceneState.test.js`: 個体・所有者・中断からの連続補間・透明度の反映。
- `cardScenePlans.test.js`: 所属の保存、表示とゲーム状態の分離、取得・出荷・1枚のストックの更新。
- `cardSceneTimeline.test.js`: 完全閉状態とスライド途中・A/Bの判定、演出開始時の判定保持、取得・返却・ドローの維持、再構成の一度だけの再開と中断、最終状態。
- `scripts/checkBoardMotion.cjs`: 非表示ボード内の演出省略と表示時の維持、途中開閉、初日配分・公開・切替・再構成・後続ドロー、実カード45枚の同一性と所属。`MYPALETTE_STOCK_MOTION=1` で演出あり。
- `scripts/checkCardScene.cjs`: 毎フレーム45枚の同一性と表示、イーゼルの同一性・支持面との一致、全経路、通知と選択、発注、途中終了と再開始。
- `scripts/checkCardSceneReduced.cjs`: 動きを減らす設定を維持した初日開始・複数着手・配置と倍率の変更・達成後の撤去・日末回収・翌朝の再構成・再度のダイス選択と出荷・縦画面。実カード45枚の同一性と最終姿勢も確認する。
- `scripts/checkCardSceneLimits.cjs`: 初日演出、45枚の手札、45/1/0枚での再構成、空ストック、1枚のストックの日末、達成した同じカードの即時再構成・再ドローとイーゼルの再利用、縦画面・固定倍率。

従来の移動用複製を観測するスクリプトは共通検証への入口へ統合する。手札・ストック取得などの操作検証は新しい表示セレクターへ更新して維持する。

内部実装の誤りだけを検出するための実行時チェックは設けない。常時表示・個体と所属の一意性・演出順序は単体／ブラウザーテストの責務とし、本体は状態更新・描画・補間・中断を行う。透明度に演出理由を渡すAPIも使用しない。

イーゼル本体・留め具の配置はカンバス演出の開始・終了で変更しない。描画用キャンバスのサイズと解像度は、画面サイズまたはピクセル比が変わった時だけ更新する。移動完了直前と直後の再描画で、イーゼルの配置と描画画像が一致することをブラウザーテストで確認する。
操作パネルはDOMから切り離した状態で組み立て、エリアへの移設が完了してから画面へ戻す。組み立て途中の要素でスクロールバーを発生させ、狭くなった画面幅でイーゼルを描画しない。ブラウザーテストでは通常のスクロールバーを表示し、描画バッファーと表示領域の幅の一致を確認する。

初日の7枚の配分では、開始を待つカードの重なり順をストック内の元の値に保つ。動き出したカードはストックより手前を通り、到着時にデッキ内の重なり順へ移る。

朝の開始では、ドローや再構成より先に、エンジンが全ダイスを未消費にして出目を未確定（current = null）へ移す。表示はこのゲーム状態をそのまま反映し、表示専用の出目の上書きを行わない。準備の復帰動作が完了してから初日の配分・ストック公開・ドローへ進み、ゲーム上の出目の抽選は既存のロール要求で行う。

［今日の仕事を終える］はプレイエリアの上端中央へ固定倍率で配置し、実カード・移動カードより手前、コルクボードより奥の操作用レイヤーに置く。カードが重なっても隠れず操作できる。

## 操作と層の分離

実カードの詳細導線はカードIDを操作提供側へ渡す。手札・場札・ストックの固定倍率層の操作と詳細操作は共通定義を使用する。カードのない操作欄をDOM検索で補完しない。

移動層への配置はカードごとに判断する。移動開始時の所属・姿勢・反転と到着予定を比較し、出荷対象を含む移動対象だけをmoving層に置く。fieldからfieldへ留まるカードは、イーゼルに追従してもmain層に保持する。移動完了後は所属に対応した層へ戻す。

### 手札の操作ボタンの追従

`handPresentation.js` はカードIDと操作要素を対応させ、カードシーンの描画後に現在姿勢の行列からカード中心を求める。ボタンの座標はLayoutContent基準のCSSピクセルから最新の固定倍率で除して変換し、ボタン層だけに固定倍率を適用する。寸法と文字サイズはカードの倍率に連動させない。

ボタンはLayoutContent直下の専用層（z-index: 5）へ配置し、手札エリア境界で切り取らない。縦位置には、通常の手札中心から既存ボタン行までの間隔を加える。カードの回転・散らばりによる中心の移動も反映する。日次・効果ドローでは、表示用スナップショットに先行追加されても、カードシーンの現在の所属がhandになるまで対象カードの操作要素をhiddenで隠す。複数枚ドローでは各カードの移動完了時に表示し、演出全体の操作ロックは維持する。待ち時間や姿勢の比較で到着を判断しない。ストックから手札へ取得する場合も同じ所属判定を使う。着手したカードの操作要素は移動開始時に撤去する。残る手札は同じ描画後処理で再配置に追従する。

演出中はボタン層をinertにし、既存の操作定義の再検証も維持する。リセット時は保持した操作要素をすべて撤去する。A/B・リサイズ・固定倍率変更では最新のフレームとカード姿勢を使い、動きを減らす設定でも同じ配置処理を使う。

`node scripts/checkHandActionFollow.cjs <開発URL>` は日次・2枚効果ドローで待機中・移動中に操作要素が見えず、各カードの到着後に表示されることをカードID・フレームごとに検証する。山札残数による枚数制限、残る手札の途中座標、演出中のA/B・固定倍率変更、操作遮断、着手開始時の撤去、動きを減らす設定での最終表示・操作復帰も確認する。

`MYPALETTE_SCENE_LAYOUT_STRESS=1`で`checkCardScene.cjs`を実行すると、各演出中に画面幅・高さ・固定倍率・パネル開閉を変更する。通常実行と共通して毎フレームのカード個体・所属枚数・有限な姿勢・操作遮断と、終了後の全カードの到着姿勢・所属・動作所有者の解放を確認する。配置変更がない場合のイーゼル固定確認は通常実行で行う。
