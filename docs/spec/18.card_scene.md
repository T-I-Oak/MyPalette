# 全エリア共通カード表示

## 不変条件

ゲーム中の実カード45枚は、IDごとに同じCard・DOM要素を保持する。エリア間移動や再描画のために実カードを複製・再生成・非表示にしない。山の下、画面外、裏向きのカードも現在の姿勢を保持する。非表示の例外は達成時のカンバス演出だけとする。

拡大詳細・選択ダイアログ・出荷済み一覧のカードは閲覧用の参照表示であり、実カードの管理には参加しない。実カードには`data-scene-card`、その配置要素には`data-scene-id`を付ける。

## 責務

| モジュール | 責務 |
| --- | --- |
| `cardSceneState.js` | 全IDの個体、現在姿勢、透明度、動作の所有者、補間・中断。内部状態の検証はテスト側で行う。 |
| `cardScene.js` | CardとDOMの保持、表示内容・操作・描画、移動時間の適用。実カードの描画を更新する唯一の管理者。 |
| `cardSceneLayout.js` | ゲーム状態の表示用スナップショット、各エリアのアンカーと投影行列。 |
| `cardScenePlans.js` | 表示上の所属を段階的に移す計画と、日末のストック更新対象。 |
| `cardSceneTimeline.js` | 着手・達成・取得・交換・日末・初日配分・ドロー・再構成の順序と進行。 |
| `playPresentation.js` | イーゼルとカンバスの描画、個体・現在位置・向きの保持、カード支持面の投影。 |
| `handPresentation.js`、`stockPresentation.js` | エリア固有のラベル・固定倍率の操作と配置。実カードを描画しない。 |

位置は既存のCanvasArea/MoveAreaの座標変換から取得する。実カードは共通のメイン・パネル・移動層へ配置する。移動中も同じ要素を移動層へ移すだけとし、元と先のカードを別々に隠す方式は使用しない。

## 状態

ゲーム上の所属・ステップはengineが所有する。CardSceneは演出中の表示状態を別に持つ。後続のゲーム処理が進んでも、未開始の移動の位置へ表示を先回りさせない。

各カードは現在の4×4姿勢行列、表裏の回転角、重なり順、透明度、所属・グレード、動作の所有者を持つ。表示内容のステップと参照中のタブも共通管理する。位置・倍率・傾き・回転は現在の姿勢から連続して補間する。イーゼル上の既存カードは毎フレーム実際の支持面に一致させ、着手中のカードはイーゼルの到着先へ運ぶ。

山の枚数は共通管理が持つ現在の所属から計算する。デッキから取り出したカードと、捨て札からデッキへ移動中のカードは`transit`で追跡する。45枚は移動中を含めて常に一意であり、所属の不足・重複はテストで検証する。

裏向きカードは表面の情報をアクセシビリティ上も隠す。捨て札は見えている面からのみ詳細を開く。隠れた捨て札の一覧を設けない。

## 演出

- 初日配分は90ms間隔、各300ms。ストック公開は持ち上げ180ms、裏返し360ms、下降180ms。A/B/Cの開始差は120ms。
- ドローは持ち上げ180ms、表返し360ms、手札への移動420ms。開始間隔660ms。これから引くカードも、取り出すまでは同じ実カードがデッキ内に存在する。
- 着手ではカードとイーゼルの追加・再配置を420msで進める。残る手札・イーゼルも同じ時間進行で動く。
- 達成時のカンバス・画材演出を維持し、次ステップのカードの復帰後に520msで捨て札または情報エリアの出荷済みの山へ運ぶ。その後に達成時効果を解決する。
- 日末は全対象の手札・制作中カードを同時に300msで捨て札へ運ぶ。その間ストックは公開状態を保持する。
- ストック→捨て札は520ms。最後の発注と日末回収が同じ操作で進む場合は、全対象を300msで同時に運ぶ。補充カードの公開後に日末の裏返し・最下段挿入へ進む。
- 手札交換は持ち上げ・裏返し、ストック左側への移動、下降、差し込みを順に進める。返却カードのステップ変更は裏向きになってから反映する。ストックから手札への取得は持ち上げ180msと移動420ms。
- デッキが空のときの再構成は、[捨て札エリア](17.discard_area.md#デッキへの再構成)の3段階を使用する。シャッフルによる並び順の変更は、中央に全カードが裏向きで重なった瞬間だけ行う。

イーゼルも同じ個体を保持する。追加は画面右側の外から入り、撤去は左側の画面外へ出る。残るイーゼルの位置・大きさ・向きも補間する。退いた個体はプールに保持し、そのカードが再びプレイされたときに再利用する。資源の破棄はゲームの終了・再開始時に行う。

## 中断と再描画

操作パネルの更新は実カードとイーゼルを再生成しない。エリアのレイアウト変更はアンカーの再計算として扱う。動作の中断は現在の姿勢を保持する。表示を続けるエラー復帰では現在位置からゲーム上の状態へ移動し、入口へ戻る場合はシーン全体を解放する。中断した古い処理は後続の描画を再開しない。

動きを減らす設定は各動作を即時完了する。カードの個体はこの場合も維持する。効果通知だけの更新は、開いている詳細を破棄せず、閉じた後に操作パネルへ反映する。

## 検証

- `cardSceneState.test.js`: 個体・所有者・中断からの連続補間・透明度の反映。
- `cardScenePlans.test.js`: 所属の保存、表示とゲーム状態の分離、取得・出荷・1枚のストックの更新。
- `scripts/checkCardScene.cjs`: 毎フレーム45枚の同一性と表示、イーゼルの同一性・支持面との一致、全経路、通知と選択、発注、途中終了と再開始。
- `scripts/checkCardSceneLimits.cjs`: 初日演出、45枚の手札、45/1/0枚での再構成、空ストック、1枚のストックの日末、達成した同じカードの即時再構成・再ドローとイーゼルの再利用、縦画面・固定倍率。

従来の移動用複製を観測するスクリプトは共通検証への入口へ統合する。手札・ストック取得などの操作検証は新しい表示セレクターへ更新して維持する。

内部実装の誤りだけを検出するための実行時チェックは設けない。常時表示・個体と所属の一意性・演出順序は単体／ブラウザーテストの責務とし、本体は状態更新・描画・補間・中断を行う。透明度に演出理由を渡すAPIも使用しない。

イーゼル本体・留め具の配置はカンバス演出の開始・終了で変更しない。描画用キャンバスのサイズと解像度は、画面サイズまたはピクセル比が変わった時だけ更新する。移動完了直前と直後の再描画で、イーゼルの配置と描画画像が一致することをブラウザーテストで確認する。
操作パネルはDOMから切り離した状態で組み立て、エリアへの移設が完了してから画面へ戻す。組み立て途中の要素でスクロールバーを発生させ、狭くなった画面幅でイーゼルを描画しない。ブラウザーテストでは通常のスクロールバーを表示し、描画バッファーと表示領域の幅の一致を確認する。

初日の7枚の配分では、開始を待つカードの重なり順をストック内の元の値に保つ。動き出したカードはストックより手前を通り、到着時にデッキ内の重なり順へ移る。

朝の開始では、ドローや再構成より先に、エンジンが全ダイスを未消費にして出目を未確定（current = null）へ移す。表示はこのゲーム状態をそのまま反映し、表示専用の出目の上書きを行わない。準備の復帰動作が完了してから初日の配分・ストック公開・ドローへ進み、ゲーム上の出目の抽選は既存のロール要求で行う。

［今日の仕事を終える］はプレイエリアの右上へ固定倍率で配置し、実カード・移動カードより手前の操作用レイヤーに置く。カードが重なっても隠れず操作できる。
