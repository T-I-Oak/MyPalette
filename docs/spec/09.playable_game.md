# 評価用ゲームの実装仕様

## 入口と設定

開発者用入口（`/MyPalette/dev.html`）の「ゲームを始める」から、保存済み `public/data/cards.json` を使う一局を開始する。
「カード設定を開く」は `#settings` の既存エディターを開く。
エディターから入口への移動はページ遷移とし、未保存変更の確認とWorkerの破棄をブラウザに任せる。
保存した設定は入口を開き直した際に読み込まれ、次のゲームに反映される。

開始前に構造検証と制作途中の検証を行う。未設定の目標・効果はカードIDとステップを示して開始を拒否する。
設定の自動補完は行わない。ゲームはカード定義を複製し、カードのステップやダイス面変更を設定へ保存しない。

## 状態と責務

- `src/game/engine.js`：初期配置、カード領域、日数、名声、信用、チラシ、進行操作。
- `src/game/dice.js`：乱数注入、シャッフル、初期面、獲得候補、指定面、ロール。
- `src/game/goals.js`：現在の未使用ダイスによる厳密な達成判定。
- `src/game/effects.js`：全16効果、対象選択、獲得・ストック取得、特殊面の対象固定。
- `src/game/session.js`：Gameの生成、操作受付と更新通知。再プレイでは新しいセッションを生成する。
- `src/game/view.js`、`view.css`：情報表示、対象選択、結果、再プレイ。プレイヤー向け入口でも同じ処理を使い、presentationで7エリアへの表示先を分離する。

カード状態は `{ id, step }` とし、同一カードを領域間で移動する。
領域は `deck`、`hand`、`field`、`discard`、`shipped`、グレード別 `stocks`。
`public` は各ストックで公開中の先頭カードのID。取得直後に次の先頭カードのIDへ更新し、ストックが空になった場合は `null` とする。

ダイス状態は一意のID、6面、現在面の番号、消費状態、所持期間を持つ。
通常面は `{ color, material }`、特殊面は `{ special }`。
消費済みも所持領域に残り、破棄時は所持領域から取り除く。

正式プレイ画面の達成演出では、`beginAchievement(id, ids)`で判定とダイス消費を行い、`state.achievement`へ処理対象を保持する。保持中は他のゲーム操作を拒否する。キャンバスを描き変えた後、`completeAchievement()`で既存の達成時効果とステップ更新・領域移動を実行する。評価用ゲームなどの`achieve(id, ids)`は両処理を同期実行し、従来の操作契約を維持する。

## エリア間移動の試験適用

既存のグリッドが静止中のカードとダイスを配置し、[エリア間移動ライブラリ](13.area_transition.md)が移動中の表示を担当する。操作前後のカード所属から移動を検出し、選択したダイス候補については確定前の位置を獲得後のダイスIDと対応づける。複数個を獲得する場合は、所持欄に追加されるまでそれぞれの候補位置を保持する。

| 経路 | 評価用ゲームでの操作 |
| --- | --- |
| 山札 → 手札 | 翌日の仕事を始める。捨て札を切り直して引くカードも山札の位置を使う。 |
| ストック → 手札 | 手札交換の効果で公開ストックから取得する。 |
| ストック → 捨て札 | ストック取得のカード効果、またはチラシによる発注で公開ストックから取得する。 |
| 手札 → ストック | 手札交換の効果で手札をストックに戻す。 |
| 手札 → 制作中 | 「場にプレイ」を押す。 |
| 手札・制作中 → 捨て札 | 一日の仕事を終える。制作中の作品はステップ達成でも捨て札へ移ることがある。 |
| 獲得候補 → 所持ダイス | 通常ダイス獲得の選択を確定する。 |

カードの流れは右からストック、山札、手札、制作中、捨て札の順を目安とする。非表示のストックと山札は画面右に置き、ストックは山札よりさらに右を使う。非表示の捨て札は画面左に置く。画面外の枠は表示側のカードと同じ高さに置く。手札と制作中はワイド画面では手札が右、制作中が左にあり、狭い画面では既存の縦並びを使う。

「ストック・山札・捨て札」タブを開いた状態でドローすると、画面を更新する直前の山札の枚数表示からカードが出発する。捨て札への移動では表示中の枚数表示を到着点とし、移動中にタブを開閉しても到着位置を更新する。描画するカードが両端に存在しない移動は枚数に反映する。ゲーム開始時のストックから山札への配分と初期配布は初期状態として表示する。

移動中は同じカードやダイスを二重に表示しないよう、到着先の要素をレイアウトに残したまま隠す。ゲーム進行の操作と次の選択ダイアログは移動の終了まで待ち、タブは切り替えられる。OSの「視差効果を減らす」などで `prefers-reduced-motion: reduce` が有効な場合は、移動演出を省略する。

## 進行と選択待ち

進行は `start` → `play` → `end` → `betweenDays`、信用0で `finished`。
最初の日はゲーム開始と同時に開始し、翌日は「翌日の仕事を始める」で開始する。
ターン終了後を明示的に区切り、予約効果や信用の更新を記録で確認できるようにする。

効果処理はGeneratorで配列順に実行する。選択が必要な場合に `pending` を返し、処理を中断する。
`pending` は対象種別、説明、候補ID、選択数の下限・上限を持つ。
`choose(ids)` は候補外、重複、不足、超過を拒否し、有効な選択だけで再開する。
中断中はプレイ・達成・リロール・ターン移行を拒否する。対象なしは選択を要求せず処理を完了する。

通常ダイスを複数獲得する場合、1個ごとに候補生成と選択を行い、全選択後にまとめてロールして加える。
手札交換は、返却・必要時の公開・手札への取得を1回ずつ完了させる。
特殊面の即時適用は対象を発動時に固定し、名声、リロール権、ドロー、一時ダイスの順で処理する。
新規獲得ダイスは今回の対象へ追加しない。

達成は目標をORで分割し、各AND条件に異なる未使用通常面ダイスを割り当てる。
選択したダイスは、そのOR候補の目標数と同数で、すべてが割り当て可能な場合だけ受け付ける。
達成時効果より先に消費し、全効果完了後にステップと領域を更新する。
確率表示の近似計算は判定に利用しない。
プレイフェーズの終了は任意とし、手札枚数や達成可能な場札の有無で制限しない。効果の選択待ち中は終了できない。

ターン終了時は特殊面を予約し、通常面の未使用ダイスを最大2個消費してチラシを制作する。制作後に残った未使用ダイス数を数え、信用が残る場合に自動発注を処理する。信用が0になる場合は、完成枚数、制作進捗、次回の発注必要枚数を保持して発注をスキップする。その後、数えておいた未使用ダイス数で信用を更新し、ゲームの終了を判定する。
チラシ用ダイスは色・画材を問わず同じ結果になるため、所持順の先頭から選ぶ。使用IDを記録する。
継続する場合にクリーンナップとストック更新を行う。信用0の場合は終了時点の領域を残す。
翌日の開始を待つ間は、信用更新後・クリーンナップ前に複製した `dayEndDice` を表示する。
一時ダイスも含む当日の出目と消費状態を確認でき、「翌日の仕事を始める」で終了時の表示を解除する。
この確認用の表示からダイスを使用することはできない。

## 評価画面

日数、進行状態、名声、信用、チラシ、リロール権、領域の枚数と公開情報を表示する。
手札、制作中、公開ストック、出荷済み作品では現在ステップと全ステップの目標・効果を確認できる。
絵画カードの表示と操作は[絵画カード](#絵画カード)を参照する。
ダイスは6面を共通の面アイコンで常時表示し、その中で現在面を強調する。所持期間・消費状態は文字で維持する。

達成用のダイスをチェックし、「選択ダイスで達成」で確定する。
有効な組合せを選ぶまで達成ボタンを無効化する。達成可能表示は未使用の現在面から更新する。
手札は現在ステップの目標を満たせる場合にカードの縁を発光させ、アクセシブル名で「達成可能」と示す。達成可能の判定には現在の出目を使う。
効果の選択待ちでは対象と必要数を表示し、確定までは他の進行操作を無効化する。
画面上部に進行情報、下部に直近の処理と仕事終了・翌日開始ボタンを固定する。
制作画面では左にダイス、中央に制作中の作品、右に手札を配置する。
領域内のスクロールを独立させ、操作後も各領域の位置を保持する。画面全体の上下移動は必要としない。
ダイスの個別リロールは矢印ボタンで行い、対象IDをアクセシブルな名前とツールチップで示す。
狭い画面ではダイスを左列、制作中と手札を右列の上下に配置する。
公開ストック・出荷済み・記録は情報タブで切り替え、ダイスと進行操作は常に表示する。
効果の対象選択はモーダルダイアログで行い、選択候補だけを内部スクロールし、確定操作を下部に残す。

終了時は日数・名声・出荷数と再プレイ操作を表示する。
一局の記録はメモリー内だけに保持し、途中保存や過去記録との比較は行わない。
進行記録は効果、使用ID、カード移動、チラシ制作・発注、信用減少、終了を記載する。

## 絵画カード

`src/game/Card.js` の `Card` はエリア間移動の `MoveObject` を継承し、表裏、絵の段階、タブ、アイコンの描画を担当する。評価画面は領域内の配置と操作を担当する。

カード上部にグレードと作品名を置く。グレードは白・銀・金の枠色と A・B・C の表記で示す。作品名は1行に収まるよう、必要に応じて文字を縮小する。
絵画画像は `public/assets/paintings/` のカードIDと段階番号（1〜3）で参照する。Step 0 では第1段階の画像をマスクして表示する。Step 1・2 では現在段階の画像に次の段階の画像を重ね、左上から右下へなだらかに変化させる。出荷済みでは第3段階の完成画を表示する。絵は縦横比を保って枠内に収める。
絵の下の `Step 0`〜`Step 2` タブで目標と効果を切り替える。実際の制作段階はタブと内容欄の明るさで示し、選択したタブは太字にして内容欄とつなげる。絵はカードの実際の制作段階に連動する。
出荷済みカードは4つのタブを等幅で並べ、初回は `Done` を開く。内容欄の証明書には作品番号・作品名・My Palette Atelierを表示する。過去のステップは暗い配色で参照できる。
表向きのカード本体をタップすると画面中央に拡大する。拡大したカード本体を再度タップするか、カード下の「閉じる」を押すと戻る。拡大中もタブとアイコンの説明を操作できる。プレイや達成のボタンはカード外に置き、拡大時にも該当する操作をカード下に表示する。
カードの基準寸法は幅294px、高さ約414pxとする。エリアの内容全体は、画面に割り当てられた枠とエリアの基準寸法の幅比・高さ比のうち、小さい方を倍率に使う。
評価用ゲームの手札は4枚まで重ねずに横に並べ、5枚以上は等間隔で重ねる。プレイヤー向け手札は4枚分を標準描画サイズとし、5枚以上も与えられた論理幅に収まれば横並び、収まらない場合に均等に重ねる。配置と固定倍率ボタンは[画面レイアウト制御](14.screen_layout.md#手札の内容配置)を参照する。制作中は1列に並べる。ストックはグレードごとに裏向きのカードを厚み分ずつ上に重ね、公開カードを一番上に置く。

### カードの共通アイコン

手札・制作中・公開ストック・出荷済み作品・カード対象選択で共通の `Card` を使う。選択中のステップに対応する目標・プレイ時効果・達成時効果を `src/cardIcons.js` の共通アイコンで表示する。
目標は同時に満たす条件を1行に並べ、選択肢を改行し、行間に `or` を表示する。目標アイコンは各段の中央に配置する。効果は設定順に並べる。
目標は上段の黄土色の枠、プレイ時と達成時の効果は下段の左の青枠と右の緑枠に置く。それぞれ見出しアイコンと内容を同じ枠にまとめ、効果が空の場合は「—」を表示する。
アイコンの説明はポインターを重ねるかタップして開く。アクセシブル名でも意味を示す。効果説明は効果名と設定値を「 · 」で区切り、個数・回数には `×`、名声の増加値には `+` を付ける。説明文は日本語と英語の翻訳リソースから取得する。
表示側に完成状態の再検証や値の補完を追加せず、開始時に検証したカード設定を共通描画APIへ渡す。

## 使用済みダイスの再利用

`refreshDice`は対象選択なしで、所持する全ダイスのusedをfalseへ戻す。
永続・一時、通常面・特殊面を区別せず、現在面・面構成・リロール権は変更しない。
所持ダイスなし・使用済みなしでも処理を完了し、次の効果を続ける。
プレイ時・達成時のどちらにも設定でき、達成時は直前の達成で消費したダイスも対象になる。

## ダイス面の表示

ダイス面は`src/dice/icons.js`の`faceCanvas`を再利用し、6面の構成・獲得候補の面を表示する。
6面の各アイコンは22pxで縦横比を維持する。6面は常時横へ並べ、領域が足りない場合だけ折り返す。単独の現在面表示と6面の開閉操作は設けない。
6面内の現在面を枠・背景と「現在」の文字で示す。ホバーとフォーカスで色・画材・特殊面の説明を表示する。
選択チェック、リロール、所持期間・使用状態の操作と表示は維持する。

通常ダイスの獲得候補は効果の所持期間（lifetime）を保持し、候補の6面もその期間に対応するアイコンで描く。

## 検証

`tests/implementation/game/` は進行の中断・再開、データの分離、目標割当、ダイス生成、評価画面でのエリア間移動を確認する。
`tests/spec/rules_01_game_flow.test.js` は終了までの操作列、45枚の保存則、出荷時の信用増加、発注と予約を確認する。
`tests/spec/` の第6章・第7章のテストはダイスとその他の効果の挙動、特殊面10種類、色変更・破棄・再利用の設定データを確認する。
乱数はGameの第2引数から差し替え、面構成、ロール、シャッフルを再現可能にする。
