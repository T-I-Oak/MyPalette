# ゲーム共通アイコン

## 対象と入口

カードとダイスが共有する目標・効果アイコンを提供する。要求仕様04〜07に従い、要求自体は変更しない。
確認画面は開発・保守で継続使用する常設ページとし、入口の「共通アイコン確認を開く」、または `/MyPalette/dev.html#icons` から開く。画面には一時的なレビュー進行の注意書きを表示しない。
`?icon=color-orange#icons` のようにレビューIDで初期項目を指定できる。
カード全体のレイアウトと既存ゲームへの組込みは今回の対象外。

## 所有と公開API

| モジュール | 責務 |
| --- | --- |
| `src/icons/symbols.js` | 画材・色・ダイス・チケット・手札の共有図形。レビュー済みの形状の正本 |
| `src/icons/glyphs.js` | 色文字・0〜9・符号・矢印のパス。OSフォントを使わない |
| `src/icons/laurel.js` | 月桂冠と符号付き名声数値 |
| `src/icons/catalog.js` | ゲーム効果と描画のみの追加案をまとめたアイコンの型定義 |
| `src/icons/iconPlan.js` | 効果・条件の検証、構成要素と数量表記の決定。DOMに依存しない |
| `src/icons/render.js` | 構成要素の合成と透過Canvas生成 |
| `src/icons/reviewCases.js` | レビュー対象と一意のID |
| `src/icons/lab.js` / `layout.css` | 1件ずつ表示する確認画面 |

- `effectIconCanvas(effect, height=192)`：ゲームのeffectCatalog.jsの16効果を受け、透過Canvasを返す。
- `goalIconCanvas({material?, color?}, height=192)`：画材・色・画材＋色の単一条件を描く。
- heightは16〜2048の整数。Canvasの横幅は構成と数量の桁数から求め、正方形に押し込まない。
- 呼出元がCanvasのrole、翻訳済みaria-label、表示寸法を与える。APIは説明文を画像へ焼き込まない。
- パラメータが欠けている、不正な種類・値である場合は例外。既定の効果に置き換えない。
- 返却Canvasは呼出元が所有する。ここではアニメーション・イベント・GPU資源を保持しない。
- ダイス面は `src/dice/icons.js` が面の背景と余白を付け、共有のsymbolsを呼ぶ。glyphs/laurelの旧パスは共通実装を再公開するだけで、複製を持たない。
- 面検索の条件アイコンもgoalIconCanvasを使用する。

## 描画の契約

| 効果 | 表現 |
| --- | --- |
| 通常ダイス獲得 | 白い六角形＋Y字、必要時×N |
| 色指定ダイス獲得 | 補色で塗り分けた六角形＋各色文字、必要時×N |
| 画材指定ダイス獲得 | 六角形内の共通画材記号、必要時×N |
| リロール権獲得 | レビュー済みチケット、必要時×N |
| 即時リロール | チケット内と共通の傾いた六角形＋Y字＋波紋、その右に即時を表す雷 |
| 色変更 | ペン＋指定色の角丸ひし形＋白抜き色文字 |
| 画材変更 | ペン＋角丸ひし形内の共通画材記号 |
| 特殊面への変更 | ペン＋角丸ひし形内に変更先特殊面の効果。星を追加しない |
| ダイス破棄 | 六角形＋Y字とゴミ箱、必要時×N |
| 名声変更 | レビュー済み月桂冠と＋N/−N。負数は赤、数値は白で縁取り |
| ドロー | レビュー済み扇形手札と左矢印、＋N |
| ストックから獲得 | 左矢印の下に×N＋積み重ねたカード。×1も表示 |
| ステップ変更 | ペン＋長方形カード内の0/1/2。符号を付けない |
| 手札交換 | 扇形手札＋上下の矢印とその下の×N＋ストック。×1も表示 |
| 特殊面の即時適用 | 角丸ひし形内の星と雷 |

ダイス獲得の一時指定だけは六角形の左右にレビュー済みの雲状補助記号を付ける。
数量は通常は構成の右端に置き、×1と＋1は省略する。矢印付き数量は矢印の下に置き、×1と＋1も省略しない。月桂冠は数値を含む一体型の例外とし、＋1を含めて従来の内側表示を維持する。−1は省略しない。
ドローはレビュー済みの1桁表示を基準とし、確認画面は＋1〜＋10を示す。
数量パラメータ自体は正の安全な整数を受け付けるが、ドローの多桁表示は幅を追加して収め、承認は別途得る。
名声はレビュー済みの数字パスで0〜9を合成し、月桂冠の空間を超える長さに限り縮小する。

目標は全条件で傾けない角丸正方形を外形に使う。画材単独なら白い面内に無彩色シルエット、色単独なら指定色で塗った正方形内に白抜き色文字、両方なら白い面内に色付き画材記号と白抜き文字を配置する。外形は基準座標8〜92の84角、角半径8、輪郭線幅3。画材記号は内側の70角に収める。効果側のダイス面はひし形を維持する。
AND/ORの目標全体のレイアウト・個数・ゲーム接続は呼出元の責務で、単一条件APIへ混ぜない。

## 配色と共通スタイル

描画の画材色はsymbols.jsのINKS、対応する文字はLETTERSを正本とする。
カード用として同じ配色・図形を再定義しない。これは描画素材の色であり、CSSテーマのUI色とは別の契約。
HTMLの確認画面は [共通UIスタイル](11.shared_ui_style.md) の変数・質感クラスを使用する。
SVG・Canvasで使う記号はフォントの有無に依存せず、装飾文字を絵文字で代用しない。

## レビューと状態

確認画面は同じ1件を暖色/寒色の背景に、高さ128/48/32pxで表示する。
種類の選択欄は数値だけが異なる項目をまとめる。数量を持つ種類は数量入力、名声は増減値入力で指定し、入力のたびにプレビューへ反映する。数量は1以上の整数、名声は0以外の整数。数値不要の種類では入力欄を隠す。選択や入力は承認操作ではない。
新規デザインはすべて確認案。レビュー済み部品を使った合成も、それだけで承認済みにはしない。
既存のダイスでの承認は、そのダイス面・結果表示の文脈に限定して保持する。
レビューIDとオーナーの判断は実装報告へ記録する。未回答を承認として扱わない。

確認画面の機能クラスは、`IconLab` が縦配置とスクロール、`IconComparisons` が背景比較の並び、`IconPreview` が個別の比較面、`IconSample` がアイコンと寸法ラベルの配置を担当する。配色は共通textureクラスから与える。

## ストックのカード形状

手札とストックは `drawCardSymbol` の同じ角のある縦長長方形を使う。
正面の縦横比は幅22・高さ42で共有し、手札は下辺中心を基点に扇形に回転させる。
ストックはこの長方形を斜めから見た平面へ投影し、同じ向きの4枚を上下に4単位ずつずらして重ねる。
上面だけでなく下のカードの縁が見える積層として描き、カードごとに異なる形を定義しない。
ストック獲得と手札交換は同じ `drawStockSymbol` を使う。手札とほぼ同じ幅・高さとし、投影後の輪郭線を手札と同じ3単位で描く。

## 手札交換の矢印付き数量

手札・中央の数量部品・ストックを横に配置する。左右の図形は外形がほぼ同じ幅・高さになるよう配置する。
中央は `quantity.js` の共通部品で、上から右矢印・左矢印・×Nを縦に配置する。
×1も表示し、数量を末尾へ別置きしない。矢印を同じ座標へ重ね描きしない。
手札とストックはどちらもメイン高さ80とし、幅は縦横比から求める。中央は数量と矢印の輪郭に必要な幅を確保し、数量の桁数に合わせて増やす。各輪郭間の余白は8。

複数の矢印が接近する数量部品では、すべての白い縁取りを先に描き、次にすべての本体を描く。別の矢印の縁取りで本体を隠さない。glyphsのoutlineパスは縁取りだけを描くために使用する。

ダイス破棄の間隔は、以下の共通メイン・サブ配置規則で決める。個別の位置補正は持たない。

## メインとサブの共通寸法

`src/icons/compositionLayout.js` の `ICON_SIZES` を全組合せの正本とする。
`main` は対象や効果そのものを示す主図形、`sub` は変更・破棄・即時などの操作を補助する図形。
図形に共通の100単位座標系を使い、輪郭を含む高さをメイン80・サブ56へ揃える。サブはメインの70%。
幅は縦横比を維持して求め、無理に正方形にしない。輪郭間の水平余白 `gap` は8。
上下中央を揃え、Canvasの横幅は各輪郭幅と余白の合計から計算する。画面上のpx寸法は表示倍率に比例する。

| 組合せ | メイン | サブ |
| --- | --- | --- |
| 面の色・画材・特殊面への変更 | 変更後の面 | ペン |
| カードのステップ変更 | カード | ペン |
| ダイス破棄 | ダイス | ゴミ箱 |
| 即時リロール | リロールアイコン | 雷 |
| 特殊面の即時適用 | 星入りの面 | 雷 |

各図形の輪郭範囲はoutlineBounds.jsで、実際の描画のアルファから求める。基準1単位あたり4画素で測り、白い縁取りと線幅を含める。固定の推定境界や文字の送り幅を輪郭として扱わない。測定結果は図形とパラメータごとにキャッシュする。
手札交換は左右ともメインとして高さ80に揃える。両方をサブサイズへ落とす案は個別調整の候補に留め、現時点では適用しない。
数量と矢印付き数量も対象図形とは別の共通部品として寸法を管理する。

## アイコンと数量の配置先

手札交換は `[手札(main)] [矢印付き数量] [ストック(main)]`、ドローは `[手札(main)] [矢印付き数量]`。
いずれもcompositionLayoutでアイコンと数量の輪郭間隔を8とし、上下中央を揃える。
カード用APIはメイン高さ80を保つ構成を返し、横幅に応じた全体縮小をしない。
ダイス用のドローは同じ構成を使用し、面の横幅100に収まる倍率で構成全体を比例縮小する。
面そのものの外側の余白・背景は引き続きダイス用ラッパーが与える。

ストック獲得は `[←の下に×N] [ストック(main)]` とする。×1も表示し、右端に数量を別置きしない。

数量も実測した輪郭幅のみを配置に使い、最低幅60などの空白枠は追加しない。Canvas全体の外側余白は、構成要素間の間隔へ加算しない。省略条件と例外は本書の数量規則で管理し、要求仕様には個別条件を書かない。

## 取得を表す数量の例外

ダイスの獲得（通常・補色指定・画材指定、永続・一時）とリロール権の獲得は、カード効果では右端に×Nを必ず表示する。
×1も取得という動作を示すため省略しない。＋Nへは置き換えない。
ダイス面用の取得表示は×1を省略する。カード効果の共通構成は×1を保持し、ダイス表示側が1個取得の数量を除いて配置する。
ダイス破棄の×1省略、矢印付き数量の1表示、月桂冠の一体型は維持する。

面内の数量省略は `faceEffectIconPlan` に集約する。実際のダイス面と、特殊面への変更アイコンのひし形内は同じ規則を使用し、取得の×1を省略する。カード上でも面を描写する内側はこの規則に従う。カード効果として直接示す取得は×1を表示し、ドローの矢印付き＋1は維持する。

確認画面の種類一覧はreviewCasesから数量・増減値だけの違いを除いて作る。reviewCasesの数値パターンは描画検証用に保持し、UIの件数や選択肢へ重複表示しない。過去の数値付きレビューIDのURLは対応する種類と初期数値へ変換して開く。

前後ボタンは、数値バリエーションをまとめた種類一覧を順に切り替える。先頭では前、末尾では次を無効にする。数量入力とプルダウン選択は併用できる。

## アイコン追加時の共通ルール

新しいアイコンは、カード・ダイス・所持状態などの配置先に依存しない共通部品として追加する。
既存と同じ意味の図形・配色・文字パスを作り直さず、共有部品を組み合わせる。

1. アイコンが示す意味と、メイン・サブ・数量の役割を定める。発動タイミングは効果の内容と別のアイコンとして扱う。
2. 図形は共通の100単位座標系で描く。通常の輪郭線は変換前3単位を基準にし、文字・符号・矢印は共通パス、画材色はINKSを使う。
3. メイン/サブの合成にはroleを指定し、compositionLayoutとICON_SIZESを通す。高さ80/56と間隔8を個別の描画関数へ複写・再定義しない。
4. 配置はoutlineBoundsによる白縁・線幅込みの実測輪郭を使う。文字の送り幅や余白付きCanvasの大きさを図形の輪郭幅として扱わない。
5. 横幅は縦横比と構成から求める。極端に横長の場合は個別に提示して調整し、無断で高さを変える例外を導入しない。
6. 配置先のサイズ制約で縮小するときは構成全体を比例縮小する。部品のサイズ比や間隔の比率を配置先ごとに変更しない。
7. 数量は共通の構成規則、矢印付き数量はquantity.jsを使う。省略はiconPlan/faceEffectIconPlan側で決め、図形関数へ効果別の判断を散在させない。
8. 共通確認ページへ追加し、2背景・128/48/32px、数量の有無や桁数で確認する。追加された構成の寸法・間隔は配置テスト、実画像の欠けは描画確認の対象にする。

新しい共通規則や承認された例外は、この仕様と共通定義の双方へ反映する。個別アイコンだけの隠れた寸法補正で済ませない。


## 使用済みダイスの再利用

`effectIconCanvas({type:'refreshDice'}, height)` はグレーの六角形＋Y字と、その右肩の十字形の光を描く。
メイン図形として高さ80へ揃え、光は右肩の一体の装飾として扱う。確認IDはrefresh。
この種類はsrc/icons/catalog.jsのアイコン用定義に置く。ゲーム用effectCatalog.jsの効果・保存データへは追加しない。
基本の効果とアイコンは要求仕様06の6節に定義する。永続・一時を含む所持するすべての使用済みダイスを、出目を維持して使用可能に戻し、リロールはしない。設定候補とゲーム処理でも同じrefreshDiceの定義を使う。
全対象へ適用する効果なので、数量パラメータは持たない。
