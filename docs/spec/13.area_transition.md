# エリア間移動ライブラリの実装仕様

## 描画単位と責務

エリアは、中にあるコンポーネントの位置と大きさをまとめて拡縮する描画単位とする。オブジェクトの描画上の所属と、ゲーム進行上のカード領域などの状態は別に管理する。ゲーム側はルールに従って状態を更新し、描画側に移動を依頼する。

| 担当 | 保持する情報と責務 |
| --- | --- |
| 画面レイアウト | 画面の基準座標系、共通倍率、画面上の基準原点を決める。エリアの開閉や画面サイズに応じて、エリアの位置と倍率を決める。 |
| エリア | 自身のID、画面基準座標での原点、固有倍率を持つ。所属オブジェクトをローカル座標で配置・描画し、配置先の矩形を確定する。表示状態と操作を受け付ける状態も管理する。 |
| 移動管理 | オブジェクト、出発元、到着先とその配置、移動時間を受け取り、出発・移動中・到着の描画と所属を切り替える。移動中の矩形を計算して共通の移動レイヤーへ渡す。 |
| 移動オブジェクト | 共通ベースクラス `MoveObject` がインスタンスの識別子、描画上の所属、操作可否、描画・演出用の接点を持つ。配置は所属エリアの枠が保持し、固有の見た目と演出は利用側が指定する。 |

## 座標と拡縮

矩形は左上の位置と幅・高さで表す。軸は右と下を正とする。座標系はエリア内のローカル座標、画面の基準座標、ビューポートのCSSピクセルの3つとする。倍率は正の値で、各軸に同じ値を適用する。

- `a` は画面基準座標でのエリア原点、`s` はエリア固有倍率。
- `o` はビューポート上の基準原点、`g` は画面共通倍率。
- `p` はエリア内の位置、`d` はエリア内での大きさ。ベクトルの乗算・除算は両軸に適用する。

```text
画面基準座標の位置 = a + s × p
画面基準座標の大きさ = s × d
ビューポート上の位置 = o + g × (a + s × p)
ビューポート上の大きさ = g × s × d
```

逆変換では、ビューポート上の位置から `o` を引いて `g` で割り、次に `a` を引いて `s` で割る。大きさは `g × s` で割る。計算途中の小数は保持する。

ゲーム本体のレイアウトA/Bは、利用可能なCSSピクセル領域へ直接割り当て矩形を配置する。画面共通倍率 `g = 1`、原点 `o = (0, 0)` とし、標準寸法から算出したエリア固有倍率だけを適用する。配置・論理寸法・Canvas解像度は[画面レイアウト制御](14.screen_layout.md)を参照する。ライブラリ自体は任意の共通倍率・原点を扱える。

閉じたエリアも、画面外に置くための原点と固有倍率、所属オブジェクトのローカル矩形を保持する。変換式に画面外の座標をそのまま渡す。移動レイヤーはエリアの描画範囲によるクリップの外に置き、画面外の部分はビューポートでクリップする。

## 移動中の所属と操作

| 状態 | 所属 | 描画 | 操作 |
| --- | --- | --- | --- |
| 出発前 | 出発元 | 出発元の描画規則に従う | 出発元が表示・操作可能で、オブジェクトも操作条件を満たす場合に受け付ける |
| 移動中 | なし | 共通の移動レイヤーに1回描画する | ポインター、キーボード、フォーカスの対象から外す |
| 到着後 | 到着先 | 到着先の描画規則に従う | 到着先が表示・操作可能で、オブジェクトも操作条件を満たす場合に受け付ける |

1. 移動管理は、出発元への所属、同じオブジェクトの移動の有無、到着先への配置可否を確認する。到着先の枠が排他的なら、移動開始前に確保する。受付条件を満たさない要求では所属と描画を維持する。
2. 出発元から離す直前にローカル矩形とエリア変換を取得し、画面基準座標の出発矩形を確定する。同じ描画更新で、エリア描画から取り除き、入力対象から外し、移動レイヤーで描画を開始する。オブジェクトがフォーカスを持っていれば解除する。
3. 移動管理は進捗 `t` を0から1へ進め、出発矩形と到着矩形の位置・幅・高さをそれぞれ同じ進捗で補間する。移動レイヤーの矩形に共通倍率と基準原点を適用して描画する。
4. `t = 1` では、到着矩形に対応するローカル矩形でオブジェクトを到着先へ所属させる。同じ描画更新で移動レイヤーから取り除き、到着先の操作条件を適用する。

到着矩形は、その描画更新時点での到着先の変換と確保済みの配置枠から算出する。画面共通倍率と基準原点も現在値を使う。これにより、移動中に到着先が開閉したり画面サイズが変わったりしても、最後の移動矩形と到着先での最初の矩形が一致する。出発矩形は取得時の画面基準座標を保持する。

## 固有の描画・演出

移動管理は、オブジェクトへ移動の開始・進捗・到着を渡す。描画側は、所属エリアまたは移動レイヤーから渡された矩形の内側に、同じインスタンスの現在の見た目を描く。移動管理が扱うのは矩形と進捗までとし、カードの表裏を切り替える時点や描画方法はオブジェクト側が決める。到着後も移動中に更新した演出状態を引き継ぐ。

## インターフェース

公開入口は `src/ui/areaTransition/index.js`。ライブラリは JavaScript で実装し、以下の型は契約を示す。座標系の異なる矩形は各メソッドの引数名で区別する。

```ts
type Rect = Readonly<{ x: number; y: number; width: number; height: number }>;
type Transform = Readonly<{ x: number; y: number; scale: number }>;
type SlotId = string;

type MoveFrame =
  | { phase: "started"; progress: 0 }
  | { phase: "moving"; progress: number }
  | { phase: "arrived"; progress: 1 }
  | { phase: "cancelled"; progress: number };

interface MoveRenderContext {
  readonly layer: "area" | "transition";
  readonly viewportRect: Rect;
  readonly interactive: boolean;
  readonly scale: number;
}

interface MoveObject {
  readonly id: string;
  readonly area: MoveArea | null;
  interactive: boolean;
  setArea(area: MoveArea | null): void;
  onMoveFrame(frame: MoveFrame): void;
  render(context: MoveRenderContext): void;
}

interface Departure {
  readLocalRect(): Rect;
  detach(): void;
  restore(): void;
  release(): void;
}

interface Arrival {
  readLocalRect(): Rect;
  attach(): void;
  release(): void;
}

interface MoveArea {
  readonly id: string;
  setTransform(transform: Transform): void;
  setPresentation(options: { visible?: boolean; interactive?: boolean }): void;
  setSlot(id: SlotId, localRect: Rect): void;
  deleteSlot(id: SlotId): boolean;
  place(object: MoveObject, id: SlotId): boolean;
  remove(object: MoveObject): boolean;
  render(): void;
  renderObject(object: MoveObject): void;
  readTransform(): Transform;
  reserveDeparture(object: MoveObject): Departure | null;
  reserveArrival(object: MoveObject, slot: SlotId): Arrival | null;
}

interface TransitionSurface {
  readViewportTransform(): Transform;
  clearFocus(object: MoveObject): void;
  renderInArea(object: MoveObject, viewportRect: Rect, interactive: boolean, area: MoveArea, scale: number): void;
  removeFromArea(object: MoveObject, area: MoveArea): void;
  renderMoving(object: MoveObject, viewportRect: Rect, scale: number): void;
  removeMoving(object: MoveObject): void;
  scheduleFrame(callback: (nowMs: number) => void): void;
}

interface MoveRequest {
  object: MoveObject;
  from: MoveArea;
  to: MoveArea;
  slot: SlotId;
  durationMs: number;
  signal?: AbortSignal;
}

type MoveResult =
  | { status: "arrived" }
  | { status: "cancelled" }
  | { status: "rejected"; reason:
      "invalid-request" | "already-moving" | "source-unavailable" | "slot-unavailable" };

interface MoveManager {
  move(request: MoveRequest): Promise<MoveResult>;
}

declare function createMoveManager(surface: TransitionSurface): MoveManager;
```

### 公開APIの使い分け

| API | 使い方 |
| --- | --- |
| `createDomTransitionSurface(root, transform?)` | ブラウザーの画面にエリア描画層と移動描画層を作る。CSSピクセルのビューポート原点で描画できるよう、変形の影響を受けないルート（例として `document.body`）を渡す。 |
| `new MoveArea(id, surface, transform?)` | 原点と固有倍率を指定してエリアを作る。同じ画面のエリアと移動管理には同じ描画面を渡す。 |
| `setSlot(id, rect)`、`deleteSlot(id)`、`place(object, id)`、`remove(object)` | 枠を登録・更新し、オブジェクトを初期配置・除去する。枠は一度に1個を収容する。配置・除去できた場合は `true` を返す。空いていて予約されていない枠は `deleteSlot` で削除できる。 |
| `setPresentation(options)`、`setTransform(transform)` | エリアの表示・操作可否や座標変換を更新する。非表示にしても枠と所属は保持する。 |
| `new MoveObject(id, element?)` | 任意のオブジェクトを作る。DOM描画面で使う場合は専用の `HTMLElement` を渡す。描画枠いっぱいに表示する場合は要素の幅・高さを `100%` にする。 |
| `createMoveManager(surface).move(request)` | エリアをまたいでオブジェクトを移す。 |

共通倍率やビューポート原点を変更する場合は、描画面の `setViewportTransform(transform)` の後に各エリアの `render()` を呼ぶ。移動中のオブジェクトには次の描画更新から反映される。オブジェクト固有の `interactive` を変更した場合も、所属エリアを再描画する。予約メソッド、`renderObject`、`setArea` はエリアと移動管理の間で使う。

`createDomTransitionSurface(root, transform?, options?)` の第3引数では、`areaRootFor(area)` で所属コンポーネントの描画ホスト、`transitionRoot` で移動中の描画ホストを指定できる。省略時は両方ともrootを使用し、所属層より後のDOM順に移動層を置く。ホストを分ける場合は呼び出し側で背景との重なり順を指定する。各ホストはビューポートと同じ座標系で、座標を変えるtransformを祖先に持たないこと。

描画コンテキストの `scale` は、エリア固有倍率と現在の共通倍率の積。移動中は出発時のエリア倍率と到着先の現在の倍率を、矩形と同じ進捗で補間してから共通倍率を掛ける。DOM描画面はビューポート矩形の幅・高さを `scale` で割った寸法でラッパーをレイアウトし、左上を基準にラッパー全体へ CSS の `scale()` を適用する。固定寸法の子要素や文字も拡縮される。

### 呼び出し側と実装側の約束

- `MoveObject.id` は画面内で一意とする。`readTransform` は画面基準座標でのエリア原点とエリア固有倍率を返し、`readViewportTransform` はビューポート上の基準原点と共通倍率を返す。両方の `readLocalRect` は各エリア内の矩形を返す。
- 画面の初期化時に、共通の移動レイヤーを扱う `TransitionSurface` を渡して、画面ごとに1つの `MoveManager` を作る。ゲーム側は、配置済みのオブジェクトと出発元・到着先、到着先が発行した枠ID、有限かつ0以上の移動時間を指定する。出発元と到着先は異なるエリアとする。ゲーム側は結果に応じて進行を制御する。移動管理は描画上の所属だけを更新する。
- エリアは `reserveDeparture` で現在のローカル矩形と元の配置を確保し、`reserveArrival` で到着枠を確保する。確保できなければ `null` を返す。到着枠のローカル矩形はレイアウト更新に追随する。エリアは枠の確保中、その枠を別のオブジェクトに割り当てず、エリアを閉じても変換と枠を保持する。
- `detach`、`restore`、`attach` は、エリア内の描画登録と所属を同期して更新する。エリアだけが `setArea` を呼び、`detach` は `null`、`restore` と `attach` は自身を渡す。復帰時のローカル矩形は元の配置枠の現在値を使う。確保済みの操作は同期的に完了し、`release` は確保を解除する。
- 描画面は、単調増加する同一のミリ秒時計で描画更新を予約する。`renderMoving` は共通の移動レイヤー上で対象を登録または更新し、`removeMoving` はその対象の描画だけを解除する。`renderMoving` は `layer: "transition"` と `interactive: false` でオブジェクトを描画する。エリアは `layer: "area"` と実際の操作可否を渡す。移動開始時に描画面がフォーカスを解除し、エリアから外れた時点でエリア側の入力登録も解除される。
- `onMoveFrame` と `render` は同期処理とし、例外を送出したり、所属や確保を変更したりしない。共通ベースクラスは `id` と `area` を保持し、固有演出が不要なら `onMoveFrame` を空の処理にできる。派生側は `render` と必要な演出を実装する。

### 呼び出し順と結果

1. 移動時間が負または有限でない場合や、出発元と到着先が同じ場合は `invalid-request` を返す。すでに受付済みの同一オブジェクトIDには `already-moving`、すでに中断された `signal` には `cancelled` を返す。所属が出発元と一致しないか出発枠を確保できない場合は `source-unavailable`、到着枠を確保できない場合は `slot-unavailable` を返す。途中で受付を拒否した場合は取得済みの確保を解除し、描画上の所属を維持する。両方の確保に成功した時点で、同一IDの再受付を止める。
2. 最初の描画更新で出発矩形を画面基準座標へ変換して保持する。フォーカスを解除し、`detach`、`started` の通知、移動レイヤーでの描画を同じ更新内で行う。初回の時刻を `startMs` とし、以後の進捗を `min((nowMs - startMs) / durationMs, 1)` とする。途中の更新では `moving` を通知してから描画する。
3. 進捗1の更新では、到着先の現在の矩形を確定し、移動レイヤーから外して `attach` を呼び、`arrived` を通知してから到着先で描画する。両方の確保と移動中の登録を解除した後、`arrived` を返す。移動時間が0の場合は同じ更新内で `started` から `arrived` まで処理し、到着先だけで描画する。
4. 確保後に中断された場合は、次の描画更新で処理する。出発済みなら移動レイヤーから外し、`restore` を呼び、最後に通知した進捗で `cancelled` を通知する。出発前なら所属を維持する。両方の確保と移動中の登録を解除した後、`cancelled` を返す。終了処理後に届いた中断は結果に影響しない。

### 利用例

ブラウザーのモジュールで次のように呼ぶ。import は `src/` 直下のモジュールを想定する。画面外のエリアにボタンを配置し、画面内の倍率2のエリアへ移す。

```js
import {
    MoveArea, MoveObject, createDomTransitionSurface, createMoveManager,
} from './ui/areaTransition/index.js';

const surface = createDomTransitionSurface(document.body, { x: 0, y: 0, scale: 0.5 });
const deckArea = new MoveArea('deck', surface, { x: -300, y: 100, scale: 1 });
const handArea = new MoveArea('hand', surface, { x: 200, y: 100, scale: 2 });
const slotRect = { x: 0, y: 0, width: 100, height: 120 };
deckArea.setSlot('top', slotRect);
deckArea.setPresentation({ visible: false, interactive: false });
handArea.setSlot('hand-3', slotRect);

const button = document.createElement('button');
button.textContent = '移動する駒';
Object.assign(button.style, { width: '100%', height: '100%' });
const piece = new MoveObject('piece', button);
deckArea.place(piece, 'top');

const transitions = createMoveManager(surface);
const result = await transitions.move({
  object: piece,
  from: deckArea,
  to: handArea,
  slot: "hand-3",
  durationMs: 300,
});
console.log(result.status, piece.area?.id); // arrived, hand
```

中断可能にするには、要求に `AbortController` の `signal` を渡し、必要になった時点で `abort()` を呼ぶ。ゲーム状態への反映時期と中断後の進行はゲーム側で決める。

山札と手札は、カードの代わりに同じ `MoveObject` を満たす駒も受け取れる。カードを裏から表にする場合は、カード側の `onMoveFrame` が進捗を受け取り、例えば0.5以上で表にする。中断時は、同じフックで出発前の表裏に戻す。

## 変換と状態の例

以下は直線補間の例。ビューポートは `800 × 450`、画面基準原点は `(0, 0)`、共通倍率は `0.5`。矩形を `(x, y, 幅, 高さ)` で示す。到着先は表示中で、到着後の操作条件を満たすものとする。

### 異なる倍率のエリア間

出発元の原点は `(100, 100)`、倍率は `1`。到着先の原点は `(600, 100)`、倍率は `2`。両エリアでローカル矩形を `(20, 40, 80, 120)` とする。

| 時点 | ビューポート上の矩形 | 所属と操作 |
| --- | --- | --- |
| 出発直前 | `(60, 70, 40, 60)` | 出発元に所属し、操作可 |
| 移動開始 | `(60, 70, 40, 60)` | 所属なし、操作不可 |
| 中間 | `(190, 80, 60, 90)` | 所属なし、操作不可 |
| 到着 | `(320, 90, 80, 120)` | 到着先に所属し、操作可 |

### 画面外のエリアから画面内へ

出発元の原点は `(-300, 100)`、倍率は `1`。到着先の原点は `(200, 100)`、倍率は `1`。両エリアでローカル矩形を `(0, 0, 100, 120)` とする。

| 時点 | ビューポート上の矩形 | 所属と操作 |
| --- | --- | --- |
| 出発直前 | `(-150, 50, 50, 60)` | 画面外の出発元に所属し、操作不可 |
| 移動開始 | `(-150, 50, 50, 60)` | 所属なし、画面外、操作不可 |
| 中間 | `(-25, 50, 50, 60)` | 所属なし、右半分が見える、操作不可 |
| 到着 | `(100, 50, 50, 60)` | 到着先に所属し、操作可 |
