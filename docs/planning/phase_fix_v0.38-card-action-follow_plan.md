# 着手ボタンのカード追従計画

## 合意内容

- 対象バックログ: 「ドロー・プレイの演出中に着手ボタンをカードに追従させる」。
- 開発ブランチ: `fix/v0.38-card-action-follow`。
- 予定バージョン: `0.38.0`。計画中は現行の `0.37.1` を維持し、初回の実装開始時に `package.json` と `package-lock.json` を更新する。
- 計画フェーズ開始と本計画のスコープ・完了条件・予定バージョン・ブランチ名は、チャットでそれぞれオーナーの合意を得た。

## スコープ

日次・効果ドローおよび手札からの着手で、着手ボタンの位置を対象カードの移動に追従させる。残る手札の再配置も対象とする。ボタンの固定倍率表示と既存の操作制御を維持する。

対象外はイーゼルのプール化、カードのCanvas統合、旧評価用ダイス一覧の生成抑止、効果UI、ゲーム終了画面など、ほかのバックログ項目。MP28-02の原因調査・修正も含めない。要求仕様書と共通リポジトリは変更しない。

## 現状と実装方針

- `handPresentation.js` は手札の最終スロットから着手ボタンの位置を計算し、手札エリアの固定倍率層へ配置している。
- `cardScene.js` はカードの現在姿勢をフレームごとに描画する。`layoutPresentation.js` の描画後コールバックは現在枚数表示の更新に使用している。
- 現在姿勢と既存の座標変換を使って、カードに対応するボタン位置を更新する。カードIDで対応させ、配列順だけに依存しない。
- 固定倍率層のボタン寸法・文字サイズを維持する。移動中の位置・重なり・表示期間は小さな実装単位で提示し、オーナーと調整する。
- ドロー・着手の開始、途中、完了時で飛びや残留が起きないよう、ボタンの生成・撤去と描画更新の順序を確認する。
- 既存の演出中の操作遮断を維持する。返却等で共有しているボタン配置を変更する場合は、その既存操作も回帰確認する。
- A/B切替・リサイズ・固定倍率変更時は最新の座標変換を使用する。動きを減らす設定では最終位置を正しく反映する。
- 実装に合わせて関連する実装仕様・開発用検証案内を必要な範囲で更新する。

## 完了条件

1. 日次・効果ドロー中に、着手ボタンが対応するカードの移動へ追従する。
2. 着手中の対象カードおよび残る手札の再配置にボタンが追従し、完了時に正しい表示へ移行する。
3. レイアウトA/B、演出中の切替・リサイズ、固定倍率変更で位置ずれやボタンの残留がない。
4. 固定倍率の表示と操作制御を維持し、演出中に二重操作できない。動きを減らす設定でも配置が正しい。
5. 対象検証・全テスト・本番ビルドの結果を実装報告へ記録し、必要なオーナー検証の判断と対応を記録する。

## 検証方針

- 座標計算や状態管理に複雑なロジックを追加する場合は、先に意味のある対象テストを定義する。
- ブラウザー検証ではカードIDごとに演出途中のカードとボタンの位置関係を確認し、最終位置だけの検証で追従の成功としない。
- 日次・複数枚の効果ドロー、着手と残る手札の再配置、A/B・リサイズ・固定倍率変更、動きを減らす設定を確認する。
- `checkCardInteraction.cjs`、カードシーン関連の既存検証を変更内容に応じて使用し、着手・返却・詳細表示・演出中の操作遮断を回帰確認する。
- 終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行し、コマンド・結果を実装報告へ記載する。
- 常用サーバーはAI側で再起動しない。表示版が一致しない場合は報告し、必要に応じて既存のdist置換検証を使い、開発画面の確認と区別する。

## オーナー検証

確認可能な実装ができた時点で、配置・表示期間・重なり方を提示する。完成後の一括確認にしない。

- `MP38-01`: 日次・効果ドロー時の着手ボタンの追従と、到着時の見た目。
- `MP38-02`: 着手するカードと残る手札への追従、ボタンの撤去・最終配置。
- `MP38-03`: A/B切替・リサイズ・固定倍率変更・動きを減らす設定での見た目と操作。

各項目は実装時に確認理由・具体的な操作手順・期待結果・設定と画面に一致する確認バージョンを提示する。未回答は保留扱いにせず、オーナーの判断を得る。修正が必要なフィードバックは実装中に対応して再提示する。
