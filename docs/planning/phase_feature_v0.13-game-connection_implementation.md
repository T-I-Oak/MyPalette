# v0.13 ゲーム接続 実装報告

## 実装内容

初回実装の確認バージョンは0.13.0。package.jsonとpackage-lock.jsonを更新した。最新の修正版は0.13.1で、GC-R01への対応は末尾に記録する。

- プレイヤー向け入口で保存済みカード設定を読み込み、構造検証と制作途中の検証を行って自動起動する。取得中・取得失敗・不備による開始拒否と再読み込みを表示する。設定の補完・保存はしない。
- Game生成と操作受付・更新通知をsession.jsへ分離し、評価用ゲームも同じセッションと操作処理を使用する。エンジン・ルール・保存済みカード設定・共通リポジトリは変更していない。
- view.jsの描画先にpresentationを追加し、layoutPresentation.jsが7エリア別のホストを管理する。情報・日次操作はinfo、制作中はplay、所持ダイスはpalette、ストックはstock、山札枚数はdeck、捨て札はdiscard、手札はhandに割り当てた。
- 各ホストをMoveObjectとしてCanvasAreaへ所属させ、描画層と論理寸法・座標変換を利用する。subscribeで配置変更に追従し、ゲーム状態を変更せず同じDOM・選択を維持する。パネルを閉じると所属DOMを画面から外し、再表示では同じ内容を戻す。
- 既存部品のカード詳細、ダイスの面構成・選択・リロール、カードのプレイ・達成を利用する。捨て札のカードも詳細確認できる。出荷済み作品・進行記録は情報エリアのボタンからダイアログで確認する。
- 候補・対象選択、仕事終了・翌日開始、信用0による結果、再プレイを接続した。再プレイでは旧画面・監視・移動・選択を破棄し、新しいGameを生成する。
- 仮表示ではエリア内のスクロールで情報と操作へ到達する。プレイヤー向けでは移動演出を省略し、状態を即時反映する。評価用ゲームの移動演出と開発者用4画面は維持した。
- screen_layout、playable_game、開発手順とバックログの残作業説明を更新した。正式実装の順序は情報表示、手札、プレイ、パレット、ストック、デッキ、捨て札のまま維持する。

### 失敗の調査と対応

- 最初の対象テストではローカル接続EACCES、一時ファイルrenameのEPERMが発生。サンドボックス制限外で同じテストを再実行し、36件すべて成功した。

## 0.13.1：GC-R01への対応

### 原因と修正

- レビュー指摘GC-R01を受け、package.jsonとpackage-lock.jsonを0.13.1へ更新した。
- 閉じたパネルのホストはルートDOMから外れるため、view.jsのreleasePaintingIcons(scope)ではその内部のアイコン監視を解除できなかった。presentation.clearが旧内容を削除すると、監視だけが残存していた。
- layoutPresentation.jsのclearで、所有する各ホストにreleasePaintingIconsを適用してからreplaceChildrenするよう変更した。DOM接続の有無に依存せず、再描画、ゲーム終了後の再プレイ、入口復帰時のview破棄とpresentation.disposeを同じ処理で扱う。
- 画面レイアウト仕様に解放責務を追記した。ゲームルール・設定データ・正式UI・共通リポジトリは変更していない。

### 回帰検証

修正前にscripts/checkIconCleanup.cjsを追加し、headless Edge、390×844、乱数0.4固定で再現した。ResizeObserverのobserve/unobserve/disconnectを記録し、登録中のPaintingIconFrameを「現在のDOMまたは現在の非表示ホストが所有する対象」と照合する。単に非接続であることを異常とせず、破棄済みの対象と現在の非表示対象を区別する。

- 修正前：最初の日次更新で登録37、現在の所有対象23、破棄済みの残存14となり、テストが意図どおり失敗した。
- 修正後：パネルを閉じたまま12回更新し、うち再プレイ2回を含めて、すべての時点で残存0・現行対象の監視漏れ0を確認した。登録数は26→23→29→32→26→26→26→23→29→32→26→26→26で、現在の所有対象数と一致した。
- パネルを再表示し、ストックの全アイコンにCanvasが生成されることを確認した。
- パネルを閉じたまま入口へ戻り、次の設定読込みをテスト用に失敗させて新規マウント前の状態を確認した。登録アイコン0、エリアホスト0となった。再読み込みで新しいpresentationを生成した後も残存0・監視漏れ0を確認した。
- ページ例外は0件。テスト用通信差替えは保存済みカード設定を変更しない。
