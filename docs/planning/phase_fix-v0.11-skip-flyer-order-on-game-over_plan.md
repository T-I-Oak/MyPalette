# ゲーム終了が確定する日のチラシ発注

予定バージョンは `v0.11.0`、開発ブランチは `fix/v0.11-skip-flyer-order-on-game-over` とする。

## 開発範囲

ターン終了時に特殊面効果を予約し、通常面の未使用ダイスを消費してチラシを制作する。制作後に残った未使用ダイスを数え、その後の信用更新で信用が0になるかを発注前に判定する。終了が確定している場合は、完成したチラシと制作途中の進捗を保持したまま信用更新と終了判定に進む。カードの選択・取得、チラシの消費、次回の発注必要枚数の増加は行わない。

信用が残る日は、必要枚数に達したら従来どおり発注する。この場合、ストックが空ならチラシの消費と次回必要枚数の増加まで行う。

## 対象外

- 名声の計算と特殊面効果の発動時期、信用減少の計算規則、カード効果によるストック取得の変更。
- プレイヤー向けUI、3Dダイス、カード演出、追加要素の開発。

## 実装・テスト方針

1. `docs/requirements/01.game_rules.md` の発注手順に終了確定時の条件を追記し、`tests/spec/rules_01_game_flow.test.js` でその挙動を定義する。
2. `src/game/engine.js` のターン終了処理で、チラシ制作後の未使用ダイス数を発注の判定と後続の信用更新に使う。信用値を実際に更新する時点は発注処理の後とする。`docs/spec/09.playable_game.md` に処理順を反映する。
3. `tests/implementation/game/engine.test.js` の既存ケースは、ストックが空でゲームが続く場合と、信用が0になり終了する場合を分ける。対象テスト、全テスト `npm.cmd test`、本番ビルド `npm.cmd run build` を実行し、結果を実装報告に記録する。

## 完了条件

- 公開ストックがあり、チラシが発注に必要な枚数に達していても、信用が0になる日はカード選択を挟まず終了する。完成チラシ、制作途中の進捗、次回必要枚数は制作直後の値を保持する。
- 特殊面効果の予約とチラシ制作で消費したダイスを信用減少から除外する。チラシ制作によって信用が残る日は、必要枚数に達していれば公開カードを選んで取得できる。
- ストックが空で信用が残る日は、チラシが消費され、次回必要枚数が2枚増える。
- 対象テスト、全テスト、本番ビルドが成功する。
