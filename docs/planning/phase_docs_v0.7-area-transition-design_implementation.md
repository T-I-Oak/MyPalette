# v0.7 エリア・移動ライブラリの実装報告

## 計画に対する成果

- 合意した範囲を[計画書](phase_docs_v0.7-area-transition-design_plan.md)に反映し、`src/ui/areaTransition/index.js` を公開入口とするライブラリを実装した。
- `MoveArea` は座標変換、枠の登録・確保、初期配置と所属、表示・操作可否を扱う。`MoveObject` は識別子、所属、固有演出のフックを持つ。
- `createMoveManager` は枠を確保して、出発・移動・到着を進める。枠の競合を検出し、中断時には元の枠へ復帰する。
- `createDomTransitionSurface` はエリアと移動の描画層を生成し、移動中のポインター入力とフォーカスを遮断する。
- [実装仕様](../spec/13.area_transition.md)に公開API、枠の受け渡しと結果、画面外のエリアから汎用ボタンを移す利用例を記載した。
- 評価用ゲームの `src/game/areaTransitions.js` と `src/game/view.js` で、既存のタブ・グリッドをライブラリに接続した。山札・ストックから手札、手札から制作中、手札・制作中から捨て札、候補から所持ダイスへの経路を扱う。既存のグリッドが静止時の配置を持ち、移動中の到着座標はタブの表示状態に追随する。
- カードは右からストック、山札、手札、制作中、捨て札と流れる配置を基本とした。非表示のストック・山札は右、非表示の捨て札は左に置いた。
- `src/game/effects.js` と `src/game/engine.js` に、候補選択と獲得ダイスIDの対応を表示側へ伝えるコールバックを追加した。複数個のダイスが所持欄に追加されるタイミングはゲームルールに従う。
- [バックログ](backlog.md)の「UIの実装」に、狭い画面でのエリア配置・倍率・表示方式の設計を追記した。
- カードの移動方向に関するフィードバックを受け、`package.json` と `package-lock.json` を `0.7.4` に更新した。

## v0.7.5 レビュー指摘への対応

- エリアは固有倍率と画面共通倍率の積を描画面に渡す。移動管理はエリア倍率を移動の進捗で補間し、現在の共通倍率を掛ける。DOM描画面はローカル寸法のラッパー全体をCSSで拡縮し、固定寸法の子要素も追随させる。
- 評価用ゲームは、山札にカードの表示要素がないとき、再描画前の枚数表示から出発位置を取得する。枚数表示も非表示の場合は画面右の外を使う。移動中の見た目は手札側のカードから取得する。
- バージョン設定を `0.7.5` に更新した。個別のオーナー検証項目はなし。
