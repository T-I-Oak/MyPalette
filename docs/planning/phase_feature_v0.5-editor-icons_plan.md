# v0.5 カード設定・ゲームバランス確認のアイコン表示と開発サーバー起動

## 合意内容

- 予定バージョン: v0.5.0。
- ブランチ: `feature/v0.5-editor-icons`。
- ゲーム画面の組み換え式UI・3Dダイス組込みより先に、本計画の2項目を実施する。
- バージョン設定は実装開始時に更新する。計画では現在のv0.4.2を維持する。

## 開発スコープ

### 開発サーバー

- `npm.cmd run dev`でポート3000を使用する。オーナーの指示により、ブラウザーは手動で開く。
- ベースパスを`/MyPalette/`とする。開くURLは`http://127.0.0.1:3000/MyPalette/`を基本とする。
- 設定保存APIの利用条件に合わせて、ホストは`127.0.0.1`を維持する。
- ポート使用中はVite標準の次ポートへの移行を許容し、実際に割り当てられたURLを開く。
- ベースパス変更に伴う入口、各確認画面、設定読込み、画像、保存APIの参照を整合させる。
- 開発環境の文書を実際の起動方法に合わせる。

### カード設定UI

- 全体一覧の目標・プレイ時効果・達成時効果を、既存の共通アイコンで表示する。
- 編集画面の目標式と設定済み効果も共通アイコンで示す。
- 効果種類・パラメータ・目標条件の入力欄、追加・削除・並べ替え操作は維持する。
- 入力変更後は対応するアイコンと説明を即時更新する。全体一覧へ戻った際も最新の値を表示する。
- 各アイコンのホバーで、数量・色・画材・所持期間等を含むテキスト説明を表示する。
- キーボードのフォーカスでも同じ説明を確認でき、支援技術から意味を読み取れるようにする。
- 目標のAND/ORと効果の実行順を識別できるようにする。
- 効果なし・目標なしと、種類未設定・パラメータ不足を区別する。
- 不完全な設定を別の効果や既定パラメータで補完せず、未設定表示と説明を用意する。
- 横長の複合アイコンは縦横比を維持し、数量や構成要素が欠けない表示とする。
- 一覧の折返し切替はアイコン列でも意味のある表示にし、内部スクロールで全内容へ到達できるようにする。

### ゲームバランス確認画面

- 評価用ゲームの手札・制作中・公開ストック・出荷済み作品と、カードを扱う対象選択で、カードの目標・プレイ時効果・達成時効果を共通アイコンで表示する。
- 全ステップ表示にも適用し、現在ステップ・目標のAND/OR・効果の実行順を識別できるようにする。
- 設定画面と同様にホバーとキーボードフォーカスでテキスト説明を確認できるようにする。
- 達成可能表示、プレイ・達成・効果対象選択などの既存操作と、ゲーム状態の表示を維持する。
- 進行記録・状態値・操作ボタンまで一律にアイコンへ置き換えることは含めない。

## 対象外

- 上記アイコン適用以外のゲーム画面改修、組み換え式UI、3Dダイスのゲーム進行への組込み。
- カード制作段階画像、キャンバス・イーゼル、作品進行・出荷演出。
- 再利用効果以外の新しいゲーム効果の追加、ゲームルールや保存JSON形式の変更。
- ランキング、アチーブメント、ギャラリー。
- エディターのモバイル対応、他ゲーム・共通リポジトリの変更、公開・デプロイ設定。

## 実装方針

- `vite.config.js`で起動ポートとベースパスを設定する。
- `src/settingsStorage.js`と`scripts/cardSettingsPlugin.js`の保存先URL・ミドルウェア接続を実際のサーバーで照合する。
- `src/icons/render.js`の`effectIconCanvas`・`goalIconCanvas`を再利用し、図形を複製しない。
- 目標・効果のアイコンと説明の組合せを共通の表示部品にまとめ、設定の一覧・編集画面と評価用ゲームで利用する。
- 説明は`cardSummary.js`等の既存表現を利用する。フォーカス時にも表示できるツールチップを用意し、title属性だけに依存しない。
- アイコンAPIが不完全な設定を拒否する契約を尊重し、描画前に設定の妥当性を判断する。
- 色・質感・機能・状態は共通CSS規約と`docs/spec/11.shared_ui_style.md`に従う。
- `docs/spec/08.card_editor.md`と`docs/spec/09.playable_game.md`、必要に応じて共通アイコン仕様と開発文書を更新する。要求仕様は変更しない。
- 合意した2項目をバックログの優先作業として記録し、実装後は残作業との対応を整理する。

## 検証方針

- 複雑な設定判定や表示状態管理を追加する場合は、実装前にテストで期待挙動を定める。
- 既存15効果、各目標条件、AND/OR、複数効果の順序、数量・負値、未設定を確認する。
- 種類・パラメータ変更、追加・削除・並べ替え、一覧への復帰、保存・再読込みを確認する。
- 評価用ゲームでは手札・制作中・公開ストック・出荷済み・カード対象選択・全ステップ表示のアイコンと説明を確認する。プレイ・達成・効果選択の結果と達成可能表示が従来のルールに一致することを確認する。
- ブラウザーでホバー・キーボードフォーカスの説明、表示の欠け、内部スクロール、折返し、JavaScriptエラーを確認する。
- 開発起動時の実URL、各入口・画像・設定読込み、同一Originの保存を確認する。
- 保存確認は既存のカード設定を不用意に書き換えない方法で実施する。
- `/MyPalette/`配下の本番ビルドをpreview等で確認し、画像・設定・各画面への参照が解決することを確認する。
- 実装終了草案の前に対象テスト、`npm.cmd test`、`npm.cmd run build`を実行し、結果を実装報告へ記録する。
- 自動確認と実ブラウザーで確認した範囲を区別して記録する。

## 完了条件

- 合意した起動方法でブラウザーが開き、画像・設定・各画面を正常に読み込める。
- ローカル開発サーバー上で保存・再読込みが正常に動作する。
- 設定の一覧・編集画面と評価用ゲームのアイコン・説明が設定値・現在ステップ・効果順に一致する。
- 設定途中でも画面が壊れず、未設定箇所を識別して編集できる。
- ホバーとフォーカスの両方で説明を確認でき、横長アイコンや説明が操作不能な位置へ欠落しない。
- 編集・保存・目標確率表示と、評価用ゲームの進行・達成・対象選択の既存機能を維持する。
- 全テストと本番ビルドが成功する。失敗があれば共通手順に従い調査・対応を記録する。
- 起動動作とアイコンの判読性・説明・編集操作をオーナー検証として提示し、判断と対応を記録する。

## 実装中の追加合意

- 効果の種類別（特殊面変更は面別）、プレイ時・達成時別の評価点と共通ステップ倍率を編集する画面を追加する。小数を許可し、数量倍・符号付き名声amount倍を適用する。各ステップの効果合計点×倍率を合計してカード評価点とする。カード設定とは別のメタデータファイルに保存し、同じ保存操作で書き込む方針に合意済み。

- オーナーの指示により、追加・編集はダイアログで行い、通常画面には目標・効果の入力欄を常設しない。
- ダイアログで成立しない入力は確定ボタンを無効化する。既存の制作途中設定は保持し、修正できるようにする。
- オーナーの明示指示により、要求仕様06の6節に定義された使用済みダイスの再利用をゲーム効果・設定候補へ追加する。既存の共通アイコンを再利用し、対象選択・出目変更・リロールは行わない。

- オーナーの指示により、各ステップの期待試行回数の合計によるカード難易度を、編集画面のカード名右と一覧のステップ0左へ表示する。計算用ダイス数は現行のグレード別設定を使用する。
