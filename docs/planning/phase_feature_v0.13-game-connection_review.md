## GC-R01 [P2] 非表示エリアのアイコン監視を解放してから内容を破棄する

- 対象: src/game/layoutPresentation.jsのclear（23〜24行）、src/game/view.jsのrender（245〜246行）およびdispose（363〜365行）。
- 縦長Bの閉じたパネルではMoveAreaが所属ホストをDOMから外す。この状態でview.jsがreleasePaintingIcons(scope)を呼んでも、rootの子孫ではないストック・捨て札のアイコンを探索できない。続くpresentation.clear()は各ホストの内容をreplaceChildrenで破棄するが、ResizeObserverのunobserveは行わない。
- 日次進行・再描画のたびに、破棄されたPaintingIconFrameの監視が残る。再プレイでも同じ経路を通り、旧ゲームの監視対象が残る。計画の旧ゲームの表示・監視の解放方針に反する。
- 再現: headless Edge、390×844、Math.randomを0.4に固定し、初期状態からパネルを閉じたまま「一日の仕事を終える」「翌日の仕事を始める」（終了時は「もう一度遊ぶ」）を6回進める。ResizeObserverのobserve/unobserveを記録すると、登録中の全対象数は27→67→107→135→175→215→243、うち非接続のPaintingIconFrameは14→48→94→122→156→202→230となった。初期の14個は現在の非表示ホスト内だが、進行後は破棄した旧内容の登録が累積している。
- 修正方針: 各ホストを所有するpresentation側で、DOM接続の有無によらずアイコン監視を解放してから内容を削除する。再描画、ゲーム終了後の再プレイ、入口への復帰・presentation破棄の各経路を確認する。
- 再検証: Bでパネルを閉じたまま日次更新・再プレイしても、破棄したアイコンの監視が残らないこと。現在の非表示ホストに必要な監視と、破棄済み対象を区別して検証する。再表示したカードのアイコンが描画されることも確認する。
