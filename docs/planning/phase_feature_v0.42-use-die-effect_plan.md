## 効果の契約

1. 効果IDを `discardDice` から `useDie` へ置換する。新形式は `{ type: 'useDie', count: N }` とし、従来の個数設定を維持する。Nは1以上の整数とする。
2. 所持する未使用ダイスから任意のN個（不足時は未使用分すべて）を選び、`used` をtrueにする。使用済みダイスは選択できない。
3. 永続・一時の両方を対象とする。所持から取り除かず、ID・面構成・現在面・所持期間を維持する。リロールや特殊面の発動は伴わない。通常面・特殊面とも対象とし、使用済みの特殊面は即時適用・日末の対象から外れ、再利用で戻る。
4. 未使用ダイスがなければ選択を要求せず完了し、後続効果へ進む。
5. 再利用効果で使用可能へ戻せる。永続ダイスは翌日の開始処理で使用可能へ戻り、一時ダイスは既存の日末処理で回収される。
6. パレットの使用済み表示と達成可能表示を状態変更に追従させる。
7. アイコンはグレーのダイスと丸囲みのグレーのチェックマークを組み合わせ、ゴミ箱を廃止し、個数表示は共通規則を維持する。名称・説明を「未使用ダイスを指定個数使用済みにする」意味へ統一する。

## 調査結果と変更方針

- `src/effectCatalog.js` は現状 `discardDice` にquantityフィールドを定義し、設定フォームとデータ検証が共有している。新定義でもquantityフィールドを維持する。
- `src/game/effects.js` は現状count個を選び、所持配列から削除する。新効果は従来と同じ個数を選択してusedを変更する。既存の選択・通知・セッション更新経路との接続も確認する。
- `public/data/cards.json` の該当効果は6件（着手時3件・達成時3件）で、すべてcountは1。新IDへ移しcountを維持し、カードの他の設定は維持する。
- `dev-data/effect-evaluation.json` の旧IDを新IDへ移し、評価値は維持する。
- 保存形式は新IDへ統一する。旧形式の自動読込移行機構は追加せず、旧IDと不正なcountが検証で拒否されることを確認する。外部の旧JSONは新形式への更新を必要とする旨を設定仕様へ記載する。
- `src/icons/iconPlan.js`、描画・レビューケース、効果説明、一覧・通知・設定画面の表示を新定義に合わせる。関連参照を横断検索し、現行効果を破棄として説明する箇所を残さない。
- 主な文書対象は要求06の§5、実装仕様08・09・12・16・19の関連記述、開発ガイドの検証説明、バックログMP40-02・EUI-10。実際に関係する記述だけを更新し、MP40-02の完了削除はレビュー承認時に扱う。
- 既存の仕様テストは複数個の破棄を要求しているため、新契約のテストへ置換する。無関係な破棄（カードや一時ダイス回収等）の説明は変更しない。

## 実装・テスト方針

状態変更と効果連鎖は、先に新契約を示す失敗テストを作成してから実装する。

- 仕様テスト: 指定個数と不足時の全選択、通常面／特殊面、永続／一時、使用済み対象外、対象なし、所持・出目維持、再利用・翌日・日末の接続を確認する。
- データ・設定テスト: 新形式の往復、旧ID・不正countの拒否、保存済み6件、設定フォームの個数入力維持、評価メタデータの整合を確認する。
- アイコン・説明テスト: グレーのダイスと丸囲みのグレーのチェックマーク、ゴミ箱なし・共通規則の数量、説明と一覧表示の整合を確認する。
- エンジン・通知の結合テスト: 着手時／達成時、連続する使用済み化、対象なしの後続効果再開、特殊面が発動しないことを確認する。
- ブラウザー検証: 保存データを変更しない検証用fixtureで、永続／一時の選択、パレットと達成可能表示、対象なし、連続効果を確認する。A/B、選択中のリサイズ、固定倍率変更、動きを減らす設定も確認する。既存の選択UIの仕様は維持する。
- 対象テストに加えて、終了草案前に `npm.cmd test` と `npm.cmd run build` を実行し、コマンド・結果・失敗時の調査を実装報告へ記録する。
