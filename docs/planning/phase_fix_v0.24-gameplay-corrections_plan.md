# v0.24 ゲーム進行と操作の修正計画

- 予定バージョン: `0.24.0`
- 開発ブランチ: `fix/v0.24-gameplay-corrections`

## 開発範囲と完了条件

1. **全体更新ボタン**。制作中で選択・演出待ちがなく、リロール権と未使用ダイスがある場合、未使用ダイスの選択がゼロまたは全数なら有効にする。一部選択では無効にする。有効時は権利を1つ消費し、全未使用ダイスを振り直す。
2. **エリア移動時のStepタブ**。カードが別エリアへ移ると、そのカードの現在の制作ステップを表示する。制作ステップが変わらない移動にも適用する。同一エリア内の再描画と再配置ではタブ選択を維持する。
3. **カード効果の名声変更**。プレイ時・達成時それぞれの効果列で、名声の増減を先に適用する。名声変更同士および残りの効果同士の記載順は維持する。対象選択や演出による中断があっても各効果は一度だけ解決する。
4. **日末の特殊面「名声値＋1」**。対象ダイスは既存の日末処理で消費し、名声を日末処理の完了時に反映する。複数の対象があれば各面の効果を反映する。翌日の開始操作を待つ画面とゲーム終了日の最終結果で反映済みの名声を確認でき、翌朝に重複適用しない。
5. **翌朝の予約ダイス取得**。前日から予約された特殊面の効果で取得するダイスは、必要な候補選択の完了後に既存ダイスと一緒に通常ロールで一度だけ振る。プレイ中のカード効果や特殊面の即時適用による取得時は、既存の個別ロールを維持する。

## 対象外

レイアウト全体の正式化、効果UIの刷新、単体更新ボタン、ダイス選択操作、およびバックログ冒頭5件以外の項目。

## 実装方針

- `src/game/view.js` の全体更新可否判定で、未使用ダイスとそのうち選択中のダイスの個数を照合する。ロール処理は既存のゲームエンジンを利用する。
- `src/game/cardScene.js` のカードごとの表示状態でエリアの変化を検知し、タブ選択をリセットする。移動中の共通カード表示と着地後の表示で同じ制作ステップを使う。
- `src/game/engine.js` と `src/game/effects.js` の既存の効果解決を使い、カードのプレイ時・達成時の処理順を変更する。通知と名声表示も実際の処理順・反映時点に合わせる。
- 日末に名声変更と翌朝に予約する効果を分ける。日末の名声反映は翌日待ちとゲーム終了の両経路で行う。予約されたダイス取得には翌朝の通常ロールを使い、取得・候補選択・付与の処理は再利用する。
- `docs/requirements/01.game_rules.md` の特殊面の予約と解決時期を更新し、関係する実装仕様も合わせる。バージョン設定は初回実装フェーズで更新する。

## 検証方針

- 全体更新は選択ゼロ・一部・全数、未使用ダイスなし、権利なし、演出待ちで確認する。有効な操作で全未使用ダイスだけが対象になり、権利が1つ減ることを確認する。
- カード移動は別タブを選んだ同一Stepのカードを別エリアへ移して確認する。同一エリア内の再描画と動きを減らす設定も確認する。
- カード効果はプレイ時・達成時それぞれで、名声変更を選択待ちがある効果より後に記載したケースを検証する。
- 日末は複数の名声面、使用済みの名声面、翌日待ち、ゲーム終了、翌朝の二重適用防止を検証する。翌朝は既存ダイスと予約で得たダイスが単一の通常ロールに含まれることを確認する。`startRoll.test.js` の予約取得時の期待値を更新し、プレイ中の取得は個別に振ることも確認する。
- 実装中に対象テストとブラウザー検証を実施し、オーナー確認が必要な項目にはID、手順、期待結果、確認バージョンを付ける。実装終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行し、結果を実装報告へ記録する。
