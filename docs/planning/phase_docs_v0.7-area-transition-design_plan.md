# v0.7 エリア間移動の設計

## 開発スコープ

- 予定バージョンは `v0.7.0`、開発ブランチは `docs/v0.7-area-transition-design` とする。バージョン設定は実装フェーズの開始時に更新する。
- ゲーム内のエリアを、中のコンポーネントも含めて描画と拡縮を制御する単位とする。画面全体の共通倍率とエリアごとの倍率を扱い、非表示のエリアにも画面外の位置を持たせる。
- MyPalette内のライブラリとして、汎用エリア、移動オブジェクトの共通ベースクラス、移動管理、ブラウザー向けの描画面を実装する。エリア作成、枠登録、初期配置、表示・操作の制御、移動を公開APIで利用できるようにする。責務と呼び出し方を実装仕様書に記録する。
- 評価用ゲームに試験適用する。山札・ストックから手札、手札から制作中、手札・制作中から捨て札、ダイス獲得候補から所持欄への移動を扱い、非表示のエリアと既存のタブ切り替えを使って検証する。
- 将来のワイド画面は、画面サイズに合わせて縦横比を保ったまま全体を一様に拡縮する。狭い画面向けのエリア配置・倍率・表示方式の検討は、別の項目としてバックログに記録する。

## 設計方針

- エリア内での位置・大きさを画面上の座標・大きさへ変換する規約を定める。出発元と到着先で倍率が異なる場合や、どちらかが画面外にある場合も同じ規約で扱う。
- 出発元に所属している状態、どのエリアにも属さず画面上に直接描画する移動状態、到着先に所属する状態の遷移を定める。コンポーネントはエリアに属している間だけ操作対象になり得る。
- 移動の仕組みと、カードの表裏の切り替えなどオブジェクト固有の描画・演出の接点を定める。エリアの開き方は配置・表示側が扱い、移動側はそのエリアの位置と倍率を使う。

## 対象外

- プレイヤー向けゲーム本体への接続、カードデザイン・カードクラス、3Dダイスの組み込み。
- ワイド画面の具体的な配置、狭い画面での具体的な倍率・配置、サイドパネルやタブの選択・実装。
- 複数オブジェクトを順番に移動するか同時に移動するかという演出上の判断。

## 完了条件と検証

- 実装仕様書から、ベースクラスに持たせる責務、エリアと移動管理が受け渡す情報、描画・所属・操作対象が切り替わる境界を読み取れる。
- 公開APIで二つのエリアを作成し、汎用オブジェクトを配置してから移す。異なる倍率、画面外からの移動、操作可否、枠の競合、中断後の復帰を自動テストで確認する。
- 評価用ゲームの通常の操作で各経路を確認し、移動中にストック・山札・捨て札のタブを切り替えても、表示と到着位置が同期することを確かめる。
- 狭い画面向けのエリア配置を後続作業としてバックログで識別できる。
- `npm.cmd test` と `npm.cmd run build` を実行して結果を記録する。
