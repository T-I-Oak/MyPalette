# v0.29 ゲーム起動処理の整理

## 合意内容

- 対象バックログ: 「ゲーム画面に残る旧評価用の設定エラー表示と『入口へ戻る』を削除する」。
- 予定バージョン: 0.29.0。初回の実装開始時に package.json と package-lock.json を更新する。
- ブランチ: fix/v0.29-game-startup-cleanup。
- オーナーは当初のスコープだけを採用。追加候補は含めない。

## スコープ

- src/game/view.js の mountGame() に残る設定エラー表示と「入口へ戻る」ボタンの生成を削除する。
- 不要になる引数・コールバック・import と、通常入口および検証スクリプト等の呼び出し元を整理する。
- 起動前の設定検証は src/main.js に集約する。設定不備ではタイトルに留まり、プレイヤーが取れる操作を案内する。
- 必要な実装仕様・開発文書と関連検証を更新する。

## 対象外

- MP28-02 の原因調査・修正。
- 日次進行ボタンの変更、ゲーム終了画面の正式化。
- ストック拡大時の取得ボタン、カード操作の共通化、バージョン表示更新、Stepタブ等の追加候補。
- 要求仕様および共通リポジトリの変更。

## 現状と実装方針

- main.js は保存済み設定と画像を取得し、gameIssues(settings) の成功後に mountGame() を呼んでいる。
- view.js には同じ検証と StartIssues の表示が残り、描画ごとに GameStatus に「入口へ戻る」を生成している。
- layoutPresentation.js は GameStatus の必要な通知を移してから要素を除去している。通知の移送は維持し、不要な生成処理を元から削除する。
- mountGame() の呼び出し元にはブラウザー検証スクリプトもあるため、引数変更時は全呼び出し元を確認する。ゲーム終了通知と破棄処理の責務を維持する。
- タイトルのエラー案内は設定内部の詳細を並べるだけで終わらせず、再試行などプレイヤーが行える操作を明示する。設定の修復や新しい設定編集導線は追加しない。
- ゲーム終了画面の「タイトルへ戻る」と再開始は維持する。

## 完了条件

1. ゲーム画面で旧設定エラー表示と「入口へ戻る」を生成しない。
2. 正常な保存済み設定で起動でき、レイアウトA/Bで日次進行できる。
3. 不正な設定ではゲームを開始せずタイトルに留まり、可能な操作を案内する。設定取得が正常になれば再試行で開始できる。
4. ゲーム終了後に「タイトルへ戻る」で戻り、新しい局を開始できる。終了・破棄時の処理が維持される。
5. 関連する呼び出し元・仕様・検証が最終実装と一致する。

## 検証方針

- 既存の scripts/checkProductionStartup.cjs を中心に、タイトル表示、設定エラーからの再試行、A/Bでの翌日進行・終了・再開始を確認する。
- 旧UIを生成しないことと、変更した mountGame() 呼び出し元を確認する。既存のゲーム接続・通知のブラウザー検証を変更の影響に応じて実施する。
- 実装終了草案の提示前に npm.cmd test と npm.cmd run build を実行し、対象検証とともにコマンド・結果を実装報告へ記録する。
- オーナー検証は、タイトルでの失敗案内と再試行、正常起動から終了・タイトル復帰を確認可能になった時点で、一意のID・手順・期待結果・確認バージョンとともに提示する。判断を記録してから終了草案へ進む。
