# パレットエリア正式UIの開発計画

## 合意事項

- 開発ブランチ: `feature/v0.16-palette-area`
- 予定バージョン: `0.16.0`。初回の実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- レイアウトA/Bのパレット仮表示を正式UIに置き換える。
- 正式UI全体に共通するオーナーとの意識合わせ方針をバックログへ記載する。

## スコープ

実装中の追加合意を優先する。現在のプレイヤー向け仕様は、初日・翌日の「今日の仕事を始める」で開始前に停止し、押すまでドローしない。開始・獲得・リロールはすべて自動物理ロールとする。「使用する画材を決める」は廃止。ダイス詳細情報は長押し操作を予約するだけで、表示はオーナー指示により未実装とする。カード目標アイコンからの全ダイスの面数検索は実装対象に追加。以下の当初計画の手動ロールと6面確認は、この追加合意に従う。

- 既存の3Dダイス、物理ロール、画材・特殊面の結果表示をゲーム本体へ組み込む。
- ターン開始・ダイス獲得・リロールの各場面で、対象を空中回転で提示し、「使う画材を決める」で一斉にロールする。ロール待機・結果確定をゲーム処理へ接続し、物理的に確定した面をゲーム判定に使用する。
- 単体・全未使用ダイスのリロールと、効果による複数対象のリロールを接続する。
- ダイスの選択、6面構成の確認、永続／一時と未使用／消費済みの区別を実装する。獲得・消費・破棄・再利用・面変更と仕事終了・翌日の状態を反映する。
- パレット内の状態変化と、達成時に選択した画材が正式プレイエリアへ移動する演出を実装する。既存の達成演出との順序を調整する。
- レイアウトから渡された論理寸法と既存の座標変換を用い、A/B、狭い画面、リサイズ、パネル開閉に対応する。
- ゲーム本体のJavaScript容量と、ゲーム開始から初回ロール可能までの時間を測定する。開発者向け画面も含めて3Dダイス関連のビルド警告を解消する。

## 対象外

実装中の追加合意：オーナーの具体的な追加指示により、達成時のフロートアイコンの時間差飛行・時計回り周回・帰還吸収、並行する斜めのカンバス描き変え、次カード表示とイーゼル消去後の効果解決を今回の対象へ追加した。下記のキャンバス演出の対象外規定は、この追加指示分を除いて適用する。捨て札等の仮エリアへの移動演出は引き続き対象外。

- パレット以外の仮エリアの正式化と、仮エリアとの移動演出。
- キャンバスの詳細な描き変え演出。画材移動との接続に必要な順序調整は対象とする。
- アイコンのホバー説明改善、ゲームルール変更、共通リポジトリの変更。

## オーナーとの進め方

完成後の一括確認にせず、実装途中から綿密に相談する。各まとまりの実装前に、配置・見た目・操作・演出の具体案を提示して意識を合わせる。小さな単位で確認可能な状態を作り、操作手順と確認点を示す。フィードバックを反映し、オーナーの確認を得てから次のまとまりへ進む。

最初にパレットの配置、ダイスと結果表示の大きさ、選択と情報確認の操作案を提示する。続いてロールと状態変化、達成時の画材移動を段階的に確認する。具体的な見た目や演出時間は計画への合意のみで確定扱いにしない。

確認項目は利用者が操作・判断できる単位で一意のIDを付け、理由・手順・期待結果・確認バージョンを提示する。判断と対応は実装報告へ記録する。未回答を保留扱いせず、現在のまとまりに依存する次の実装へ進まない。範囲・バージョン・ブランチ名の変更が必要な場合は再合意を得る。

## 実装方針

- Gameをルールと状態の正本とし、表示側へルール判定を複製しない。既存の同期抽選箇所を整理し、ロール要求・待機・確定結果の受渡しを明示する。未確定時に効果や達成可能表示が先行しないようにする。
- 既存Die・DiceGroup・DiceSceneを再利用する。対象外ダイスの出目を保持し、面変更を同じIDの表示へ反映する。固定の出目へ姿勢を置き換えて物理結果と食い違わせない。
- 評価用ゲームとダイス確認画面を維持する。自動テストで出目を再現できる接続方法を設け、ブラウザの描画処理からルール処理を分離する。
- 連打・効果選択・演出中の競合と二重表示を防ぐ。ロール失敗や描画環境・画像読込みの失敗には、状態を偽装せず復帰手段を用意する。
- 再描画ごとに3Dシーンを作り直さず、再プレイ・終了時に描画資源と監視・イベントを解放する。動きを減らす設定では装飾演出を軽減し、出目確定との整合を保つ。
- 読込みの分割と依存構成を見直し、500 kBしきい値を引き上げず警告を解消する。測定条件、容量、初回ロール可能までの時間を実装報告へ記録する。
- 実装仕様をdocs/specへ記載し、既存のゲーム・ダイス・レイアウト仕様の参照を整える。要求仕様は変更しない。

## 完了条件と検証

1. 物理的に確定した面とゲーム判定の出目が一致し、確定前に後続処理が進まない。
2. ターン開始、獲得、単体・全未使用・効果による複数対象のリロールで、対象と非対象の状態・表示が正しい。
3. 選択と6面確認、永続／一時、消費と破棄、再利用・面変更・翌日の復帰が確認でき、手札・プレイの達成可能表示も更新される。
4. 達成時の画材移動が既存のカード・キャンバス演出と整合し、二重表示や操作競合がない。
5. A/B、狭い画面、リサイズ、パネル開閉で描画と入力座標が一致する。再プレイ後に旧シーンや監視が残らない。
6. JavaScript容量と初回ロール可能までの時間を測定・記録し、開発者画面を含めて現行500 kBしきい値のビルド警告が出ない。
7. ロール待機・確定・効果再開などの複雑な状態制御はTDDで検証する。対象テストに加えて `npm.cmd test` と `npm.cmd run build` を実行し、コマンド・結果・失敗時の調査を実装報告へ記録する。
8. ブラウザで実際の物理ロール、操作、レイアウト、演出、終了・再プレイと開発者画面の回帰を確認する。オーナーによる段階的な見た目・操作感の判断とフィードバック対応を記録する。保留は明示判断がある項目だけとする。
