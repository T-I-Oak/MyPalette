# カード詳細を閉じた後のボード操作不能の調査・修正計画

## 合意した開発内容

- 対象: バックログMP38-05。達成後にカード詳細を閉じるとコルクボードを操作できなくなる問題。
- ブランチ: `fix/v0.39-board-lock`
- 予定バージョン: `0.39.0`。実装開始時にpackage.jsonとpackage-lock.jsonを更新する。計画では更新しない。
- Safariは報告環境であり、Safari固有の不具合とは確定していない。ブラウザーを限定せず調査する。

## 報告された操作列と未確定事項

1. iPad Safariで「動きを減らす」を有効にしてプレイする。
2. 達成時効果として即時リロールを獲得する。
3. 進行が止まったように見えたため、コルクボードを開く。
4. 達成したカードの詳細を開いて効果を確認する。
5. カード詳細を閉じる。
6. コルクボードを閉じようとすると操作が反応しない。

これはオーナーの報告であり、計画時点では再現未確認。最初の進行停止と詳細を閉じた後の操作不能は、同じ原因か未確定である。即時リロール、動きを減らす設定、詳細開閉、ブラウザーのいずれが必要条件かも未確定。JavaScriptエラー、端末・OS・ブラウザーの具体的な版は未取得。

## スコープと対象外

報告された操作列を検証可能にし、効果・ロール待機からの再開、詳細の開閉、背面操作遮断と解除、再描画、ボード開閉の状態を調査する。原因を特定した場合は必要な範囲を修正し、再現する回帰検証を追加する。必要な実装仕様・検証手順を更新する。

MP38-04の案内・通知の改善、MP28-02の突然タイトルへ戻る問題、他のUI改善、既存dialog全体の置換、共通リポジトリの変更は対象外。調査上は最初の進行停止が正常な入力待ちかを確認するが、案内表示の再設計は含めない。原因が対象外の変更を必要とする場合は、変更前に範囲を相談する。

## 調査・実装方針

1. WindowsのEdge／Chromiumと既存のローカル開発サーバーを使用する。保存済みカード設定を変えず、達成時に即時リロールを得られる検証用状態を用意する。
2. 達成後、詳細を開く前、閉じた直後のゲーム状態、選択・ロール待機、演出・通知、JavaScriptエラーを記録し、最初に進行が止まった理由を調べる。
3. ボードを閉じる入力が届いているか、届いた入力が処理されているかを区別する。`inert`、覆い要素、イベント制御、フォーカス、詳細終了時の再描画と状態の復元を確認する。
4. 即時リロール、動きを減らす設定、詳細開閉の有無を一条件ずつ比較し、レイアウトA/Bと利用可能な別ブラウザーで確認する。再現する条件を固定してから組合せを広げる。
5. 原因に対応する失敗する検証を先に用意し、修正後に成功を確認する。既存の詳細開閉・ボード・効果通知・ロール検証を再利用する。
6. 報告環境のiPad Safariについては、再現用ページと操作手順を用意してオーナーへ確認を依頼する。こちらで直接操作できるSafari実機環境は確認できていない。Windowsで再現しないことをSafari固有の根拠にしない。

再現しない場合は、確認条件と不足情報を記録し、実機の停止地点を取得する診断方法を検討する。診断が必要なら、利用者が取得できる範囲と操作を具体化する。推測だけの修正や、再現不能を理由とした解決扱いはしない。

## 検証・完了条件

- 原因と再現条件、修正との対応を記録する。
- 詳細を閉じた後にボードの開閉ができ、即時リロールに必要な選択・ロールと後続のゲーム操作を継続できる。
- 通常設定／動きを減らす設定とレイアウトA/Bを確認する。詳細中の背面操作遮断、閉じた後の解除、既存の操作制限も維持する。
- 対象検証に加えて`npm.cmd test`と`npm.cmd run build`を実行し、実装報告にコマンドと結果を記録する。
- iPad Safariの確認手順を提示し、オーナーの判断・フィードバック・対応、明示的な保留があればその理由を記録する。Chromiumでの成功をSafari実機確認済みとは扱わない。
- 再現・原因特定に至らない場合は修正済みとせず、実施した調査、未確認範囲、次の診断方法を提示して判断を求める。
