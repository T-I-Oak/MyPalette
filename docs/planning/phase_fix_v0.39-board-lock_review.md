- `showCardDetail.close()`の元カードへのタブclickが、捨て札の詳細開始処理へ伝播する経路を確認した。終了処理中の再入により背景のinert=trueを新詳細が保存するという原因説明は実装と一致する。
- `Card`のタブでclick伝播を止める修正は原因の経路に対応する。Step選択・コールバックは維持され、ゲーム状態や効果処理、背景の復元方式を変更していない。仕様にもタブとカード本体の操作の分離が記載されている。
- 捨て札検証は異なるStepを選択して閉じた後の詳細0件、背景inert解除、ゲーム状態不変を確認する。結合検証は実際のポインター入力で詳細開閉、Step維持、ボード開閉、即時リロールと後続効果・次の着手を検証する。検証用の設定・乱数変更は生成ページ内に限られ、保存済み設定と本番入口に影響しない。
- 通常／動きを減らす、A/B、即時リロール有無の8条件を確認した。即時リロールやSafariを必要条件と断定していない。詳細を開く前の待機についても、検証環境の正常な入力待ちと報告端末の未取得状態を区別している。
- 実装報告のMP39-01には仮版v0.39.0でのSafari修正後確認に対するオーナーの「確認okです」が記録され、確認済みである。この既存判断は維持する。その後のレビュー中に受けた共通操作への修正指示は、下記R39-01として別途対応が必要である。
- バージョン設定は両ファイルとも0.39.0。要求仕様、保存済み設定、共通リポジトリの変更は差分にない。

## 未解決指摘 R39-01: 捨て札も共通のカード操作に揃える

- オーナー指摘: 捨て札のStepタブをクリック不可にする指示はしておらず、同じものは共通にするのが基本方針である。捨て札でもタブはStepを切り替え、効果アイコンは説明を開き、それ以外のカード面から詳細を開く共通操作へ揃えることについて「そうしてください」と修正指示を受けた。
- 問題箇所: `src/game/cardScene.js`の`faces.inert`で捨て札の内部操作を無効にし、カードclick処理では捨て札のみbutton／CardIconの除外判定を迂回している。`src/game/view.js`にも捨て札専用の詳細開始条件がある。`docs/spec/17.discard_area.md`のタブ操作不可の記述もオーナー方針と不整合である。
- 必要な対応: 捨て札のタブ・アイコン・カード面の操作を既存の共通動作に揃え、専用の遮断と詳細開始の例外を整理する。関連箇所を調べ、同じ操作判定を重複させず共通に扱う。出荷済み等の別用途の制御を一括解除せず、捨て札に必要な修正に絞る。要求仕様と保存済み設定は変更しない。
- 検証: 捨て札の見えているカード上で実ポインターによるStep切替と効果説明の開閉ができ、これらで詳細を起動しないこと。その他のカード面では詳細が開くこと。詳細のStep変更後の終了で再入せず背景inertを解除すること。隠れたカード・裏面を操作できず、ゲーム状態を変更しないこと。他エリアの共通操作も維持すること。
- 通常／動きを減らす、A/Bの回帰、全テスト、本番ビルドを実施して結果を実装報告へ記録する。必要なオーナー確認は修正版のバージョンと操作手順を示して依頼する。v0.39.0の確認済み記録を修正版の確認済みへ流用しない。
- 差し戻しの実装開始時にPatchを上げてv0.39.1とする。同じブランチを継続する。
