# デッキエリアの正式UI化 実装記録

## オーナーとの調整

オーナーの指示に従い、ステップごとに進める。先に提示したDECK-01案は承認済み仕様として扱わない。

### DECK-02：エリア定義

オーナー指示（2026-11-10）：

- エリア名は「デッキ N枚」。Nはデッキの枚数。
- エリアの背景は消す。
- カードはストックエリアと同様の裏向きの山として表示する。
- ドロー時はストックと同様に山の一番上を表にして、その後手札エリアに移動させる。
- デッキへのカード追加時は、ストックと同様に山の一番下へ追加し、全体を1.5px上げる。

上記を今回の確定したエリア定義とする。

### DECK-03：初日の動き

オーナー指示（2026-11-10）：

1. ストックから7枚を時間差でデッキへ移動する。到着したカードを順次デッキの一番下へ追加し、追加ごとに全体を1.5px上げる。
2. 7枚すべてがデッキへ入ってから、手札への4枚ドローを開始する。
3. デッキの一番上のカードを表にし、その後手札へ移動する。この動きを時間差で4回繰り返す。

7枚の受け入れ完了前に手札への移動を開始しない。

### DECK-04：時間差の調整方針

オーナー指示（2026-11-10）：

- 時間差はストックの既存演出を参考にする。
- デッキでは同じ山のカードを順次表にするため、不自然な重なり方にならないよう、必要に応じて間隔を空ける。
- 具体的な間隔は実際の動きを見て調整する。既存の数値をそのまま確定値とはしない。

参考となる既存値は `stockMotion.js` の初日配分の開始間隔90ms、ストック各山の開始間隔120ms、持ち上げ180ms・表返し360ms・着地180ms。これらは参考値であり、デッキの確定値ではない。

## 実装内容（0.21.0）

- エリア名・透明背景・裏向きの山を`deckPresentation.js`へ分離した。寸法351×557は全45枚の厚みと持ち上げ余白を含み、現在枚数による倍率変化を防ぐ。
- 初日の到着カードを下へ積み、先着カードを追加ごとに1.5上げる。ストック配分の開始間隔90msを維持した。
- 7枚の受け入れとストック公開演出の後、最上段を表返しして手札へ運ぶ。持ち上げ180ms、表返し360ms、移動420ms、開始間隔660msを確認用の値とした。
- ゲーム側の`deckEvents`に実際のカード順・step・再構成を記録する。日次・効果ドロー、途中再構成にも同じ演出を接続した。抽選・ルールは表示側で再実行しない。
- 達成演出後に発生するドローも記録を取り直し、後続ロール・選択待ちへ進む既存の操作ロックを利用する。
- 動きを減らす設定は即時反映。移動中は毎フレームの座標を使用し、中断時に移動表示と監視を解放する。
- 要求仕様・保存済み設定・共通リポジトリは変更していない。
