# カード操作・拡大表示・重なり順の開発計画

## 合意内容

- 対象プロジェクト: MyPalette。
- ブランチ: `refactor/v0.35-card-interaction`。
- 予定バージョン: `0.35.0`。初回実装開始時に `package.json` と `package-lock.json` を更新する。計画では更新しない。
- カードと操作定義を共通管理し、通常表示と拡大表示で共有する。
- レイアウトBでイーゼル上のカードをコルクボードより背面に保つ。
- カード拡大の `dialog/showModal` 依存を解消し、開閉に伴う不要なフォーカスを防ぐ。

## 現状と設計上の課題

- `src/game/view.js` が手札のプレイ・返却、場札の達成ボタンを作り、各表示部品が固定倍率層へ配置する。
- `src/game/stockPresentation.js` は独自に取得ボタンを生成する。実カードからの詳細表示は `.GameCardActions` を検索するため、取得ボタンを参照できない。
- `src/game/cardDetail.js` は元のボタンDOMから文言と無効状態をコピーし、元ボタンの `click()` で実行する。操作の意味と状態がDOM配置に依存している。
- 詳細表示はネイティブdialogを使用し、閉じるボタンにautofocusを設定する。`view.js` は `[open]` と `close` イベントに依存して通知後の再描画を制御する。
- `src/game/cardScene.js` は `model.motion` 中に全カードを移動層へ移す。移動層はコルクボードより前面にあるため、静止した場札の層も変わり得る。修正時には実際の重なりと演出経路を再現して確定する。

## 開発スコープ

### カードと操作の共通管理

- カードIDと操作定義を対応づけ、プレイ・返却・達成・ストック取得を同じ契約で扱う。操作のないカードも同じ参照経路で扱う。
- 操作定義は識別子、表示文言、表示可否、有効条件、実行処理を持つ。通常・拡大の表示先は同じ定義を使用し、詳細表示側は所属エリアや元ボタンDOMを検索しない。
- ゲーム状態に依存する条件は操作提供側が管理する。表示・実行時に現在の状態へ照合し、古い選択、所属変更、通知・演出中、終了後の操作と二重実行を防ぐ。
- 達成ボタンのダイス選択による有効状態の更新も共通定義へ反映する。通常表示と拡大表示で状態を食い違わせない。
- DOMを単一の親へまとめることは要件としない。通常表示の配置・固定倍率・演出と、詳細表示の操作欄を分離しつつ共通管理する。
- ストック取得は効果、チラシ発注、手札交換に接続し、複数回の取得、公開補充、空ストック、対象外を扱う。

### カード詳細の独自UI

- カード詳細をゲーム内の独自オーバーレイへ置き換え、HTMLのdialog要素・showModal・ネイティブcloseイベント・autofocusへの依存を除去する。
- ゲーム画面ルートに表示し、背面を覆い、背面のクリック・タップ・キー操作を遮断する。背景要素を操作不能にした場合は、閉じる際に元の状態を復元する。
- 既存のカード面クリック、閉じる操作、Escape、ステップタブ、説明表示、目標アイコン操作、達成可能表示を確認して維持する。背景クリックは背面へ伝播させない。
- 操作ボタン実行時は詳細を閉じてから共通の操作を実行し、後続の演出・効果選択へ一度だけ進む。
- 開閉・タップで不要なフォーカスを発生させない。フォーカス枠の非表示だけで完了にせず、明示的なfocusやautofocus、ブラウザー既定のフォーカス取得を確認する。
- 開閉状態と終了処理を明示的に提供し、通知後の再描画、ゲーム再描画・破棄時の後始末、リスナーとアイコン資源の解放へ接続する。
- 狭い画面でもカード・タブ・操作へ到達できる配置または内部スクロールを用いる。既存の倍率管理と座標変換を使い、説明表示の位置と前後関係も整える。
- 効果選択の既存dialog内で詳細を扱う経路があれば、トップレイヤーとの競合を確認する。効果選択の置換を必要とする場合は独断で範囲を広げず、影響と案をオーナーへ提示する。

### コルクボードとの重なり順

- レイアウトBのイーゼル上のカードは、コルクボードの開閉、カード・カンバス切り替え、他カードの移動中もコルクボードより背面に保つ。
- 所属エリア、実際に移動しているカード、静止したカードの描画責務を区別し、無関係な演出で静止した場札を前面層へ移さない。
- 着手・達成・撤去・出荷・回収の経路と切り替え境界を検証する。移動中カードの必要な前面表示や操作制限を壊さない。
- 拡大画面はボードを含む通常盤面より前面に置き、通常カードの層修正と詳細UIの層管理を整合させる。

## 対象外

- 効果選択・開発者画面など、カード詳細以外のdialogの置換。
- ストック取得後のコルクボード自動閉鎖。
- タイトル・ゲーム終了画面のフォーカス制御。
- カードアイコンのCanvas統合、イーゼルのプール化、着手ボタンの移動追従など別バックログの改善。
- ゲームルール・保存済み設定・絵画素材・効果仕様の変更。
- 共通リポジトリの編集。要求仕様はオーナーの許可なしに変更しない。

## 実装の進め方

1. 現行のカード操作・拡大導線・選択画面・描画層を棚卸しし、既存挙動と確認データを整理する。
2. 操作定義の条件・実行制御をテストで定義し、共通管理へ移す。各表示部品は配置を担当する。
3. 通常表示と拡大表示を共通操作へ接続する。実カード45枚を同じ要素で維持する既存方針を守る。
4. カード詳細を独自UI化し、通知待機、背面操作遮断、フォーカス、破棄処理を接続する。
5. 層の切り替えを修正し、カード操作と詳細表示を含む通し検証を行う。
6. 実装前に独自UIの配置・開閉・操作と層構成の具体案を提示し、小さい単位で確認可能にする。各項目のフィードバックを反映して再確認する。
7. 実装仕様とバックログの残作業を整合させ、実装報告へ検証結果・オーナー判断を記録する。

## 検証方針

- 複雑な操作条件・二重実行制御はTDDで検証する。DOM構造の写しではなく、現在状態による許可・拒否と実行結果を確認する。
- ブラウザー検証は既存の `checkStockAcquisition.cjs`、`checkStockEdgeCases.cjs`、`checkHandArea.cjs`、`checkPlayArea.cjs`、`checkDiscardArea.cjs`、`checkCardScene.cjs`、`checkCardSceneReduced.cjs`、`checkScreenLayout.cjs` を影響に応じて利用・更新する。
- 必要ならカード操作と詳細表示の統合検証を追加する。dialogの `[open]` 等に依存する既存スクリプトは新しい公開状態へ合わせ、検証自体を削除しない。
- 通常表示・詳細表示のプレイ、返却、達成、取得を確認する。取得元3経路、連続取得、空・対象外、無効な操作、連打、状態更新を含める。
- A/B、開閉途中を含むボード状態、リサイズ、固定倍率変更、通常演出・動きを減らす設定を組み合わせ、場札がボードの上に出ず、ボードが覆う場所から操作できないことを確認する。
- 詳細表示中は背面を操作できず、閉じる・実行後は必要な操作が復帰することを確認する。ステップ選択の維持、アイコン説明の前面表示・位置、目標検索、通知後の再描画、破棄時の後始末を含める。
- PCのクリック・Tab/Shift+Tab・Escapeと、iPad Safariのタップでフォーカスの実状態を確認する。自動ブラウザー検証は実機Safari確認の代替としない。
- 実装終了草案前に `npm.cmd test` と `npm.cmd run build` を実行し、対象検証とともにコマンド・結果を実装報告へ記録する。

## 完了条件

1. 通常表示と拡大表示が同じカード操作定義を使用し、拡大表示側にエリア別の操作探索・元ボタンの代理クリックを残さない。
2. 取得可能なストックカードの詳細に取得操作が現れ、閉じて正しいカードを一度だけ取得する。取得不可・状態変更後は実行しない。
3. プレイ・返却・達成と、その有効状態・選択・後続演出を維持する。
4. カード詳細にネイティブdialog依存がなく、背面遮断・開閉・フォーカス抑止・通知連携・終了処理が成立する。
5. レイアウトBでイーゼル上のカードがボードより背面を維持し、詳細UIは盤面より前面で操作できる。
6. 対象検証、全テスト、本番ビルドの結果と必要なオーナー判断を記録し、未回答や未対応のフィードバックを残して終了草案を出さない。保留はオーナーが明示した項目だけとする。

## オーナー検証の予定

各項目は実装中に、理由・操作手順・期待結果・実際の確認バージョンを示して提示する。以下は予定であり確認済みではない。

| ID | 確認する内容 |
| --- | --- |
| MP35-01 | 効果によるストック取得を詳細から実行し、連続取得と補充まで確認する。 |
| MP35-02 | チラシ発注・手札交換のストック取得を詳細から実行する。 |
| MP35-03 | 手札のプレイ・返却を通常表示と詳細表示で確認する。 |
| MP35-04 | 場札の達成を通常表示と詳細表示で確認し、ダイス選択と演出が一致する。 |
| MP35-05 | レイアウトBでボードの開閉・カード表示・演出中の場札の重なりを確認する。 |
| MP35-06 | PCで独自の拡大UIの開閉・背面遮断・ステップ・説明・キー操作・リサイズを確認する。 |
| MP35-07 | iPad Safariで拡大の開閉・タップ後に不要なフォーカスが発生せず、カードと操作が画面内で使える。 |
