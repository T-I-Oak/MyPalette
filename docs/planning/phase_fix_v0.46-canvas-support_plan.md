# 達成演出のカンバス支持・固定の計画

## 合意した開発内容

- 対象はバックログMP45-01「達成演出のカンバスを上部固定具で支える」。
- 予定バージョンはv0.46.0、ブランチは`fix/v0.46-canvas-support`。
- 要求02 §5.4の支持・固定を満たすため、カンバスの寸法・向きに合わせて上部固定具を調整する。
- 関連する実装仕様と検証を更新する。
- バージョン設定は初回の実装開始時に更新し、計画ではv0.45.1を維持する。

## 現状と設計方針

### 実装開始後のオーナー指示による絞り込み

現行作品はすべて1536×1024の固定寸法なので、固定位置でよいとの指示を受けた。以下の当初方針のうち寸法追従・正方形・縦長比率への拡張は実施せず、現行の固定寸法に合わせて固定具の位置と各部の接続を修正する。支柱の伸縮や撤去時の位置復元は追加しない。現行寸法での回転・リサイズ・固定倍率・A/B・各ステップ・撤去と再利用の検証は維持する。

`src/game/easel/canvasPlacement.js`は画像の縦横比からカンバスの高さと上端を求める。下端は0.7375で、受け台上面と一致する。
`createEasel.js`の上部固定具は固定座標で作られ、`mountCanvas`はカンバスを設置するだけで固定具を調整しない。
保存済みA01（1536×1024）では、カンバス上端と固定具下面に約0.121833の差がある。

- カンバスの配置情報に基づき、固定具の接触位置を求める。画像ごとの補正値は設けない。
- 固定具のブロック・押さえ・つまみを整合する位置へ調整し、前面の厚み、面取り、背面の支柱との関係も確認する。
- カンバスと固定具を同じイーゼル前面の座標系で扱い、組全体の回転・リサイズでも支持関係を保つ。
- カンバスの撤去・再設置とイーゼル再利用を確認し、通常カード表示に固定具の不自然な位置や重なりを残さない。復元の要否と方法は既存ライフサイクルに合わせて実装時に決める。
- 受け台、通常カードの投影、演出の時間・順序は既存の契約を維持する。

## 対象外

- CARD-01のカード可読性・カード下端の接地感。
- MP40-09のカードとカンバスの絵の一致。
- MP40-15の演出全般の検証、イーゼルのプール化、その他のUI刷新。
- ゲームルール、要求仕様、保存済みカード設定・絵画素材の変更。
- GameWorksOAK共通部の変更、公開・デプロイ。

## 完了条件

1. カンバスの下端が受け台に支えられ、上端が上部固定具に自然に押さえられる。
2. 寸法・縦横比およびイーゼルの向きが変わっても、斜めから見て不自然な隙間や貫通がない。
3. 通常の達成演出のStep 0→1・1→2・2→3について、レイアウトA/Bで支持関係を画像と数値で確認する。
4. 動きを減らす設定では既存の演出省略を維持する。通常カード表示・カンバスへの切替・カードへの復帰・出荷・再利用が破綻しない。
5. 対象検証、全テスト、本番ビルドを実行し、結果と限界を実装報告へ記録する。
6. オーナーへ固定具の支持部分の見た目を提示し、確認・却下・フィードバック・明示的保留の判断と対応を記録する。

## 実装・検証方針

- `createEasel.js`を中心に、必要なら配置計算を分離する。複雑な計算や状態管理を追加する場合はテストを先に記述する。
- 配置計算・製品の設置処理について、保存済みの横長比率と検証用の正方形・縦長比率を扱う。検証用画像は保存済み素材を変更せず生成する。
- 数値検証では上下の接触、固定具各部の位置関係、同一個体への異なる寸法の再設置を確認する。対応する製品モジュールの責務に合わせて`tests/implementation/game/easel/`へ配置する。
- `scripts/checkAcceptanceCanvasSupport.cjs`を拡張または補助検証と併用し、製品の描画部品で正面・左右の斜めから画像を取得する。現在の上端・下端の差だけで面取り部分や前後方向の接触まで確認済みとしない。
- 実際の達成演出は既存の`checkCardScene.cjs`、`checkCardSceneReduced.cjs`、`checkBoardMotion.cjs`等を調べて必要な検証を選ぶ。不足するステップ・A/B・回転・切替・出荷の観測を追加する。
- 通常の向きに加え、リサイズと固定倍率変更後の支持関係・画面内表示を確認する。対象画面寸法、角度、設定、画像、数値を実装報告へ記録する。
- `npm.cmd test`と`npm.cmd run build`を実装終了草案の提示前に実行する。
- 実装仕様は`docs/spec/15.play_area.md`へ支持・固定の契約を記載し、必要な場合だけ開発ガイドの検証案内を更新する。バックログはレビューの削除承認前に削除しない。

## 検証環境と成果物

- ブラウザー検証は既存の`http://127.0.0.1:3000/MyPalette/`を使用する。常用サーバーを停止・再起動・置換せず、追加サーバーも起動しない。接続できない場合はオーナーへ報告する。
- 検証画像・測定結果・検証専用ページは`tmp_`等の一時成果物として扱い、証拠の場所と結果を実装報告に記録する。
- 実装報告は`phase_fix_v0.46-canvas-support_implementation.md`、レビュー報告は`phase_fix_v0.46-canvas-support_review.md`とする。
- 本計画と各`phase_`成果物は開発中のみ追跡し、レビューの承認後、マージ前に共通手順に従って整理する。
