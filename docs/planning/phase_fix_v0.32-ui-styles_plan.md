# v0.32 UIスタイル調整 計画

## 合意内容

- 対象ブランチ: `fix/v0.32-ui-styles`
- 予定バージョン: `0.32.0`。実装開始時にpackage.jsonとpackage-lock.jsonを更新する。計画段階では現行の0.31.3を維持する。
- バックログの「無効なボタンを見分けやすくする」「カードのステップタブの折り返しを確認する」の2項目を扱う。
- オーナーはスタイル系の項目をまとめることを希望し、リロール権の表示見直しはスタイルだけに閉じないため対象外と指定した。上記スコープ・バージョン・ブランチ名への合意を得た。

## スコープと完了条件

### 無効なボタン

- 共通ボタンの無効時の配色・輪郭・質感を調整し、有効時との違いを明確にする。グレーの平坦な面を方向案とし、文字の読みやすさを維持する。
- 有効・無効を見分けられ、無効時にホバー・押下の外観へ変化しないこと。
- 既存の操作不可と、無効状態にも付与される注目アニメーションを維持する。動きを減らす設定での停止も維持する。
- ゲーム本体・カード詳細・開発者画面など、共通スタイルの適用箇所を確認する。専用スタイルを持つタイトルへの影響も確認する。

### ステップタブ

- 正式版の手札・制作中のカードで、ステップタブの折り返しを確認する。報告された検証版固有の余白と正式版の挙動を区別して記録する。
- 各Step Nが1行に収まり、タブの欠け・重なりがなく、既存の切替操作を維持すること。
- 正式版で再現しない場合は、検証条件と結果を記録し、不要なスタイル変更を行わずオーナーの判断を得る。

## 対象外

- ボタンが無効になる条件、ゲーム処理、操作条件の変更。
- リロール権表示、日末ボタンへの注目属性追加、アイコンのホバー説明、効果獲得表示、ゲーム終了画面の正式化。
- フォーカス制御、ブラウザーズーム制御、その他のバックログ項目。
- GameWorksOAK共通部とdocs/requirementsの変更。

## 実装方針

- docs/spec/11.shared_ui_style.mdと共通CSS規約を適用する。無効時の装飾はsrc/ui/states.css、色はsrc/ui/theme.cssを中心に管理し、機能別CSSへの重複を避ける。
- 現行の無効時は影を除去し、inactiveの面・文字を使用している。既存値と有効時を比較して具体案を示す。
- ステップタブはsrc/game/card.cssを確認する。現在は.has-completion付きのタブにwhite-space: nowrapが指定されており、他の表示条件も調べる。
- 実装前に具体的な見た目の案を提示する。小さな単位で比較可能な状態を作り、操作手順・確認点を提示してフィードバックを反映する。
- 仕様変更に応じてdocs/spec/11.shared_ui_style.mdなど必要な実装仕様を更新する。バックログの完了項目削除はレビュー時の承認手順に従う。

## 検証方針

- 既存scripts/checkSharedStyles.cjs等の内容を確認し、今回の変更に対応する検証を選ぶ。単なるCSS記述の複製となる単体テストは追加しない。
- レイアウトA/B、画面幅・エリア倍率の変更時に、ボタンの有効・無効とカードのStep 0〜3のタブを確認する。
- PCでは通常・ホバー・押下と有効／無効切替、タブ操作を確認する。注目属性の有無と動きを減らす設定も確認する。
- iPad Safariで無効表示とステップタブを確認する。実機確認はオーナーへ依頼し、確認可能な実装とバージョンを示す。
- オーナー検証IDはMP32-01（無効ボタン）、MP32-02（ステップタブ）とし、各項目の理由・操作手順・期待結果・確認バージョンを実装中に提示する。判断と対応を実装報告へ記録する。
- 実装終了草案の提示前にnpm.cmd testとnpm.cmd run buildを実行し、対象検証とともにコマンド・結果を実装報告へ記録する。失敗は原因と範囲を調査する。
- 未回答の検証や未対応フィードバックを残して終了草案を提示しない。保留はオーナーの「現時点で確認しない」という明示判断に限る。
