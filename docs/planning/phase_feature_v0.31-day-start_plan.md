# 日次の自動開始と日付演出の計画

## 合意内容

- 予定バージョン: `0.31.0`。実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- 開発ブランチ: `feature/v0.31-day-start`。
- 初日も「今日の仕事を始める」ボタンを廃止する。ゲーム開始で初日を開始し、日末の片付け後に翌日を開始する。新たな開始操作は設けない。
- 左上のDay・名声値表示そのものを中央へ移動しながら拡大する。中央でDay (N-1)からDay Nへ切り替え、左上の元の位置・大きさへ戻してから朝の処理を開始する。
- 名声値はその時点の値を表示する。初日は中央にDay 1・初期名声値を表示して左上へ戻す。

## 開発スコープ

- プレイヤー用画面の初日・翌日の自動開始と、開始ボタンの撤去。
- 既存のDay・名声値表示を用いた開始演出と、日末・朝の処理との接続。
- 関連する実装仕様、開発・確認手順、単体・結合テスト、ブラウザー検証スクリプトの更新。
- 実装途中で演出を確認できる状態を用意し、操作手順と確認点を提示してオーナーと調整する。

## 対象外

- 終了ボタンの注目属性、無効ボタンの見た目、リロール権表示など他のバックログ項目。
- MP28-02の原因調査・修正。現環境で再現しない事象として保留を維持する。
- ゲームの基本ルール、効果内容、保存済みカード設定の変更。
- 共通リポジトリの編集。変更が必要ならオーナーへ報告する。

## 完了条件

1. ゲーム開始後に初日が自動で始まり、初日・翌日とも開始ボタンや代替の開始操作を必要としない。
2. 日末の片付け・ストック更新が完了するまで当日の日数表示を維持し、中央で翌日の日数に切り替える。名声値は日末処理を反映した値を表示する。
3. 翌日は左上の既存表示が中央へ拡大移動し、日付更新後に左上へ戻る。初日は中央のDay 1・初期名声値表示から左上へ戻る。同じ表示を二重に見せない。
4. 演出が終わってから、初日の配分・公開、ドロー・権利付与・予約効果・物理ロールを既存の論理順に一度だけ実行する。必要な選択・ロール待機を維持する。
5. 演出中に進行操作が競合しない。ゲーム終了時には翌日を開始せず、タイトル復帰・再開始後も演出と日次処理が正常に動く。
6. レイアウトA/B、リサイズ・パネル開閉・固定倍率変更で移動先が正しく、動きを減らす設定でも日付更新と処理順が維持される。移動・拡縮を省く場合の表示をオーナーに提示する。
7. 通常の評価用同期進行を維持する。関連テスト・ブラウザー検証を新しい開始方式に更新し、全テストと本番ビルドの結果を実装報告に記録する。
8. 演出の大きさ・時間・日付切替の見た目を含め、実装中にオーナー確認を行う。未回答・未対応のフィードバックを残して終了草案を提示しない。

## 実装方針

- `src/game/infoPresentation.js`のInfoDayが既存のDay・名声値表示を保持する。既存の日数増加アニメーションとの重複を避け、日次演出で表示日付を制御する。
- `src/game/view.js`のプレイヤー向け開始待ち・日末演出完了からのnextDay接続を調整する。awaitingStart等の内部待機状態を残すかは実装時に判断し、ユーザーの追加操作を不要にする。
- `src/game/engine.js`と`session.js`の既存の日次処理・物理ロール待機を再利用する。表示のために朝の論理処理を先行実行しない。
- レイアウトの座標変換を使って左上の表示と画面中央を接続する。中断・破棄・再開始時に演出と後続処理を確実に終了し、古いセッションを再開しない。
- 演出時間・拡大率等は実装時に調整する。新しい表示情報や開始操作は追加しない。
- `docs/spec/09.playable_game.md`、情報表示に関連する仕様、`docs/01.development.md`などの記述を実装と一致させる。要求仕様の編集が必要なら許可を得る。

## 検証方針

- 日次開始の状態遷移・非同期の一度限りの再開・終了と破棄の競合は、実装前に意味のあるテストで定義する。
- 既存の`tests/implementation/game/dayStart.test.js`などで、朝の処理順・初日と翌日・予約効果・ロール待機・評価用同期進行の維持を確認する。
- 開始ボタンに依存する`scripts/check*.cjs`を洗い出し、単なる待機の置換にせず、各検証の目的に合わせて自動開始後の観察時点を設定する。開始前の観察が必要な検証には適切な制御を用意する。
- ブラウザーで初日、複数日の連続進行、日末名声値の反映、終了・再開始、A/B、リサイズ、固定倍率、動きを減らす設定を確認する。
- 演出の配置・拡縮・日付切替・名声値・復帰と朝の処理順をオーナー検証項目として提示し、ID・操作手順・期待結果・確認バージョン・判断を実装報告に記録する。
- 実装終了草案前に`npm.cmd test`と`npm.cmd run build`を実行し、結果と必要な調査を記録する。
