# 捨て札エリア正式UI化の計画

## 合意内容

- 開発ブランチ: `feature/v0.22-discard-area`
- 予定バージョン: `0.22.0`。初回実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- 2026-11-10、オーナーがチャットのスコープ・対象外・完了条件・予定バージョン・ブランチ名の提案に合意した。

## スコープ

レイアウトA/Bの捨て札エリアを正式UIに置き換え、枚数、カード確認、正式エリアとのカード移動を既存ゲーム状態・操作へ接続する。

- 手札・プレイ・ストックから捨て札への移動。日末の回収、ステップ達成後の移動、効果・チラシ発注による取得を含む。
- 捨て札からデッキへの補充と、既存ドロー演出への接続。
- 関連する実装仕様・開発文書・バックログ・検証の更新。

## 対象外

情報表示の正式化、レイアウト全体の正式化、効果別UIの全面改修、ダイス効果変更、カンバス画像変更、QA-01。ゲーム要求仕様および共通リポジトリは変更しない。仮エリアとの移動演出は追加しない。

## 表示・操作の初案

表向きカードを重ねた山と枚数を表示し、クリック／タップで全捨て札の一覧を開く。一覧からカードを選んで現在ステップと各ステップの情報を確認する。空の場合も置き場所と0枚表示を残す。

具体的な配置・見た目・操作・演出案は実装前に提示する。この初案を基に、小さい単位でオーナーと調整し、確認を得て次のまとまりへ進む。

## 完了条件

1. 枚数・カード・現在ステップがゲーム状態と一致し、全捨て札を閲覧できる。閲覧・他ステップの参照でゲーム状態が変化しない。
2. 日末の手札・制作中カード、達成後のカード、ストック取得カードが捨て札へ移る演出を接続する。ステップ3の出荷は捨て札へ移さない。
3. デッキ不足時に捨て札の裏返し・デッキへの補充を示し、既存ドロー演出へ接続する。ゲーム側で確定したシャッフル順を再抽選しない。
4. 二重表示・操作競合を防ぎ、達成時効果・連続ドローの処理順を維持する。移動途中のカードと枚数は演出進行に対応する。
5. レイアウトA/B、パネル開閉、リサイズ、固定倍率変更、動きを減らす設定、空・複数枚・デッキと捨て札の不足を確認する。
6. 表示・閲覧、流入演出、デッキ補充のまとまりごとに操作手順・期待結果・確認バージョン付きの一意な検証IDを提示し、オーナー判断と対応を実装報告へ記録する。未回答を保留扱いしない。
7. 関連仕様と検証を更新し、対象テスト・全テスト・本番ビルドのコマンドと結果を実装報告に記録する。

## 実装方針

- 既存Card・カード詳細表示・共通UIスタイルを再利用し、捨て札用の配置とpresentationを分離する。標準描画寸法とオフセットはエリア側からレイアウトへ通知する。
- 共通のエリア間移動基盤と座標変換を使用し、描画先を毎フレーム更新する。既存のplayEffects、stockEffects、deckEffectsとの順序とキャンセル処理を整合させる。
- deckEventsのrecycle・draw順序を利用する。最終状態の差分だけでは失われる途中の捨て札流入・再構成は、必要に応じて操作時の記録を追加する。
- 達成後の捨て札移動と効果発動の接続は既存ルールを維持する。同じカードが達成後に捨て札へ移り、その達成時効果で再構成・ドローされる場合も扱う。
- 動きを減らす設定では状態を正しく反映し、演出の省略によって後続処理が停止しないようにする。

## 実装・検証の順序

1. 配置・見た目・操作の具体案を提示し、表示・一覧・カード詳細を実装してオーナー確認を得る。
2. 流入演出案を提示し、日末・達成・ストック取得を接続してオーナー確認を得る。
3. デッキ補充演出案を提示し、再構成・既存ドローを接続してオーナー確認を得る。
4. 結合・回帰検証、文書更新、実装報告とレビューへの引継ぎ草案を作成する。

複雑な進行記録・演出計画には実装前にテストを作成する。単体テストは対応ソースに合わせて配置し、ゲーム規則の既存テストを維持する。ブラウザー検証では保存済み設定と必要な検証用設定を使い、保存済みデータは変更しない。checkDeckMotion.cjs等の既存経路も回帰確認する。実装終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行する。

## 追加要望

オーナー指示により、全7エリアの正式UI実装完了後にレイアウト全体を正式化する項目をバックログへ追加した。本開発では全体レイアウトの正式化は行わず、捨て札の配置に必要な寸法等の接続を扱う。
