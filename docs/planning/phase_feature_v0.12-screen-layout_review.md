### LAYOUT-R01 / P2 コンポーネントがパネル用Canvasの背面に隠れる

- 対象は `src/ui/screenLayout/layout.css` のストック・捨て札・デッキの `z-index: 1` と、`createLayoutScreen.js` が生成する共有描画面の重なり順。
- `CanvasArea` は `MoveArea` を継承し、コンポーネントは既存の `createDomTransitionSurface` により別のDOMレイヤーへ描画される。そのレイヤーにはz-indexの指定がなく、3エリアの不透明なCanvasが手前になる。
- ヘッドレスEdgeで1200×700の仮画面を開き、既存のCanvasを使った `CanvasArea` に、`setSlot` と `place(new MoveObject(...))` でボタンを配置して再現した。ボタンの画面矩形は `(620, 20, 100, 60)` と正しく計算されるが、矩形内の `document.elementsFromPoint` はストックCanvas、ボタンの順に返る。描画とクリックがCanvasに遮られる。共有の移動レイヤーも同じ重なり順の影響を受ける。
- エリアと移動描画面を接続したとき、背景Canvas、所属コンポーネント、移動中コンポーネント、パネルの関係が正しくなるように重なり順を整理する。Bではパネル内のコンポーネントを描けることに加え、パネルがメイン側コンポーネントの手前に重なることも確認する。実際のカードやゲーム進行を接続せず、仮の移動オブジェクトで確認できる。
- 回帰確認では、ストック・捨て札・デッキ内でオブジェクトが表示されて入力を受け取れること、移動レイヤー上で描画されること、パネル開閉とリサイズでも座標と重なり順が保たれることを確認する。
