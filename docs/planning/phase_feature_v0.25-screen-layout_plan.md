# v0.25.0 ゲーム画面全体のレイアウト正式化

開発ブランチは `feature/v0.25-screen-layout`。

## 開発スコープ

正式UIが実装済みの7エリアを配置するゲーム画面全体のレイアウトを正式化する。A/Bの構成、各エリアの配置・配分、背景、パネルやスクロールの見た目と操作は、実装フェーズでオーナーの指示を受けて決める。

## 対象外

各エリア内部の再設計、ゲームルール・効果の変更、タイトル画面とゲーム終了後の遷移、QA-01。今回の開発の次はタイトル画面とゲーム終了後の遷移に着手し、その後に実機検証用の GitHub Pages 公開を行う。ダイスの積み重なりの修正は着手順未定とし、各項目をバックログで管理する。

モーダルの外観も対象外とする。ゲーム中の選択モーダルとゲーム終了時の結果報告モーダルは、それぞれを扱う開発で背景と見せ方を決める。

## 完了条件

- オーナーが指示した見た目と操作を、ゲーム画面で確認できる。
- 横長・縦長・タブレット・高さの低い画面で必要な操作に到達できる。
- リサイズやパネル操作がある場合の開閉中も、カード移動の座標が表示に追従し、選択状態が保たれる。パネルが背面に重なる場合は背面を誤操作しない。動きを減らす設定でも確認する。
- 関連する検証、全テスト、本番ビルドが通る。

## 実装・検証方針

指示を受けた内容に応じて、画面レイアウト計算・描画層・操作の必要箇所を更新する。既存のエリア間座標変換とゲームセッションを使い、見た目や操作を確認できる単位でオーナーに提示する。合意した動作を画面レイアウト仕様に反映する。

画面レイアウトとエリア間移動の対象テスト、および `scripts/checkScreenLayout.cjs`、`scripts/checkLayoutLayers.cjs`、`scripts/checkGameConnection.cjs` を使い、変更箇所と既存操作を検証する。実装フェーズの終了承認前に `npm test` と `npm run build` を実行し、結果を実装報告に記録する。
