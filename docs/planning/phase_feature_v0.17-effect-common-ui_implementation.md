## 実装箇所と契約

- game/effectDescriptions.js、game/cardMessages.js: 日英のユーザー向け本文の生成。文字列とインライン効果データを返し、アクセシビリティ用の説明も同じ定義から生成する。
- cardIcons.jsのeffectBody: 「効果アイコン＋説明文」の行を通知とカード説明で共用する。
- iconPopovers.js: 表示元アイコン・ポップアップ・タップによる保持状態を各階層で管理する。カード内と本文内の効果アイコンは同じ処理を使う。
- game/paintingBlock.js: カードと通知の外枠・左の発動契機欄を共用する。プレイ時は既存の青系、達成時は緑系。特殊面の即時適用・予約は★を使う。
- game/engine.js: ID付きの構造化イベントをeffectNoticesへ追加する。ログの文字列解析は行わない。プレイ・達成は全効果を1件へまとめ、特殊面の即時適用では子の効果群を別件として追加する。
- game/effectNoticeQueue.js、game/effectNotices.js: イベントの受領順を維持し、演出後に通知する。再描画で寿命を延長・重複させない。画面破棄時はキュー・タイマー・通知内アイコンの監視・レイヤーを解放する。
- game/specialNoticeEffects.js: 特殊面の通知だけ、同じ種類・設定の効果を1行にまとめる。数量・名声値をアイコン用データで合算し、補色・画材等が違うものは別行にする。元の処理・予約データ・発動回数は変更しない。
- game/view.js: 通知消去後に対象選択・物理ロールへ進む。通常レイアウト以外の表示経路でも、移動演出完了時に再描画して通知の待機を解除する。
- docs/spec/16.effect_common_ui.md: 本文、通知構造、操作、イベント、ライフサイクルの実装仕様。開発文書・バックログから参照する。

## 表示と操作の合意

- 通知には背景・枠線付きの「獲得効果」タイトルを付ける。英語はGained effects。
- 本文20px、効果アイコン40px、発動契機欄52px、最大幅720px、本文余白20px。通知は効果数にかかわらず3秒で自動消去する。
- 通知自体はゲーム操作を止めない。未解決の選択・ロールなど、効果処理に必要な既存の制限だけ維持する。
- 対象なし・数量不足でも確定済みの本文を同じ時間で通知する。実処理は実行可能な分だけ行う。
- 特殊面の即時適用は、親の通知後に★の枠で子の効果群をまとめて通知する。
- ターン終了時の特殊面予約を★の枠で通知し、翌日の発動時には再通知しない。「翌日に発動」の補足は付けない。通常の日次ドロー・リロール権付与は通知しない。
- ホバーはアイコンから離れたら閉じる。タップ表示は保持し、そのアイコンの再タップまたはポップアップの外側のタップで閉じる。
- 親をタップで開いた後、本文内アイコンも同じホバー・タップ処理を使う。子の外側を親の中でタップした場合は子だけを閉じ、最上位の外側なら全体を閉じる。
- 通知はスクロール領域や高さ制限を設けない。本文は折り返し、アイコンの大きさ・縦横比を維持する。特殊面の重複効果は通知上で集約して高さを抑える。
- 特殊面用の配色判断はオーナー指示で後に回し、中立色を使用した。★の枠の表示は確認済み。独自の紫系配色案は採用していない。

## 要求仕様変更の承認と反映

### ダイス破棄

オーナーは、通常のパレット操作と揃えるため、破棄対象を未使用ダイスへ限定する変更を指示した。

- requirements/01.game_rules.md: 消費済みダイスの対象外一覧に破棄効果を加え、「ただし、破棄効果では選択できる。」を削除する案を承認後に反映した。
- requirements/03.information_and_interaction.md: 破棄の対象を永続・一時の未使用ダイスとし、不足時は未使用分をすべて破棄する。対象なしの表現は即時リロール・色変更に合わせた案を承認後に反映した。
- 同書の対象選択の一覧は、オーナー指定の「リロール・面変更・破棄では、消費済みダイスを対象に含めないこと。」にした。特殊面の即時適用は選択操作ではないため一覧から外すが、消費済みを処理対象にしないルールは維持した。
- requirements/06.dice_effects.md: 5.1の冒頭、不足時、対象・対象なしの各文を個別に承認後に反映した。
- effects.jsと対象テストを更新し、消費済みは選択不可、未使用の一時ダイスは選択可能、不足時・対象なしの処理を確認した。

### 達成時の順序

オーナーは達成カードが捨て札へ移ってから通知・効果を発動するよう指示した。

- requirements/01.game_rules.mdの変更案を提示し、今達成したカードがドロー時の捨て札補充に含まれる影響も説明して、承認を得た。
- 承認された文は「カードのステップを1段階上げ、ステップ3なら出荷し、ステップ2以下なら捨て札に置く。その後、達成したステップの達成時効果を発動する。」。
- finishAchievementでは達成前の効果配列を保持し、ステップ更新・捨て札への移動・出荷（信用増加を含む）の後に通知と効果を処理する。選択待ちの間もカードは移動先にある。
- 達成後のカードを捨て札から引けること、次のステップの効果を誤発動しないこと、出荷と信用更新が選択より先に終わることをテストした。

## 検証中の失敗と調査

- 初回のComputer UseはWindowsブラウザのURL判定に失敗して停止した。その時点では実画面未確認として報告し、後続で既存Playwrightによる検証を実施した。
- サンドボックス内の全テストはローカル接続EACCESと保存APIの500で2件失敗した。同じコマンドを制限外で実行して全件成功し、製品コードの修正は不要だった。
- 旧3003番サーバーはHTTP応答がタイムアウトしたため、検証用サーバーを3010番で起動した。
- 達成順の追加ブラウザ検証は、閉じたパネルの切り離された捨て札DOMを直接検索してタイムアウトした。パネルを開いてから表示を検査するよう修正し、成功した。
- 検証環境でVite HMRのWebSocket接続はローカルネットワーク制限により失敗したが、HTTP読み込み・検証操作は成功し、ページ例外はなかった。
