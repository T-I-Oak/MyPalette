# バックログ

## 要望・バグ指摘

以下の分類と順序で開発を進める。既知のバグは最優先とし、先頭に置く。各項目の具体的なスコープと完了条件は、着手する計画フェーズで定める。

### 1. ルール

#### MP40-02: ダイス破棄効果を未使用ダイスの指定個数の使用済み化へ変更する

- 要望: ダイスを破棄する効果を、未使用ダイスを指定個数選んで使用済みにする効果へ変更する。
- 変更範囲: 効果アイコン、説明文、対象選択と効果処理。ダイスを所持から取り除かず、使用済み状態として残し、パレット表示と達成可能表示を更新する。
- 完了条件: アイコン・説明文・処理が未使用ダイスの指定個数の使用済み化として一致する。既存の効果定義・個数設定・保存済みデータ・関連仕様・テストへの影響を着手時に確認し、必要な変更を計画する。対象なしや永続／一時ダイスの扱いを計画時に確定する。
- 関連するEUI-10は、効果変更の内容を確定してから正式UIの対象と確認内容を合わせる。

#### MP40-03: 所持ダイスの面構成をゲーム中に確認できるようにする

- 発見事項: v0.40定期見直しで確認。要件01の§4-1は「所持ダイスの内容（各面の構成含む）」を公開情報とし、原則としてゲーム中にいつでも確認できることを求めるが、正式UIには面構成を確認する手段がない。全6面を表示する一覧は通常のゲーム画面でも組み立てられるが、正式パレットの表示時に取り除かれる。面検索で分かるのは条件に合う面の数だけで、獲得時の候補表示は獲得のときだけである。
- 対応: 所持ダイスの面構成をゲーム中に確認できる表示を実装する。実現手段はMP40-04（長押しによるダイス情報表示）が候補で、着手時にあわせて定める。
- 関連: MP40-04、MP40-14（通常のゲーム画面で旧評価用のダイス一覧を生成しない）。

### 2. 検証・テスト

#### QA-01: 要求02〜05と検証の対応を確定する

- 発見事項: 定期見直しでは文書単位の対応表までしか作成しておらず、個々の要求について既存テストのどのassertで確認するか、手動確認が必要か、未実装かを追跡できない。章別のテストファイルがないこと自体を不具合とはしない。
- 対象: コミット `020980161f58939ff52c5f20ed5ad10ad46d25d1` の `docs/requirements/02.visual.md`、`03.information_and_interaction.md`、`04.effect_conventions.md`、`05.icon_presentation.md` に記載された要求。後から追加された要求、要求01・06・07、全操作順・全入力の網羅は含めない。
- 成果物: `docs/spec/20.acceptance_verification.md` に対応表を作成する。要求のファイル名・節番号と、本文・箇条書き・表のどの条件かを各行で特定する。1行に実装済みと未実装の条件を混ぜない。

以下のすべてを満たしたとき、QA-01を完了とする。

1. 対象4文書の各節を一覧にし、各節の要求を対応表の行へ割り当てる。目的・説明・調整の許容範囲など合否条件を持たない記述は、その理由を記載する。未分類の節・条件を残さない。
2. 実装済みの各要求は、自動検証または手動検証を実施して成功を記録する。自動検証はファイル・テスト名・該当assertと実行コマンドを示す。手動検証は初期データ、画面サイズ、操作手順、観察対象、期待結果、実行結果と証跡を示す。いずれも確認バージョンを記載する。既存検証で十分なら新規テストは不要。対象テストがないという理由だけで未確認のまま完了にしない。
3. 未実装の各要求は、対応する既存バックログのID、IDがなければ見出しと項目名を記載する。長押し6面確認などの機能自体をこの項目で実装せず、既存項目へ二重登録しない。部分実装は条件を分け、実装済み部分には条件2を適用する。
4. 検証失敗、対応先のない要求、未回答の判断事項が残っていればQA-01は未完了とする。別項目へ分割する場合は、要求・再現条件・期待結果・完了条件をその項目に明記し、その移管についてオーナーの判断を記録する。単に「今後対応」と書き換えて完了にしない。

着手条件は現行の保存済み設定と既存ブラウザー検証が利用できること。全エリアやEUIの正式化は待たず、この対応表の作成・検証は単独で着手できる。

#### MP40-15: 演出の検証（二重表示・操作競合・座標・追従）

演出中の二重表示や操作競合を防ぎ、画面外の座標、リサイズ・パネル開閉への追従、動きを減らす設定を検証する。

#### MP40-16: 要求01のコンポーネント定義と公開情報に対応する仕様テストを追加する

- 発見事項: v0.40定期見直しで確認。`docs/requirements/01.game_rules.md` の仕様テストは `tests/spec/rules_01_game_flow.test.js` が§3（ゲームの流れ）に集中しており、§2（コンポーネント定義）と§4-1（公開情報）に対応する専用の仕様テストがない。通常ダイスの面構成は実装テスト（`tests/implementation/game/goals.test.js`）でのみ確認されている。
- 対応: §2の定義値（画材ダイスの面構成、絵画カード、チラシ）と§4-1の公開情報の範囲を仕様テストで検証する。QA-01の対象は要求02〜05で要求01を含まないため、本項目で扱う。

#### MP40-17: 実装仕様（08〜19）の統括モジュールに対応するテストを追加する

- 発見事項: v0.40定期見直しで確認。`docs/spec` の08〜19には仕様テストがなく、統括モジュール `src/editor.js`（08.card_editor）、`src/game/cardScene.js`（18.card_scene）、`src/game/view.js`（09.playable_game）は実装テストからも到達しない。下位モジュールにはテストがある。
- 対応: 統括モジュールの責務に対応するテストの要否と範囲を着手時に定め、必要なテストを追加する。

### 3. UI

#### MP40-04: 長押しによるダイス情報表示

ダイスの進行・獲得・リロール・消費・破棄との接続と配置は実装済み。残作業として、オーナー指定で未実装の長押しによるダイス情報表示を実装する。所持ダイスの面構成の公開（MP40-03）の実現手段の候補。

#### MP40-05: アイコンのホバー説明の改善

アイコンをホバーした際の説明表示を改善する。効果アイコンのホバーは完了。残作業は、目標ダイスアイコンのホバー改善と、目標・プレイ時・達成時の見出しアイコンへのホバー説明追加。具体的な改善内容と完了条件は、その計画フェーズで定める。

#### MP40-09: カンバスの絵をカードと同じ絵へ変更する

- 要望: カンバスに表示する絵を、同じステップのカードに表示する絵と一致させる。カード側の制作段階のグラデーションを含む絵に合わせる。
- 達成演出: 例えばStep 0の達成時は「Step 0カードの絵」から「Step 1カードの絵」へ描き変わるアニメーションにする。他のステップも達成前後のカードの絵へ対応させる。
- 完了条件: カードからカンバスへの切り替え、次ステップへの描き変え、カードへの復帰で絵が一致する。Step 0→1・1→2・2→3と、動きを減らす設定での表示を確認する。具体的な見た目と演出はオーナーと調整し、関連仕様・検証を更新する。

#### MP40-10: 効果獲得の表示を見直す

- 要望: 効果獲得の表示を見直す。具体的な見直し内容は、着手時にオーナーが説明する。

#### 効果発生時のUIの正式化

プレイ時効果・達成時効果を、効果の種類ごとに個別のバックログとして管理する。`src/effectCatalog.js`の16種類のうち、確認済みの即時リロール（EUI-06）を除く15種類を対象とし、同じ効果のプレイ時・達成時は1項目へまとめる。各行は独立した未完了項目であり、着手時に具体的なUIと完了条件をオーナーと確認する。

既存のゲーム処理・物理ロール・状態表示は再利用し、すでに接続済みの機能も、効果発生元の提示、対象・候補の選択、結果の通知・演出、後続処理への再開を含めて正式UIとして確認する。既存の実装を未実装とみなして作り直すものではない。個数、色、補色、画材、永続／一時、特殊面の種類などのパラメータ違いは各項目の確認範囲に含める。

プレイ時は着手に続く効果として、達成時はカンバス・画材・次カード・イーゼル消去の演出を終えた後の効果として接続する。対象なし・連続効果・ロール待機・操作競合、A/B・リサイズ・固定倍率変更・動きを減らす設定も確認する。仮エリアとの間の移動演出は、既存方針どおり両側の正式化後に対応する。

### 4. 実装基盤

#### MP40-12: イーゼルをページ内の共通プールで再利用する

- 改善: カードIDごとにイーゼルを保持する方式を改め、場に出すときにプールから借り、撤去・出荷の演出完了後にカード固有の状態を外して返却する。局の終了時も使用中の台を返却し、次の局で再利用する。
- 保持台数は演出中も含めて同時に必要な台数に応じて増やす。同時に5台程度が必要になる可能性があり、実機ログで確認した7台からの削減幅は限定的と見込む。
- MP28-02（プレイ中に突然タイトルへ戻る事象）との因果関係は未確認。資源の再利用は別項目として検証する。

#### MP40-13: カードのアイコン描画をカードごとに1枚の Canvas にまとめる

- 改善: カード上のアイコンごとに Canvas を作る方式を改め、カードごとに共有の Canvas に描画する。正式版のカード表示とサイズ変更時の描画を確認する。

#### MP40-14: 通常のゲーム画面で旧評価用のダイス一覧を生成しない

### MP28-02: iPad の Safari でプレイ中に突然タイトルへ戻る（原因未特定・現環境で再現せず）

- 経緯: iPad Safari で通常プレイ中に突然タイトルへ戻る現象が複数回発生した。保持ログでは日開始、着手・効果、達成、日末など複数の処理で旧ページの記録が途切れ、別ページIDで起動していた。手動の戻る操作や再読み込みではないとの報告。特定の操作や効果との因果関係は未特定。
- 調査: 解像度、リサイズ、WebGL・物理ロールの除去、Canvas削減、演出の比較を行ったが、原因と修正は確定していない。これらの調査用変更は最終実装に含めない。
- 現状: iPadOS更新の申告後、再発したv0.28.21の公開成果物をそのまま復元して通常プレイ22日・約22分を完走。さらに調査開始前の通常構成v0.28.5でも9日＋26日を完走したとの報告。環境変化の可能性はあるが、更新前後のOS版と原因は未特定。
- 対応: 原因未特定・現環境では再現しない状態として保留し、再発時に通常構成での再現確認から再開する。修正済みとは扱わない。
