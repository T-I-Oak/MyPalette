# バックログ

## 要望・バグ指摘

以下の順序で開発を進める。各項目の具体的なスコープと完了条件は、着手する計画フェーズで定める。

### 1. UIの実装

ゲームの評価を踏まえて、ゲームの見た目を設計・実装する。

ゲーム接続は完了。保存済み設定から起動し、レイアウトA/Bで一局を進行できる。手札・プレイ・パレット・ストック・デッキ・捨て札・情報表示の全7エリアは正式UIを実装済み。

#### 既存部品と残作業

- ゲーム本体の入口 `/MyPalette/` と開発者用入口 `/MyPalette/dev.html` を分離している。本番ビルドには両方を含める。開発者入口はカード設定・共通アイコン確認を維持する。

- 組み換え式UI: エリア間移動ライブラリと評価用ゲームへの試験適用、仮7エリアのレイアウトA/B・エリア単位の等方拡縮・狭い画面の重なるサイドパネルを実装。ゲーム接続では評価用UIを7エリアへ仮配置し、状態更新・操作を接続した。全7エリアを正式化済み。各エリアの描画とエリア間の演出は既存の座標変換を使う。[画面レイアウト制御](../spec/14.screen_layout.md)と[エリア間移動の実装仕様](../spec/13.area_transition.md)の座標変換を使用する。
- ダイス単体・群、3D物理ロール、面表示、浮遊する結果表示、面構成の条件検索、ゲームの進行・獲得・リロール・消費・破棄との接続と配置は実装済み。残作業は、オーナー指定で未実装の長押しによるダイス情報表示・6面構成の確認。
- カード: ステップに応じた表示、評価用ゲームでの検証、プレイヤー向け手札の重なりと達成可能状態の表示、プレイエリアの正式UIへの組込み、手札からの着手演出、ストックの正式UIへの組込み、ストック内の公開・裏返し・補充と手札交換の返却・取得演出、デッキへの組込みとドロー演出は実装済み。実カード45枚の所属・位置・角度・表裏を共通管理し、捨て札への回収・再構成・残る手札とイーゼルの再配置も連続移動にした。出荷済み作品は完成画を情報エリアへ移動し、カンバスからカード詳細を確認できる。
- アイコンをホバーした際の説明表示を改善する。効果アイコンのホバーは完了。残作業は、目標ダイスアイコンのホバー改善と、目標・プレイ時・達成時の見出しアイコンへのホバー説明追加。具体的な改善内容と完了条件は、その計画フェーズで定める。
- カンバス: 達成時のカードとの切り替え、画材の時間差飛行・時計回り周回・帰還吸収、斜めの段階画像更新は実装済み。残る画材配置や未実装のエリア間移動は、対応する正式UI実装で扱う。

#### エリアごとのゲームUI実装

正式UIの実装は、すべてのエリアでオーナーと綿密に意識合わせしながら進める。実装前に配置・見た目・操作・演出の具体案を提示し、小さな単位で確認可能な状態を作って、操作手順と確認点を提示する。フィードバックを反映し、オーナーの確認を得てから次のまとまりへ進む。完成後の一括確認にせず、実装途中から相談する。

手札 → プレイ → パレット → ストック → デッキ → 捨て札 → 情報表示の順に正式化した。各エリアはレイアウト側から渡される描画寸法に合わせて中身を配置・描画する。

#### MyPalette を実機で動作するようにする

- 経緯: 実機検証用の GitHub Pages 公開準備はオーナー確認済み。初回配信後のオーナー検証 `MP27-01` は不合格だった。実機での動作対応は今回の配信設定の範囲外とし、この項目で扱う。
- 調査: 着手時に機種、OS、ブラウザー、失敗した操作と症状を確認し、公開 URL で再現する。対応する機種とブラウザーは計画フェーズで決める。
- 完了条件: 対象の実機で公開 URL を開き、タイトルのバージョン表示を確認できる。「ゲーム開始」から「今日の仕事を始める」へ進み、初日の手札が配られ、ダイスの出目が表示されることを確認する。

#### ゲーム終了画面の正式化

- 仮のゲーム終了画面を正式な画面に仕上げる。
- 完了条件: ゲーム終了と最終名声値を確認でき、タイトルへ戻れる。画面構成、最終名声値以外の表示項目、演出は着手時にオーナーと確認する。

#### 演出の実装方針と残作業

オーナー指定により、移動元・移動先のいずれかが仮エリアである移動演出を対象外とする。正式エリア内の演出と、正式エリア同士の移動演出は、各エリアの正式UI実装の対象に含める。全7エリアの完成までは待たない。具体的な内容・タイミングと完了条件は着手時に相談する。

- 手札からプレイエリアへの着手、ストック内の公開・裏返し・補充、手札交換の返却・取得演出は実装済み。初日のストックAからデッキへの7枚配分、デッキから手札への日次・効果ドロー、手札・プレイ・ストックから捨て札への移動、捨て札からデッキへの補充も実装済み。イーゼルから情報エリアへの出荷演出も実装済み。
- プレイエリア内のカードとキャンバスの切り替え、画材の時間差飛行・時計回り周回・帰還吸収、斜めの段階画像更新、完成・出荷の表示、空のイーゼルの撤去は実装済み。残る画材配置と未実装のエリア間移動は、対応する正式UI実装で扱う。仮エリアとの間の移動は両側の正式化後に対応する。移動演出を追加しない場合もゲーム状態と表示は正しく更新する。
- 演出中の二重表示や操作競合を防ぎ、画面外の座標、リサイズ・パネル開閉への追従、動きを減らす設定を検証する。

#### ダイス破棄効果を未使用ダイス1個の使用済み化へ変更する

- 要望: ダイスを破棄する効果を、未使用ダイスを1個選んで使用済みにする効果へ変更する。
- 変更範囲: 効果アイコン、説明文、対象選択と効果処理。ダイスを所持から取り除かず、使用済み状態として残し、パレット表示と達成可能表示を更新する。
- 完了条件: アイコン・説明文・処理が未使用ダイス1個の使用済み化として一致する。既存の効果定義・個数設定・保存済みデータ・関連仕様・テストへの影響を着手時に確認し、必要な変更を計画する。対象なしや永続／一時ダイスの扱いを計画時に確定する。
- 関連するEUI-10は、効果変更の内容を確定してから正式UIの対象と確認内容を合わせる。

#### カンバスの絵をカードと同じ絵へ変更する

- 要望: カンバスに表示する絵を、同じステップのカードに表示する絵と一致させる。カード側の制作段階のグラデーションを含む絵に合わせる。
- 達成演出: 例えばStep 0の達成時は「Step 0カードの絵」から「Step 1カードの絵」へ描き変わるアニメーションにする。他のステップも達成前後のカードの絵へ対応させる。
- 完了条件: カードからカンバスへの切り替え、次ステップへの描き変え、カードへの復帰で絵が一致する。Step 0→1・1→2・2→3と、動きを減らす設定での表示を確認する。具体的な見た目と演出はオーナーと調整し、関連仕様・検証を更新する。

#### 効果発生時のUIの正式化

プレイ時効果・達成時効果を、効果の種類ごとに個別のバックログとして管理する。`src/effectCatalog.js`の16種類のうち、確認済みの即時リロール（EUI-06）を除く15種類を対象とし、同じ効果のプレイ時・達成時は1項目へまとめる。各行は独立した未完了項目であり、着手時に具体的なUIと完了条件をオーナーと確認する。

既存のゲーム処理・物理ロール・状態表示は再利用し、すでに接続済みの機能も、効果発生元の提示、対象・候補の選択、結果の通知・演出、後続処理への再開を含めて正式UIとして確認する。既存の実装を未実装とみなして作り直すものではない。個数、色、補色、画材、永続／一時、特殊面の種類などのパラメータ違いは各項目の確認範囲に含める。

プレイ時は着手に続く効果として、達成時はカンバス・画材・次カード・イーゼル消去の演出を終えた後の効果として接続する。対象なし・連続効果・ロール待機・操作競合、A/B・リサイズ・固定倍率変更・動きを減らす設定も確認する。仮エリアとの間の移動演出は、既存方針どおり両側の正式化後に対応する。

### QA-01: 要求02〜05と検証の対応を確定する

- 発見事項: 定期見直しでは文書単位の対応表までしか作成しておらず、個々の要求について既存テストのどのassertで確認するか、手動確認が必要か、未実装かを追跡できない。章別のテストファイルがないこと自体を不具合とはしない。
- 対象: コミット `020980161f58939ff52c5f20ed5ad10ad46d25d1` の `docs/requirements/02.visual.md`、`03.information_and_interaction.md`、`04.effect_conventions.md`、`05.icon_presentation.md` に記載された要求。後から追加された要求、要求01・06・07、全操作順・全入力の網羅は含めない。
- 成果物: `docs/spec/17.acceptance_verification.md` に対応表を作成する。要求のファイル名・節番号と、本文・箇条書き・表のどの条件かを各行で特定する。1行に実装済みと未実装の条件を混ぜない。

以下のすべてを満たしたとき、QA-01を完了とする。

1. 対象4文書の各節を一覧にし、各節の要求を対応表の行へ割り当てる。目的・説明・調整の許容範囲など合否条件を持たない記述は、その理由を記載する。未分類の節・条件を残さない。
2. 実装済みの各要求は、自動検証または手動検証を実施して成功を記録する。自動検証はファイル・テスト名・該当assertと実行コマンドを示す。手動検証は初期データ、画面サイズ、操作手順、観察対象、期待結果、実行結果と証跡を示す。いずれも確認バージョンを記載する。既存検証で十分なら新規テストは不要。対象テストがないという理由だけで未確認のまま完了にしない。
3. 未実装の各要求は、対応する既存バックログのID、IDがなければ見出しと項目名を記載する。長押し6面確認などの機能自体をこの項目で実装せず、既存項目へ二重登録しない。部分実装は条件を分け、実装済み部分には条件2を適用する。
4. 検証失敗、対応先のない要求、未回答の判断事項が残っていればQA-01は未完了とする。別項目へ分割する場合は、要求・再現条件・期待結果・完了条件をその項目に明記し、その移管についてオーナーの判断を記録する。単に「今後対応」と書き換えて完了にしない。

着手条件は現行の保存済み設定と既存ブラウザー検証が利用できること。全エリアやEUIの正式化は待たず、この対応表の作成・検証は単独で着手できる。

### ダイスが他のダイスの上で静止した場合は出目を確定しない

- 要望: ロール中のダイス同士の衝突を維持し、別のダイスの上で静止した場合は出目を確定せず再投入する。
- 完了条件: 床に着地して既存の静止・上面条件を満たしたダイスは出目を確定し、別のダイスの上で静止したダイスは再投入する。両方のケースを検証し、水平に安定した積み重なりを確定条件に含めている現行仕様を更新する。
- 着手順序: 未定。
