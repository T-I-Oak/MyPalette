# バックログ

## 要望・バグ指摘

以下の順序で開発を進める。各項目の具体的なスコープと完了条件は、着手する計画フェーズで定める。

### 効果発生時の共通UI

- EUI-C01：効果発生時の共通UIを設計・正式化する。プレイ時・達成時で共通に使う、効果の発生元・内容・処理順・選択待ち・ロール待ち・解決結果の提示方法を定める。個別効果のUI正式化（EUI-01〜EUI-16）とは別のバックログとして管理し、具体的なスコープと完了条件は着手時にオーナーと確認する。

### 1. UIの実装

ゲームの評価を踏まえて、ゲームの見た目を設計・実装する。

ゲーム接続は完了。保存済み設定から起動し、評価用UIの仮表示で7エリアのレイアウトA/Bにおける一局の進行・終了・再プレイを接続済み。今後は1回の開発につき1エリアだけを正式実装し、接続済みの仮表示を置き換える。

#### 既存部品と残作業

- ゲーム本体の入口 `/MyPalette/` とローカル開発者用入口 `/MyPalette/dev.html` の分離、および本番成果物からの開発者用ツールの除外は実装済み。プレイヤー向けのゲーム本体を作る際も、開発者向けの評価プレイ・カード設定・ダイスやアイコンの確認画面を維持する。

- 組み換え式UI: エリア間移動ライブラリと評価用ゲームへの試験適用、仮7エリアのレイアウトA/B・エリア単位の等方拡縮・狭い画面の重なるサイドパネルを実装。ゲーム接続では評価用UIを7エリアへ仮配置し、状態更新・操作を接続した。各エリアを正式なゲームUIへ置き換え、正式エリア内と正式エリア同士の演出は各開発の対象に含める。仮エリアとの間の移動演出は対象外とし、両側の正式化後に対応する。[画面レイアウト制御](../spec/14.screen_layout.md)と[エリア間移動の実装仕様](../spec/13.area_transition.md)の座標変換を使用する。
- ダイス単体・群、3D物理ロール、面表示、浮遊する結果表示、面構成の条件検索、専用動作確認画面は実装済み。残るダイス作業は、既存ゲームの進行・獲得・リロール・消費処理への組込みとゲーム画面での配置。
- ゲーム本体への3Dダイス組込み時に、プレイヤー向けの入口で読み込むJavaScriptの容量と、ゲーム開始から初回のロールが可能になるまでの時間を測る。開発者向け画面も含めてビルド時の3Dダイス関連のサイズ警告を解消し、現行の500 kBしきい値で警告が出ないことを完了条件とする。
- カード: ステップに応じた表示、評価用ゲームでの検証、プレイヤー向け手札の重なりと達成可能状態の表示、プレイエリアの正式UIへの組込み、手札からの着手演出は実装済み。残る作業は、他エリアの正式UIへの組み込みと、未実装のカード移動・裏返しの演出。仮エリアとの間の移動演出は両側の正式化後に対応する。
- アイコンをホバーした際の説明表示を改善する。オーナー指摘により、手札エリア実装とは別のブランチで対応する。具体的な改善内容と完了条件は、その計画フェーズで定める。
- カンバス: 達成時のカードからキャンバスへの切り替えと段階画像の更新は実装済み。残る作業は、ダイス移動を含む詳細な描き変え演出。
- 達成時のキャンバスの描き変えを、ダイスの移動などを含む細かな演出へ拡張する。オーナー指定により別ブランチで対応する。今回のプレイエリア実装では待機時間を長めに取り、ダイス移動は追加しない。
- パレット: ダイスが置かれると画材が表示される演出などを実装する。

#### エリアごとのゲームUI実装

正式UIの実装は、すべてのエリアでオーナーと綿密に意識合わせしながら進める。実装前に配置・見た目・操作・演出の具体案を提示し、小さな単位で確認可能な状態を作って、操作手順と確認点を提示する。フィードバックを反映し、オーナーの確認を得てから次のまとまりへ進む。完成後の一括確認にせず、実装途中から相談する。

ゲーム接続の完了後、手札 → プレイ → パレット → ストック → デッキ → 捨て札 → 情報表示の順に、1回の開発につき1エリアだけを正式実装する。レイアウトA/Bの対象エリアの仮表示を正式なゲームUIへ置き換え、接続済みのゲーム状態・操作を使用する。各エリアはレイアウト側から渡される描画寸法に合わせて中身を配置・描画する。既存のカード・ダイス・カンバス・パレットの残作業との対応と具体的な完了条件は、各開発の計画フェーズで定める。

- パレットエリアの実装。所持する画材ダイスの表示・操作と、ロール・獲得・リロール・消費・破棄などの状態変化をゲーム状態に接続する。
- ストックエリアの実装。ストックの絵画カードの表示・確認と、発注によるカード取得をゲーム状態に接続する。
- デッキエリアの実装。デッキの表示と、ドローやカードの出入りをゲーム状態に接続する。
- 捨て札エリアの実装。捨て札の表示・確認と、カードの出入りをゲーム状態に接続する。
- 情報表示エリアの実装。ゲームの進行状況と判断に必要な情報を表示する。

#### 演出の実装方針と残作業

オーナー指定により、移動元・移動先のいずれかが仮エリアである移動演出を対象外とする。正式エリア内の演出と、正式エリア同士の移動演出は、各エリアの正式UI実装の対象に含める。全7エリアの完成までは待たない。具体的な内容・タイミングと完了条件は着手時に相談する。

- 手札からプレイエリアへの着手演出は実装済み。手札へのドロー、返却、仕事終了などの移動・裏返しは、接続先が仮エリアの間は演出を追加せず、正式化後に対応する。
- プレイエリア内のカードとキャンバスの切り替え、段階画像の更新、完成・出荷の表示、空のイーゼルの撤去は実装済み。残る作業は詳細な描き変え、画材の配置、その他の未実装のエリア間移動などの演出。仮エリアとの間の移動は両側の正式化後に対応する。移動演出を追加しない場合もゲーム状態と表示は正しく更新する。
- 演出中の二重表示や操作競合を防ぎ、画面外の座標、リサイズ・パネル開閉への追従、動きを減らす設定を検証する。

#### 効果発生時のUIの正式化

プレイ時効果・達成時効果を、効果の種類ごとに個別のバックログとして管理する。`src/effectCatalog.js`の16種類を対象とし、同じ効果のプレイ時・達成時は1項目へまとめる。各行は独立した未完了項目であり、着手時に具体的なUIと完了条件をオーナーと確認する。

既存のゲーム処理・物理ロール・状態表示は再利用し、すでに接続済みの機能も、効果発生元の提示、対象・候補の選択、結果の通知・演出、後続処理への再開を含めて正式UIとして確認する。既存の実装を未実装とみなして作り直すものではない。個数、色、補色、画材、永続／一時、特殊面の種類などのパラメータ違いは各項目の確認範囲に含める。

プレイ時は着手に続く効果として、達成時はカンバス・画材・次カード・イーゼル消去の演出を終えた後の効果として接続する。対象なし・連続効果・ロール待機・操作競合、A/B・リサイズ・固定倍率変更・動きを減らす設定も確認する。仮エリアとの間の移動演出は、既存方針どおり両側の正式化後に対応する。
