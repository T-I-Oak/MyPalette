# v0.13 ゲーム接続 計画

## 合意した開発内容

- ブランチ: `feature/v0.13-game-connection`
- 予定バージョン: `0.13.0`。初回の実装開始時にpackage.jsonとpackage-lock.jsonを更新する。計画フェーズでは現行の0.12.1を維持する。
- ゲーム接続と各エリアの正式実装を分ける。今回の対象はゲーム接続だけとする。
- 後続は情報表示、手札、プレイ、パレット、ストック、デッキ、捨て札の順に、1回の開発につき1エリアだけを正式実装する。

## スコープ

- プレイヤー向け入口 `/MyPalette/` で保存済みpublic/data/cards.jsonを読み込み、既存の検証とGameエンジンを使用してゲームを起動する。
- 既存の評価用UIの表示・操作を仮表示として再利用し、7エリアへ配置する。情報、制作中、所持ダイス、ストック、デッキ、捨て札、手札を対応するエリアへ割り当てる。
- 操作の受付と状態更新をまとめ、各エリアが同じゲーム状態を参照して更新される接続を整える。後続で1エリアの仮表示を差し替えられる責務に分ける。
- カードのプレイ・達成、ダイスのリロール、効果対象と獲得候補の選択、日次進行、終了表示・再プレイを接続する。出荷済み作品や処理記録の確認は既存の確認UIを活用する。
- 設定の取得中・取得失敗・不備による開始拒否を表示する。
- ローカル開発者用入口、評価用ゲーム、カード設定、ダイス・アイコン確認を維持する。
- バックログにゲーム接続とエリア単位の正式実装の区切り・順序を記録する。

## 対象外

- 7エリアそれぞれの正式な外観・専用演出と最終的な操作デザイン。
- 3Dダイスのゲーム本体への組込み、物理ロールとゲーム判定の同期。今回は既存の評価用ダイス表示とロール処理を使用する。
- 手札の重なりや発光の調整、カードの移動・裏返しの演出調整、カンバス・パレットの演出。接続に既存表示を利用しても正式実装の完了とは扱わない。
- ゲームルール・カード設定の変更、要求仕様の変更、共通リポジトリの編集。
- ランキング、アチーブメント、ギャラリー、途中保存、過去記録の保存・比較、公開設定。

## 完了条件

1. プレイヤー向け入口で保存済み設定を検証して起動し、エラー時に理由を表示する。設定の補完や書換えを行わない。
2. 7エリアの仮表示が同じGameインスタンスの状態を参照し、操作・効果・日次更新の後に表示が一致する。表示確認だけではゲーム状態を変更しない。
3. 手札のプレイから達成・出荷、リロール、対象選択、仕事終了・翌日開始、信用0による終了・再プレイまで操作できる。選択待ち中はゲームエンジンの制約を守り、許可された操作に余分な順序制約を加えない。
4. A/Bの配置、エリアの等方拡縮、サイドパネルの遮蔽・入力制御を維持する。パネル開閉・画面寸法変更によってゲーム状態や選択が失われず、必要な情報・操作へ到達できる。
5. 1エリアずつ表示を差し替えられる構成になり、既存の評価用ゲームでも同じゲーム処理を使用する。
6. 開発者用各画面を維持し、本番成果物へ開発者用入口・設定編集・評価メタデータを含めない。
7. 対象テスト・全テスト・本番ビルドを実行し、結果と必要なオーナー検証の判断を実装報告へ記録する。

## 実装方針

- 既存のGame、gameIssues、保存済み設定読込み、評価用画面の部品を確認し、ルール処理を複製せず再利用する。
- ゲームの起動・操作・更新通知とエリアの表示責務を分離する。既存のview.jsをそのまま全画面に重ねるだけでは7エリアへの接続完了としない。
- ScreenLayout、CanvasArea、所属エリア別の描画層と座標変換の契約を使用する。仮表示も各エリアの割当寸法へ追従させる。
- 選択UI・カード詳細・終了表示などの共通表示は、所属エリアやパネルとの入力競合を避けて接続する。再プレイ時には旧ゲームの選択状態・イベント・表示を残さない。
- 実装に合わせてdocs/spec/14.screen_layout.mdと関連する実装仕様・開発手順を更新する。要求仕様は変更しない。

## テスト・確認方針

- 状態管理と操作の中断・再開など複雑な接続は、先にテストで期待挙動を定義する。既存のルールテストを活用し、エリアへの反映・選択中の操作制約・再プレイの状態分離を追加検証する。
- 対象テスト: `node --test tests/implementation/game/*.test.js tests/implementation/ui/*.test.js tests/implementation/settingsStorage.test.js tests/implementation/devServer.test.js tests/spec/rules_01_game_flow.test.js`。新規モジュールに対応するテストも実行する。
- ブラウザで横長A・縦長B、パネル開閉と遮蔽、リサイズ、情報確認・対象選択、終了・再プレイ、設定エラー、既存開発者入口を確認する。ブラウザ検証スクリプトはscriptsへ置き、Playwrightを必須依存へ追加しない。
- 正式な外観の評価と区別し、仮表示による一局の操作性とA/Bでの情報・操作への到達性を、確認可能になった時点でID・操作手順・期待結果・確認バージョン付きのオーナー検証として提示する。
- 実装終了草案前に `npm.cmd test` と `npm.cmd run build` を実行する。失敗時は原因を調査し、今回の変更に起因するものを修正して再実行する。
