# v0.12 画面レイアウト制御の開発計画

- 予定バージョン `0.12.0`
- 開発ブランチ `feature/v0.12-screen-layout`

## 開発範囲と責務

- レイアウトクラスは、利用可能な表示領域の寸法とサイドパネルの開閉状態から、各エリアの割り当て矩形、表示倍率、表示状態を決める。縦長ではレイアウトB、正方形と横長ではレイアウトAを使う。切り替え先でも同じ7エリアを使う。
- エリアクラスは正の標準幅・高さを持ち、受け取った論理幅・高さで中身を配置・描画する。表示状態はレイアウト側が扱う。既存のエリアクラスは接続に必要な範囲で修正し、評価用ゲームでの動作を維持する。
- `/MyPalette/` に7つの仮エリアを配置する。各仮エリアはエリアクラスの責務としてフレームとエリア名を描画する。サイドパネルを開閉できる操作部を設ける。

## 仮レイアウト

### レイアウトA

画面を左右 `1:1` に分ける。左半分は上から `1:3:2` で、情報表示エリア、プレイエリア、パレットエリアを置く。右半分は上から `2:2:2` で、ストックエリア、中央段、手札エリアを置く。中央段は左右 `1:1` で、左に捨て札エリア、右にデッキエリアを置く。

### レイアウトB

画面を上から `1:3:2:2` に分け、情報表示エリア、プレイエリア、パレットエリア、手札エリアを置く。右端の操作部をタップすると、初期状態で閉じているパネルが右からスライドインする。パネル上段にストックエリア、下段の左に捨て札エリア、右にデッキエリアを置く。開閉中もメインの4エリアの位置と寸法を維持する。パネルの寸法とアニメーション時間は仮画面で確認しながら実装時に決める。

## 実装方針

- 割り当て幅を `w`、高さを `h`、エリアの標準幅を `W`、高さを `H` とする。表示倍率は `s = min(w / W, h / H)`。エリアに `w / s` と `h / s` を渡す。片方の軸は標準と一致し、もう片方は標準以上となる。縦横比が一致する場合は両軸とも標準と一致する。
- 表示領域のリサイズを監視してレイアウトを再計算する。論理寸法が変化したエリアは、その寸法で中身を再配置する。位置や倍率の変更は、論理寸法が変わらない場合にも反映する。
- 閉じたパネル内のエリアは、画面右の外に原点と割り当て寸法を持つ。エリア内のコンポーネント矩形を、原点と倍率を使って画面座標へ変換できるようにする。パネルのスライドとエリアの座標更新を同期させる。座標系は既存の[エリア間移動の実装仕様](../spec/13.area_transition.md)と照合し、画面倍率の二重適用を防ぐ。
- CanvasはCSS上の表示寸法で配置し、表示寸法と端末のピクセル比から描画バッファーの寸法を決める。エリア側の論理座標からバッファーへの変換を描画コンテキストに適用して描く。表示寸法やピクセル比が変われば更新した解像度で描き直す。

## 対象外

ゲーム進行・カード設定との接続、ダイアログ、仮エリアの中身に相当するゲームUIや演出の実装。

## 完了条件とテスト方針

- レイアウト計算のテストを先に用意し、A/Bの切り替え境界、分割比、縦長・横長・同一比率での描画寸法と倍率、非表示エリアの画面外座標とコンポーネント矩形の変換を確認する。
- `/MyPalette/` を横長と縦長で開き、リサイズに追従して7エリアが指定の配置になることを確認する。Bでは初期状態でパネルが閉じており、開閉時にパネルだけがスライドし、メインの4エリアの位置と寸法を維持することを確認する。
- パネルの開閉中もコンポーネントの移動座標がエリアの表示位置に追従することと、Canvasの描画バッファーが表示寸法とピクセル比に応じて更新されることを確認する。
- 開発者向けの既存画面が維持され、本番ビルドから開発者用ツールが除外されることを確認する。対象テスト、`npm.cmd test`、`npm.cmd run build` を実行し、結果を実装報告に記録する。
