# 全エリア共通カード表示の設計

2026-11-10、オーナーが根本対処と常時表示・配置の連続性を指定。イーゼルは画面外との出入り、出荷先は情報エリア内の表向きの山とする回答を受領。実装契約は[全エリア共通カード表示](../spec/18.card_scene.md)へ反映する。

## 解消する問題

現在はviewがエリアごとのカードDOMを再生成し、演出側が複製を作り、元と先の表示を別々に隠している。そのため、ゲーム状態が先に進んだときの表示保持、後続演出の待機、キャンセル処理が複数のモジュールへ分散している。カードの消失・二重表示・瞬間移動を局所的な非表示条件で修正し続ける構造を解消する。

## 対象と境界

- 45枚の実カードの表示と移動を、ストック・デッキ・手札・プレイ・捨て札・出荷済みで共通管理する。
- 既存の合意済みの位置ずれ、表示、演出時間、順序、再構成手順を維持する。ゲーム要求仕様・ルール・共通リポジトリは変更しない。
- 手札やプレイ枚数の変化に伴う、移動対象以外のカードの再配置も共通管理に含める。
- 出荷済みの実カードは情報エリア内の表向きの山へ移動する。現在の出荷済み一覧は閲覧用として残す。
- イーゼルの追加・撤去・再配置・向き・倍率の変更も連続した動作として接続する。3Dモデルと描画方式は再利用する。ダイス・カンバスの描画方式と画面全体のデザイン変更は含めない。カードとカンバスの達成演出の接続は置き換えに含める。

## 表示と連続性の原則

2026-11-10のオーナー指定を設計・検証の基準とする。

- 実カードは常時どこかに存在して描画される。山の下に重なったカードも、位置・角度・表裏・重なり順を保持する。カードを一旦消して別の位置に出す方式は使用しない。
- 非表示の例外は、達成時にカードからカンバスの演出へ切り替えている間。理由を達成演出として明示した状態で管理し、その前後の姿勢を連続させる。
- シャッフルによる並び順の変更は、全カードが捨て札の中央へ集まって裏向きに重なった瞬間だけ行う。展開中・集合中・デッキへの移動中には並び順を飛ばさない。
- 手札のドロー・着手・交換によって配置が変わる場合、移動対象以外のカードも現在位置から新しい配置まで連続して動く。位置だけでなく倍率・向きの変化も補間する。
- イーゼルの増減でも、既存イーゼルを作り直して新しい位置へ置かず、同じ個体を現在の姿勢から新しい配置へ運ぶ。追加する個体・撤去する個体にも移動経路を持たせる。
- イーゼル上のカードのアンカーは、そのフレームでのイーゼルの位置・向き・倍率から計算する。カードとイーゼルを別々の終点へ先に更新しない。
- 後続動作への切り替えは直前の動作の最終姿勢から開始する。リサイズ・パネル開閉・動作の中断でも現在の姿勢を失わない。ゲーム画面が表示されたままの中断では、現在の姿勢から動作を組み直す。入口への復帰は表示シーン全体を破棄する。

イーゼルは画面右側の外から入り、左側の外へ抜ける。再利用する個体も右側から入る。退いた個体を保持して再利用する。

## 管理するもの

`CardScene`が全IDを登録し、実カード1枚につき1つのCardとDOM要素を維持する。

| 状態 | 意味 |
| --- | --- |
| ゲーム上の所属・ステップ | engineが管理するルール上の状態。表示から変更しない。 |
| 表示上のエリア・重なり順 | カードが現在存在する表示位置。後続処理が進んでも演出の到着までは保持する。 |
| アンカー | エリアのレイアウトから得る位置・大きさ・投影。リサイズやパネル開閉時に再評価する。 |
| 姿勢 | 位置・倍率・面内回転・立体投影の行列、表裏の回転角、透明度。 |
| 表示内容 | 表示するステップと参照中のタブ。ゲーム上のステップと区別する。 |
| 動作 | 移動元・移動先・進行度・開始条件・完了処理。 |
| 操作 | その時点で許可される閲覧・選択・ゲーム操作。 |

拡大詳細は物理的なカードの移動ではなく閲覧用の表示として分離し、実カードの所属や姿勢の管理に参加させない。

## 責務

1. 各エリアはカードのアンカーと重なり順を計算する。カードを作ったり隠したりしない。
2. 共通の進行管理が、操作による移動・裏返し・再配置を時間順に計画する。未開始の動作でカードの表示位置を変えない。
3. CardSceneだけが実カードDOMの配置・姿勢・表裏・表示内容を更新する。移動中も同じ要素を共通移動層へ移して使用する。
4. イーゼル上のカードは平面投影行列をアンカーとして受け取り、同じCardを描く。達成時の透明度や内容変更も共通管理を通す。
5. 全体の描画更新はカードを再生成しない。カードの操作内容や詳細への入口は、現在の状態を参照する接続として更新する。
6. 動きを減らす設定、キャンセル、エラー復帰は共通進行管理が扱う。表示継続時は現在姿勢を起点として再計画し、入口へ戻るときはシーン全体を解放する。
7. プレイ側はイーゼルの個体と姿勢を維持し、共通の時間進行に合わせて移動する。その時点のカード支持面の投影をCardSceneへ渡す。

エリア単位の非表示制御を共通APIへ移すだけでは完了としない。実カードの複製・再生成・表示の複数管理を廃止する。

## 移行順序

1. 全45IDの登録・姿勢・アンカー・動作の所有権・キャンセルを扱う純粋な状態管理を、テストを先に作って実装する。
2. 共通描画を追加し、静止中と移動中で実カード要素が同一であることを検証する。
3. ストック・デッキ・手札・捨て札の配置、公開・交換・初日配分・ドロー・再構成を接続する。
4. プレイの立体投影、着手・達成・日末回収、残りカードの再配置、イーゼルの追加・撤去・再配置を接続する。
5. 既存の複製、手札／山全体の非表示、途中状態を保つためのエリア別上書きを削除する。
6. 既存ブラウザー検証を、新しい表示構造と共通の不変条件へ合わせて実行する。出荷の見せ方をオーナー確認後に接続する。

途中の互換接続は移行のために限定する。既存経路と新経路の両方が同じカードを所有する状態は作らない。

## 完了条件

- 45IDすべてについて実カードが常に1つ存在し、同じカードの動作が重複しないことをテストで確認する。
- 移動開始・到着だけでなく、動作切替の前後と移動中の各フレームでも姿勢が連続する。達成時のカンバス演出以外では実カードを非表示にせず、待機中の消失・先回り表示を起こさない。
- シャッフル順の不連続な変更は中央に全カードが重なった瞬間に限定する。
- 手札とイーゼルの増減を実行し、残りのカード・イーゼルと、追加・撤去するイーゼルが連続移動することを確認する。カード支持面とカードの投影位置が各フレームで一致する。
- 各エリアは表示位置を計算する役割となり、他の演出のためにカード全体を隠さない。
- 既存の合意済み演出、表示、ゲーム操作を維持し、枚数変化時の再配置も補間する。
- 連続操作、途中再構成、達成直後の同じカードの再ドロー、発注と日末回収、空ストック、途中終了、リサイズ・パネル開閉・固定倍率・動きを減らす設定を確認する。
- 対象・全テスト・本番ビルドとブラウザー検証を記録し、利用者が確認できる単位でオーナーへ提示する。

内部実装の誤りだけを検出するための実行時チェックは設けない。常時表示・個体と所属の一意性・演出順序は単体／ブラウザーテストの責務とし、本体は状態更新・描画・補間・中断を行う。透明度に演出理由を渡すAPIも使用しない。
