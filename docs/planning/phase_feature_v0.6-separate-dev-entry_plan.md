# v0.6 開発者用入口の分離

## 開発スコープ

- 予定バージョンは `v0.6.0`、開発ブランチは `feature/v0.6-separate-dev-entry` とする。バージョン設定は実装フェーズ開始時に更新する。
- `/MyPalette/` をゲーム本体の入口、`/MyPalette/dev.html` をローカル開発サーバー専用の入口とする。HTMLと起動用JavaScriptを分ける。今回はゲーム本体側にタイトルとバージョンを表示する入口を用意する。
- 評価プレイ、カード設定、ダイス動作確認、共通アイコン確認を開発者用の入口にまとめる。各画面からの戻り先と開発者向けの確認手順を新しい入口に合わせる。
- プレイヤー向けの本番成果物から、開発者用のHTML、コード、スタイル、専用データを除外する。保存APIはローカル開発サーバーで提供する。

## 対象外

- プレイヤー向けゲーム画面の設計と実装、レスポンシブ配置、3Dダイスのゲーム本体への組み込み、カード・キャンバス・パレットの演出。
- ゲームルール、カード設定や評価データの内容、開発者用ツールの機能変更、追加要素、公開設定。
- ゲーム本体への3Dダイス組み込み時に行う読み込み計測とチャンクサイズ対策。

## 実装方針

- 本番ビルドのHTML入口は `index.html` のみとする。プレイヤー向け入口の依存関係にツールの起動コードや画面が入らない構成にする。
- `public/` はViteのビルドでコピーされるため、開発専用の `effect-evaluation.json` は `public/` 外に移し、ローカル開発サーバー経由で読み書きする。共有の `cards.json` とゲーム用素材は既存の公開パスを維持する。評価データを移す際は内容を保持する。
- 現行の画面を呼び出している確認スクリプト、実装仕様、開発環境の案内を新しい入口に合わせる。

## 完了条件と検証

- ローカル開発サーバーで両方の入口を直接開ける。開発者用の入口から4つのツールを起動し、入口へ戻れる。評価プレイの起動とカード設定・評価データの読み書きを確認する。保存の検証にはテスト用の設定ファイルを使う。
- `npm.cmd test` と `npm.cmd run build` が成功する。ビルドのモジュール構成と `dist/` の出力を調べ、開発者用HTML、画面・Worker・スタイル、専用データが含まれないことを確認する。
- 本番プレビューでゲーム本体の入口を表示できる。`dev.html` を直接指定しても開発者用ツールは起動せず、専用データの取得や保存APIによる書き込みもできないことを確認する。
