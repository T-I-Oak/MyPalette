## 0.16.1：レビュー指摘対応

### PA-REV-01：多ダイス対応

最大12個という描画側の上限を撤去した。オーナーから「13個だけ直して20個で止まるのでは不十分」「ダイスを小さくするより、画像を比率維持で拡大しエリア拡縮へ任せる」との指示を受け、同方針へのok後に実装した。

パレット・物理床・外縁・配置範囲をs=max(1,√(N/12))で拡大。12は従来サイズを維持する基準で、所持上限ではない。本体・物理形状・フロート・境界余白の論理サイズは維持する。標準寸法は12個536×232、13個558×239、20個688×280、30個839×328。既存のエリア倍率で全体が縮小表示される。固定層ボタンの高さ36は変わらない。

配置番号の固定長割当を廃し、空き番号を再利用。初期・再投入位置は拡大後の行列で算出する。既存のX/Zは倍率比で移動し、出目・面・使用状態は保持する。ドラッグは現在の境界を使い、減少時も縮小する。カメラ・投影・影の範囲を追従させ、カメラの行列はサイズ変更と同時に更新する。物理境界の再構築時には古い剛体を削除し、破棄後のロール完了で境界が再生成されないようにした。

TDDでlargePalette.test.jsを追加し、修正前は13・20・30個すべてMaximum 12 diceで失敗したことを確認。修正後はGameと実際のDiceGroup／syncPaletteSnapshotを接続して、初期3個＋獲得、物理結果と上面の一致、獲得前の出目保持、後続名声効果の再開、全体リロール、破棄まで成功。scaledField.test.jsでは1000個までの個数に対する境界・寸法の計算、画像比率、外縁ガード、縮小、状態保持、空き番号再利用を確認。1000個の実画面・物理ロールを検証したとの意味ではない。追加調査として30個全体の物理ロールを異なる10seedで実行し、すべて確定した。

checkLargePalette.cjsで実ブラウザーの13・20・30個について、獲得ロールと後続効果、全ダイスの表示、背景倍率、エリア倍率の縮小、固定ボタン高さ、選択・単体更新、狭幅390×844での破棄と縮小を確認して成功。tmp_large_palette_30.pngを目視し、パレット画像の比率とダイス・フロートの縮小表示を確認した。通常個数のcheckDiceDrag.cjs、checkAutomaticRolls.cjs、checkConsecutiveAchievements.cjsも成功。
