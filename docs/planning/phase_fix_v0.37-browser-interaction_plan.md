# ブラウザー操作抑止の開発計画

## 合意内容

- ブランチ: `fix/v0.37-browser-interaction`
- 予定バージョン: `0.37.0`。実装開始時に `package.json` と `package-lock.json` を更新する。
- 対象バックログ: 「ピンチ・ダブルタップによるブラウザー標準の拡大・縮小を無効にする」「タイトル・ゲーム終了画面のフォーカス制御を共通方針に合わせる」。
- オーナー合意: 効果選択UIはスコープから外し、ズーム抑止とタイトル・終了画面のフォーカス制御を扱う。タイトルのポータルリンクも含む。
- 実装中の追加合意: 常用サーバーでバージョン定数が古いまま配信されることを受け、package.jsonを直接参照するバージョン取得の修正を含める。共通Env Utilityの利用を維持し、ゲーム本体と開発者画面に反映する。Vite設定とサーバー起動状態は変更しない。
- 追加合意: 「正式版・仮版の共通公開へ移行する」を本ブランチ・v0.37.0へ追加する。今回の修正を`/MyPalette/preview/`へ公開してiPad SafariのMP37-01〜03を確認できるようにする。この追加に伴うVite base設定の変更を含む。常用サーバーを手動で停止・再起動・置換しない。
- オーナーの検証方針の追加合意: 一般的なズーム抑止を実装し、Safari等の仕様に照らして妥当性を確認する。ほぼ抑止できるが特定条件で抑止できない可能性について、完全な非再現の保証を完了条件にしない。ブラウザー側の問題の可能性もあるため、一般的な実装の妥当性を確認できた後は例外条件を深追いせず、残る不確実性を制約として記録する。WebKit起因とは断定しない。

## 現状と目的

`index.html` は倍率制限付きviewportを指定しているが、iPad Safariでピンチ・ダブルタップによるブラウザー標準ズームが発生するとの報告がある。`touch-action` はダイスや一部ボタン等に指定されている。ゲーム本体のタイトル・プレイ中・終了画面でブラウザー標準ズームを抑止し、既存のゲーム操作を維持する。

`src/ui/createTitleScreen.js` のメニューボタンとポータルリンク、`src/main.js` の終了画面の戻るボタンはTab移動から除外されていない。タイトル部品には任意の設定ボタン生成経路もある。`src/main.js` はゲーム終了時とタイトル復帰時に明示的な `focus()` を呼ぶ。これらを共通の不要なフォーカス移動を発生させない方針に合わせる。

## スコープ

1. ゲーム本体のタイトル・プレイ中・ゲーム終了画面で、ピンチおよびダブルタップによるブラウザー標準ズームを抑止する。
2. タイトルのメニューボタン、ポータルリンク、設定ボタン生成経路と、終了画面の「タイトルへ戻る」をTab・Shift+Tabによる順次移動から外す。
3. ゲーム終了時・タイトル復帰時の不要な明示的フォーカス移動をなくす。
4. 対応する実装仕様・検証手順を更新する。必要なオーナー検証を実装中に提示し、判断と対応を記録する。
5. 公開済みGameWorksOAK masterの共通公開ワークフローへ移行し、`DEPLOY_BASE_PATH`をVite baseへ反映する。標準JSONの画像・ロゴ・プレイ先を公開ルート相対パスへ揃える。
6. 開発ブランチをpreviewへ公開し、素材・カード設定・標準JSON・バージョンとポータルの`preview=on`連携を確認する。正式版との相互保持を確認し、今回のSafari実機検証先を提示する。

## 対象外

- 効果の対象選択UIのチェックボックス、標準dialogのフォーカス制御や独自UIへの置換。各EUI項目と「ブラウザー標準モーダルを独自UIへ置換する」で扱う。
- ズーム抑止の回帰確認で既存の効果選択・カード詳細の操作維持は確認するが、選択UIの設計・表示・フォーカス処理は変更しない。
- 開発者画面の入力・フォーカス・ズーム操作の変更。
- PCのブラウザーメニューやキーボードによるズーム制御。
- MP28-02の原因調査、描画負荷改善、着手ボタン追従、上記追加合意以外のバックログ。
- GameWorksOAK共通部およびオーナー管理の要求仕様の編集。

## 完了条件

1. タイトル・プレイ中・終了画面に、Safari等の仕様から見て妥当な一般的なピンチ／ダブルタップズーム抑止を適用し、適用範囲と通常操作の維持を検証する。特定条件の例外が残る可能性は明記し、Safari実機で例外が一切起きないことの保証は求めない。
2. 単発・連続タップ、開始・終了・タイトル復帰・再開始、ポータルリンクのタップ操作が維持される。
3. ダイスの選択・ドラッグ、カード詳細の開閉、必要な内部スクロール、サイドパネルの開閉が維持される。画面回転・A/B切替後も操作できる。
4. タイトルの全メニュー項目・ポータルリンク・設定ボタン生成経路と終了画面の戻るボタンがTab移動の対象にならず、終了・復帰時にボタンへの明示的なフォーカス移動が発生しない。
5. 対象検証・全テスト・本番ビルドを実施し、コマンドと結果を実装報告に記録する。必要なオーナー検証の判断・対応・明示的な保留を記録する。実機未確認を自動検証だけで確認済みとは扱わない。
6. master pushは正式版、開発ブランチの手動実行はpreviewを公開し、公開先の任意入力を設けない。正式版・previewの相互保持と公開URLでの読込を確認する。正式版の更新は既存のレビュー・マージ承認手順に従い、それまでは未実施と記録する。
7. previewのゲーム本体・開発者画面に確認対象バージョンを表示し、標準JSON・画像・ロゴ・プレイ先・空の更新履歴がpreviewから取得できる。ポータルの`preview=on`でpreviewを参照できる。最終実装版はフィードバック修正後のv0.37.1とする。

## 実装方針

- ゲーム本体に適用範囲を限定し、既存のviewport設定とCSSによる入力制御を確認してから、必要なイベント抑止を追加する。
- 必要な内部スクロールを維持する。全タッチイベントの一律キャンセルは避け、ピンチ・ダブルタップと通常操作を分ける。追加したイベントの登録先・ライフサイクルを明確にする。
- タイトル部品と終了画面の生成時に順次フォーカスの対象を制御し、`src/main.js` の不要な `focus()` を除去する。全画面のキーイベントを一律に遮断する実装にはしない。
- 実装仕様は `docs/spec/09.playable_game.md`、検証手順は `docs/01.development.md` の該当箇所を必要に応じて更新する。
- バックログの対象項目の削除はレビューの承認手順に従う。
- `.github/workflows/deploy.yml`を共通公開呼出しへ切り替える。共通部のブランチ・HEAD・remote master・src/libの差分を確認する。共通部自体は編集しない。
- preview公開用の途中コミット・開発ブランチpush・workflow_dispatchは実機確認のために行い、フェーズ完了やmasterへのマージと区別する。引継ぎ書は実装のまま維持する。

## 検証方針

- 入力判定・イベント制御にロジックを設ける場合は、複数タッチ、単発タップ、連続タップ、スクロール後のタップ、解除・再登録など、実際に壊れうる境界を対象とするテストを先に作る。
- ブラウザー検証はタイトルの1・2・3項目、ポータルリンク、設定ボタン生成経路、ゲーム終了・復帰時の `document.activeElement` とTab／Shift+Tabの挙動を確認する。
- 既存の `scripts/checkTitleMenu.cjs`、`scripts/checkProductionStartup.cjs`、カード詳細・ダイス操作の検証から関連する経路を使い、A/B・短い画面・動きを減らす設定で回帰を確認する。必要な追加スクリプトは `scripts/` に置く。
- 合成イベントのキャンセルやPCのモバイル相当表示だけでは、Safariの実際のズーム抑止を証明したことにしない。
- 一般的な抑止実装・仕様上の根拠・検証結果と、実機の特定条件の不確実性を分けて記録する。後者を解消するための追加計測や、通常操作を変える防御処理を一律に追加しない。特定条件の原因追究は今回の完了に必須としない。
- 全テスト: `npm.cmd test`。本番ビルド: `npm.cmd run build`。
- `DEPLOY_BASE_PATH=/MyPalette/preview/`でもビルドし、共通公開検証とゲーム・開発者画面の起動を確認する。Actionsの対象コミット・共通処理・共通checkout・配置先・成否を記録し、既存正式版のindexと素材がpreview公開後も保持されることを確認する。逆方向は正式版の更新が承認されるまで未実施とする。
- 常用の開発サーバー `http://127.0.0.1:3000/MyPalette/` を停止・再起動・置換しない。バージョン更新が画面へ反映されない場合はオーナーに報告する。
