## REV-DISCARD-01: 動きを減らす設定でイーゼルとカードの最終配置を確定する（P1）

### 場所と原因

`src/game/cardSceneTimeline.js:204-206` の `enabled && changed` により、`prefers-reduced-motion: reduce`では通常の所属変更に対してタイムラインを実行せず、カードの表示スナップショットだけを採用する。一方、`src/game/playPresentation.js:121-132` は新しいイーゼルを画面右外に生成し、枚数が変わると `motion = true` にする。最終配置へ進める `play.sample(1)` / `play.finish()` は `cards.move()` 経由でのみ実行されるため、この経路では画面外の姿勢が残る。`play.update()`もmotion中は配置を更新しない。

### 再現と実測

1. Edgeの新しいブラウザーコンテキスト、1200×800、`reducedMotion: 'reduce'`を使用する。
2. 保存済みcards.jsonを読み取り、検証ページ内だけで各ステップのプレイ時・達成時効果を空にする。保存済みファイルは変更しない。
3. 既存のcreateLayoutScreen・createLayoutPresentation・mountGameで起動し、「今日の仕事を始める」を押す。ゲームがplay、cards.busyがfalseになるまで待つ。
4. 手札の最初の着手ボタンを押し、1200ms待つ。
5. ゲームのfieldは1枚、cards.busyはfalseだが、制作中カードの左端は `1247.103515625px`、イーゼルのtransformは `translate(1240px, 133.333px) scale(0.5625)`。幅1200pxの画面右外に残り、作品を画面上で確認できない。

一時スクリプト `node tmp_review_reduced.cjs` で上記を再現した。サンドボックス内のEdge起動が終了したため、通常環境で同じスクリプトを実行して実測した。一時スクリプトはレビュー後に削除し、再現条件と実測を本報告へ保存した。

### 期待結果と必要な確認

動きを減らす場合も、カードとイーゼルを同じ個体のまま最終配置へ即時反映する。新しい着手だけでなく、制作中の増減・再配置、達成・出荷後の撤去、日末回収でも画面外の初期姿勢や古いイーゼルが残らないこと。待機が必要な再構成の即時再開も維持する。

reduceのまま初日開始→複数着手→達成→日末まで操作するブラウザー回帰検証を追加する。カードの個体数だけでなく、制作中カード・イーゼルが最終位置にあり、撤去対象が画面外へ確定することも確認する。実装再開時は共通規約に従い0.22.1へ更新する。

既存のcheckCardScene.cjsはreduceで起動するが、最初の着手前にno-preferenceへ切り替える。checkCardSceneLimits.cjsも着手前に切り替えており、この不具合は既存の成功結果では検証されていない。
