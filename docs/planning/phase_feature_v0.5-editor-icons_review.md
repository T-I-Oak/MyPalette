## v0.5.12 で記録した指摘

### REV-01 [P2] 評価設定の保存競合から編集内容を保持したまま復旧できない

- 対象: `src/editor.js` の保存処理、`scripts/cardSettingsPlugin.js` のリビジョン照合。
- カード設定の保存が成功した後、評価設定が他の画面で更新されていると、評価設定のPUTは409になる。カード設定と評価設定の更新は別ファイル・別リビジョンなので、一方だけ競合する状態が成立する。
- 失敗時には評価設定のリビジョンを更新する操作がなく、再度保存しても同じ `If-Match` を送る。カード設定の書き込みを先に再実行する一方で、評価設定は同じ競合で失敗する。ページ再読込みでは保持していた未保存の評価入力が失われる。
- サーバーテストで古いリビジョンの拒否を再確認し、クライアントの再試行経路をコードで照合した。二画面のブラウザー再現は行っていない。
- 競合を検出したら、既に保存されたカードと未保存の評価設定を区別し、評価の入力を保持したまま最新の評価設定と照合して保存を再開できる手段を用意する。競合先の変更は無断で上書きしない。

### REV-02 [P2] バックログに完了済みの優先作業と削除予定の参照が残る

- 対象: `docs/planning/backlog.md` の「優先作業：開発起動とカード情報のアイコン表示」。
- 対象機能は実装され、オーナー検証の判断も記録済みだが、バックログは今後の作業として表示したまま。マージ前に削除する `phase_` の実装報告も参照している。このままマージすると次回の計画で作業の優先順を誤認し、参照先も失われる。
