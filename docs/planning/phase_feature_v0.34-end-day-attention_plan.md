# v0.34 日末ボタンの注目表示

## 合意した開発内容

- 対象バックログ: 「『今日の仕事を終える』ボタンに状況に応じて注目属性を付ける」。
- 予定バージョン: v0.34.0。実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- ブランチ: feature/v0.34-end-day-attention。
- オーナーは2026-11-22に下記条件を指定し、同日中の解除処理は不要、翌日・新規ゲーム開始時にリセットする方針を含めて開発内容へ合意した。

## スコープと条件

「今日の仕事を終える」ボタンへ既存のstate-attentionを付与する。条件は次の論理式とする。

```text
（手札が1枚 または
 （手札に達成可能なカードが存在しない かつ
   手札にプレイ時効果を持つカードが存在しない））
かつ リロール権が0
```

- 達成可否は現在ステップの目標と未使用ダイスを使う既存のmatchingDice判定に合わせる。
- プレイ時効果の有無は現在ステップの定義で判定する。効果の対象がない等の理由で処理結果が変わらなくても、効果を持つものとして扱う。
- 制作中のカードの達成可否は条件に加えない。オーナー指定の具体条件を用い、全操作の可否を探索する機能へ拡張しない。
- プレイ操作が可能な状態で条件成立時に付与する。効果選択・通知・演出・ロール等の操作待機中には注目表示を出さない。
- 同日中の条件不成立への復活を扱う専用処理は設けない。翌日および新規ゲーム開始時に前日の注目状態をリセットする。初日開始前・日末・ゲーム終了時にも注目表示を残さない。
- 見た目は既存のstate-attentionを再利用し、位置・配色を変えない。

## 対象外

- 日末処理、プレイ・リロール・達成のルールや操作可否の変更。
- 他ボタンや他のバックログ項目への対応。
- 共通ライブラリの変更、要求仕様の変更。

## 完了条件

1. 手札1枚では達成可否・プレイ時効果の有無にかかわらず、リロール権0なら注目表示する。
2. 手札2枚以上では、達成可能なカードもプレイ時効果を持つカードもなく、リロール権0の場合だけ注目表示する。
3. リロール権が残る場合は注目表示しない。制作中のカードの達成可否によって判定を変えない。
4. 操作可能になった時点で条件を反映し、待機中や日末に不要な注目表示を出さない。翌日・新規ゲームに状態を持ち越さない。
5. レイアウトA/Bで既存の注目表示が適用され、動きを減らす設定では拡縮を停止する。通常の日末・翌日・再開始操作を維持する。
6. 関連実装仕様を更新し、対象テスト・全テスト・本番ビルドの結果を実装報告へ記録する。

## 実装・検証方針

- src/game/view.jsの日末ボタン生成と操作待機判定を起点とする。必要に応じて条件判定を小さな関数へ分離し、既存のゲーム状態・目標判定を利用する。
- 条件の組み合わせを先にテストで定義する。手札枚数、達成可否、現在ステップのプレイ時効果、リロール権、制作中カードに依存しない点を確認する。
- ブラウザーでは条件成立前後、待機中、日末、翌日、新規ゲームのボタン状態を確認する。A/Bと動きを減らす設定も確認する。
- 実装のまとまりごとに確認可能な状態と操作手順を提示する。オーナー検証には固定IDと確認バージョンを付け、判断・フィードバックを実装報告へ記録する。
- 実装終了草案の提示前にnpm.cmd testとnpm.cmd run buildを実行する。
