# ダイスコンポーネント開発計画

## 合意した開発内容

- ブランチ: `feature/v0.4-dice`
- 予定バージョン: `0.4.0`。実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- ゲームで使用するダイスを、単体とダイス群のクラスとして設計・実装する。
- 既存の確認用ゲーム画面の拡張ではなく、独立したコンポーネントと専用の動作確認画面を作る。
- ダイスの仕様設計、3D表示、物理ロール、通常面と特殊面に必要なアイコン、結果表示演出を対象とする。

## 対象外

- 既存ゲームへの組込み、ゲーム進行・効果処理・カード設定の変更。
- パレット、カード、キャンバス、イーゼルと、ゲーム画面全体の構成。
- 特殊面の表示に必要な範囲を超える効果アイコンの実装。
- ランキング、アチーブメント、ギャラリー、公開設定。

## ダイスの仕様設計

実装フェーズで `docs/spec/10.dice_component.md` を作成し、次を定める。

- ダイス単体クラスの生成、ID、6面定義、永続・一時、表示位置、面変更、ロール、結果取得、破棄の契約。
- ダイス群クラスの追加・削除・参照、対象指定、複数の同時ロール、全対象停止後の結果取得の契約。
- ロール前の空中回転、物理ロール中、停止・出目確定、結果の出現・浮遊の状態と遷移。
- 同時ロール中の再操作、対象外ダイス、消費状態、削除・破棄時の扱い。
- 物理空間、床・境界、ダイス間の衝突、停止判定、傾いて止まる場合の扱い。
- 上面の判定と面インデックスの対応。見えている上面と返却する出目を一致させる。
- 各ダイスの結果通知と、群全体の完了通知のタイミング。
- カメラ、照明、表示寸法、配置の揺らぎ、結果グラフィックの追従と重なりへの対応。
- 描画・物理ライブラリの選定理由、依存関係、実行ループとリソースの所有・解放。

既存の面データ `{ color, material }` / `{ special }` と
`permanent` / `temporary` の識別子を利用する。既存Gameの乱数処理を今回のコンポーネントへ置換しない。
物理ロール結果を将来ゲームへ渡せるAPIとし、ゲームのルール判定を表示クラスへ持ち込まない。

## 通常面の表示

面の中央には大きな画材記号と色文字を表示する。

| 項目 | 表示 |
| --- | --- |
| 絵筆 | 先端の尖ったしずく形 |
| パステル | 角丸平行四辺形 |
| エアブラシ | 3つの丸がつながった雲形 |
| 色文字 | 橙O、黄Y、緑G、青B、紫P、赤R |
| 永続ダイス | 出目の色で記号を塗り、内部に白抜き文字 |
| 一時ダイス | 白い記号に出目の色の縁取り、内部に出目の色の文字 |

- 3画材×6色を永続・一時それぞれで確認する。
- 特に黄色の視認性を実際の表示サイズで確認し、色調、線幅、文字の補助表現をオーナーと調整する。
- 永続・一時の配色差は実際の通常面の表現であり、一時ダイスを獲得する効果アイコンの雲状補助記号とは区別する。

## 結果グラフィック

- `public/assets/dice/` の既存素材を使用する。素材そのものは保持する。
- 各画材の `*_grayscale.png` を出目の色で着色し、同位置・同サイズに `*_fixed.png` を重ねる。
- 持ち手、金具、巻き紙などの固定部分は元の色を保ち、画材の質感と透過を維持する。
- ロール前・ロール中は結果グラフィックを表示しない。
- 出目確定後、対応する画材グラフィックがサイコロからふわっと飛び出す。
- 出現後はダイスの上でゆっくり上下に浮遊し、各ダイスの位置に追従する。
- 再ロール開始時は以前の結果を消し、新しい結果の確定後に再度出現する。
- 面変更時も面と結果表示が一致するようにする。
- 特殊面の結果グラフィックは実装時の仕様設計で定め、確認画面で提示する。

## 特殊面と効果アイコン

`src/effectCatalog.js` のSPECIAL_FACESとSPECIAL_FACE_EFFECTSを正本として、10種類を扱う。

- 名声＋1、カードドロー＋1、リロール権獲得。
- 通常構成の一時ダイス獲得。
- 補色指定の一時ダイス獲得3種。
- 画材指定の一時ダイス獲得3種。

月桂冠、手札・矢印、リロール・チケット、六角形・Y字、補色領域と色文字、
画材記号、一時獲得の雲状補助記号など、これらに必要な共通部品を実装する。
構成と数値表記は効果共通仕様と各効果仕様に従う。
特殊面の中央には効果アイコンを表示し、発動タイミングは含めない。
具体的な効果アイコンに特殊面全体を表す星型を追加しない。

## 動作確認画面

- 同じダイスクラスとダイス群クラスを使用し、専用画面のための別実装にしない。
- 単体・全体・選択した複数をロールできる。ロール開始ボタンは「使う画材を決める」とする。
- 各6面、通常面18組、永続・一時、特殊面10種類、面変更、追加・削除を確認できる。
- 出目とIDを確認でき、表示上面と返却結果を照合できる。
- アイコン一覧で色・画材・所持期間を比較でき、黄色の調整を判断できる。
- PC、タブレット、スマートフォン相当の画面で、ダイスと結果表示、操作部を確認できる。
- 確認画面への入口と操作方法を文書に記載する。

## 文書とバックログ

- 要求仕様（`docs/requirements/`）を変更する前に、対象ファイル・該当箇所・修正前後の内容・変更理由をオーナーへ提示し、明示的な修正許可を得る。許可された内容だけを反映する。
- 今回の表示方針や計画への合意を、要求仕様の修正許可とは扱わない。許可前は要求仕様を変更しない。
- 中央の記号表示、浮遊する画材画像、永続・一時の配色について、上記の手順で要求仕様の修正案を提示する。
- `02.visual.md`、`04.effect_conventions.md`、`05.icon_presentation.md` の関連記述を整合させる。
- 要求仕様の変更は今回合意したダイス表示に限定する。
- バックログから完了済みの「ゲームの評価」を削除する。
- UI実装の項目は、今回のダイスと残る作業の境界を明記し、完了した作業を未完了として残さない。
- 共通リポジトリは参照専用とする。

## 実装・テスト方針

- 描画、物理処理、面・効果アイコン、画像合成を責務に応じて分離し、同じ記号は共通化する。
- 1ファイル500行以内、CSSの機能・質感・状態の分離、モバイル操作の共通規約に従う。
- 状態遷移、上面判定、群の完了管理などの複雑なロジックは、テストを先に作る。
- 単体テストで面と上面の対応、面変更、対象指定、同時ロールの結果対応・完了、破棄を確認する。
- 描画・物理処理はブラウザ上でも確認する。衝突、停止、繰り返しロール、画面サイズ変更、削除を含める。
- ロール中の旧結果の非表示、確定後の出現・浮遊、素材の合成と6色の視認性を目視確認する。
- 不安定なタイミング依存テストを避け、実際の物理・描画の確認と制御可能なロジックの検証を組み合わせる。
- 対象テストに加え、終了草案前に `npm.cmd test` と `npm.cmd run build` を実行し、結果を実装報告へ記録する。

## 完了条件とオーナー検証

- ダイス単体と群の契約が文書化され、そのクラスを使って3D表示と物理ロールを実行できる。
- 単体・複数のロールで、停止した上面と取得結果が一致し、各IDで結果を識別できる。
- 繰り返しロール、対象外の保持、面変更、追加・削除で表示と状態が整合する。
- 通常面18組と特殊面10種類を表示でき、必要なアイコンが共通部品で構成される。
- 通常面の永続・一時を判別でき、結果グラフィックの出現と浮遊が合意した流れになっている。
- 削除・画面離脱時に描画・物理処理とリソースが解放される。
- 全テストと本番ビルドの結果、ブラウザ検証の条件と結果を記録する。
- オーナーには一意のID・操作手順・期待結果・確認バージョンを付け、通常面の視認性、特殊面、ロール、結果演出を個別に提示する。
- 黄色を含む配色調整と特殊面の結果表示は、確認できる実装を提示して判断を得る。
- 未回答・未対応を残して終了草案を提示しない。明示的に保留された検証のみバックログへ記録する。

## 追加合意: 面構成の条件検索

オーナーの「その機能を入れてもらえませんか？ 条件は画材、色、画材＋色です」に基づき、このブランチ内で追加する。

- 対象は所持ダイスの6面構成。画材、色、同一面の画材＋色で一致する面を数える。
- 固定ID `dice-search-notice` のDOM要素に条件アイコンと一致するダイスの個数を表示し、0件も必ず通知する。
- 固定位置の通知もダイス上の表示と同じ3秒間とし、共通i18nを使って文言・条件名を翻訳する。
- 固定通知・ダイス上の個別表示は共通の透明度でフェードイン・フェードアウトする。
- 一致するダイスには条件アイコンと「×面数」を約3秒重ねる。分母は表示しない。
- 同じ条件を再指定した場合も再表示する。0面のダイスには重ね表示しない。
- 現在の出目、対象選択、消費状態と独立した検索にする。
- 面変更・追加・削除時には有効な検索条件の件数を更新する。
- ゲームの目標選択との接続は既存ゲームへの組込み時に扱い、今回はAPIと専用確認画面を対象にする。

## 追加合意: カード用の共通アイコン

オーナーが提示範囲に `ok` と回答したため、このブランチに追加する。
従来の「特殊面に必要な範囲を超える効果アイコンは対象外」を、この追加範囲について解除する。

- 効果15種類、画材・色・画材＋色の目標アイコン、数量・永続/一時・変更先のバリエーション。
- ダイスとカードが同じ描画部品を使用するゲーム共通モジュール。
- 独立した確認画面と実装仕様。新しいデザインは1件ずつオーナーレビューを受ける。
- カード全体のレイアウトと既存ゲームへのアイコン組込みは対象外のまま。
- 要求仕様を変更せず、効果共通・ダイス効果・その他効果・アイコン表示の既存要求に従う。

## 追加合意: パレット画像を使うロールフィールド

提供された画像をロール面に使う。ゲーム全体のパレットUIへの組込みは引き続き対象外。
最初は中央の木地に限定したが、オーナーの追加指示により絵の具の領域も利用可能とし、穴・外縁を避ける範囲へ拡大する。
描画、物理境界、生成、位置指定、ロール中の制限を同じ領域定義に揃える。
