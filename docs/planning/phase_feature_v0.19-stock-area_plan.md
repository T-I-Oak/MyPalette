# ストックエリアの正式UI実装計画

## 合意内容

- 予定バージョン: `0.19.0`。実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- 開発ブランチ: `feature/v0.19-stock-area`。
- バックログの順序に従い、今回はストック1エリアを正式化する。
- 表示・配置・操作・演出の具体案は未確定とする。実装時にオーナーと相談し、小さな単位で提案・確認・フィードバック反映を行う。完成後の一括確認にはしない。

## 現状と参照

手札・プレイ・パレットは正式化済み。ストックは既存カード表示を仮エリアへ配置している。既存のゲーム処理は公開カード取得、取得直後の公開補充、手札交換での返却、日末の公開カード更新に対応している。これらを再利用する。

- [バックログ](backlog.md)
- [ゲーム基本ルール](../requirements/01.game_rules.md): ストックのリフレッシュ、ストック取得の共通ルール、チラシと発注。
- [ビジュアル要求](../requirements/02.visual.md)
- [情報と操作の要求](../requirements/03.information_and_interaction.md): グレード別ストック、ストックからのカード取得。
- [ゲーム実装仕様](../spec/09.playable_game.md)
- [エリア間移動](../spec/13.area_transition.md)
- [画面レイアウト](../spec/14.screen_layout.md)
- 共通のフェーズ作業手順、コーディング・CSS・モバイル規約を適用する。GameWorksOAKは参照専用とする。

## スコープ

- レイアウトA/Bのストック仮表示を正式UIへ置き換える。
- グレードA・B・C、公開カード、残り枚数、空状態を表示し、公開カードの詳細を確認できるようにする。
- チラシによる自動発注の公開カード選択・取得と、取得直後の公開補充を既存ゲーム状態・操作に接続する。
- カード効果による取得、手札交換の返却・取得、日末のストック更新でも正式ストック表示を正しく更新する。
- ストック内の公開・裏返し・補充と、正式化済みの手札とのカード移動を扱う。見せ方・タイミング・操作方法は実装時の相談で決める。
- 対応する実装仕様・開発案内を更新する。要求仕様は許可なく変更しない。

## 対象外

- デッキ・捨て札・情報表示エリアの正式化。
- 移動元または移動先が仮エリアである移動演出。状態と表示の更新は正しく行う。
- 効果別UIの全面的な正式化。既存のストック取得・交換処理は接続するが、EUI-13・EUI-15全体の完了とは扱わない。
- 目標アイコンのホバー改善、ダイス長押し情報、既存のTab移動チェックの整合。
- ゲームルール変更、共通部変更、公開設定。

## 実装方針

1. 実装開始時にバージョンを更新し、既存のCard・ストック処理・エリア描画契約を確認する。
2. 表示・配置・詳細確認の具体案を提示し、オーナーと相談して最初の確認単位を決める。
3. 小さな単位で確認可能な実装を作り、操作手順・期待結果・確認バージョンを示す。判断と対応を実装報告へ記録し、確認を得てから次のまとまりへ進む。
4. 発注・補充・日末更新・手札との移動についても、具体的な操作・演出を事前に相談して同様に進める。
5. エリアから渡される描画寸法と共通座標変換を使用する。二重表示、演出中の操作競合、表示更新での演出再始動を防ぐ。

## 完了条件

- レイアウトA/Bでグレード別の公開カード・残り枚数・空状態を識別でき、公開カードの詳細を確認できる。
- 自動発注時に取得可能な公開カードを選択でき、取得・補充・返却・日末更新が実際のゲーム状態と一致する。空ストックと全ストック空でも進行が停止しない。
- 合意したストック内演出および手札との移動演出が動作し、二重表示や操作競合がない。
- リサイズ、A/B切り替え、Bパネル開閉、固定倍率変更、画面外への移動、動きを減らす設定に対応する。
- 必要なオーナー検証の判断とフィードバック対応が記録されている。未回答を保留として扱わない。
- 対象テスト・全テスト・本番ビルドを実行し、結果を実装報告へ記録する。失敗時は共通手順に従って原因と扱いを明記する。

## テスト方針

- 複雑な配置計算・状態管理・イベント連鎖を追加する場合は、先にテストで挙動を定義する。
- 既存のゲーム進行・効果・カード移動テストを活用し、変更に対応する対象テストを実施する。取得後の補充、空状態、返却、連続取得、日末更新の接続を確認する。
- ブラウザーで公開カードの詳細・発注選択・補充・移動を確認する。A/B、狭い画面、リサイズ、パネル開閉、固定倍率、動きを減らす設定を検証する。
- 正式化済み手札・プレイ・パレットと既存の取得・交換処理への回帰を確認する。
- 終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行する。
