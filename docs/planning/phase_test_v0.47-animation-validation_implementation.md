## 実装

### 到着前に表示される［着手］の是正

`handPresentation.follow()`は表示用スナップショットの手札IDだけで操作要素を残していた。ドロー開始時に表示用手札は到着先の内容になるため、ゲーム状態だけでなく表示用手札を基準にしても到着前表示を防げなかった。

既存のCardSceneStateの各カードの現在所属を参照し、`record.area !== 'hand'`の操作要素をhiddenで隠す。既存のflex指定がhiddenを上書きしないよう手札操作層にCSSを追加した。描画後処理で各カードの到着と同じフレームに表示する。移動時間・行列の近似比較・演出全体の完了待ちには依存しない。ストックからの取得も同じ判定になる。

着手で離れるカードは表示用手札から外れた時点で操作要素を撤去する既存処理を維持。到着済み・残る手札の追従と、演出全体のinertによる操作遮断を維持した。

### 検証の追加・整備

- `checkHandActionFollow.cjs`: 日次4枚、効果2枚、山札残数1枚での効果ドローを区別。待機・飛行・個別到着をカードIDとフレームで記録し、到着前非表示・到着後表示・到着姿勢・inertを確認。最後のカードは演出終了フレームに到着するため、操作可能状態で全手札の可視ボタン数とinert解除も確認する。
- `checkCardScene.cjs`: 毎フレームの姿勢の有限性・実カードのinert、待機復帰時の全45枚の到着行列・表裏・所属・移動層の撤去・動作所有者の解放を追加。
- 同スクリプトの`MYPALETTE_SCENE_LAYOUT_STRESS=1`: 各演出名を最初に観測した後、画面幅390px／全幅、高さ700／390px、固定倍率0.65／1.2、パネル開閉を交互に変更。画面外から入るイーゼルはそのフレームの幅で確認。配置固定を前提とするカンバス演出中のイーゼル不動確認は通常実行で維持し、配置変更時は支持面一致と最終姿勢を確認する。
- `checkBoardMotion.cjs`とボード確認ページ: 表示だけの合成シナリオでゲームの操作欄が古い手札を保持し、リサイズ時に存在しない操作要素を参照する検証側の問題を修正。合成シナリオ前に`presentation.clear()`で操作欄を外し、実カード45枚の同一性は維持する。通常ゲームのソースへ例外回避処理は追加しない。
- 手札確認ページの説明と実装仕様・開発手順を到着後表示へ更新。

### 全テストの既存サーバーテストの制限

`tests/implementation/devServer.test.js`はViteで別サーバーを作り、実行時は5173番へのfetchが`EACCES`となった。finallyでserver.closeを行い終了した。今回の手札・演出変更と無関係な既存テストであり、常用3000番を保護し追加サーバーを起動しない合意に従って、権限を上げた再実行やテストの書き換えは行わない。全件成功とは扱わない。

再確認ではNodeの`--test-skip-pattern`にこのテスト名を渡し、追加サーバーを必要としない対象を実行した。ログに当該テストの実行結果がないことを確認。初回の無除外実行の失敗はそのまま記録する。
