# 計画書：v0.40 定期見直し

- 対象ブランチ：review/v0.40-periodic-review
- 予定バージョン：v0.40.0
- 根拠：共通ワークフローガイド「定期見直し」（新規開発で Minor の下1桁が 0 になるとき、その版は文書とソースの見直しだけにする）

## 開発スコープ

共通ワークフローガイドの5観点で点検する。

1. **開発ルール**：共通ルール（GameWorksOAK の docs/common）とプロジェクト固有の規定（docs/01.development.md 等）を読み直し、食い違いを確認する。
2. **文書**：docs/spec の11件、docs/requirements、docs/01.development.md について、現在存在しない仕様・章構成・参照先を確認する。文書の分割は共通の文書ガイドに従う。
3. **テスト**：tests/spec・tests/implementation と文書の挙動を照合する。ソースを分割・移動した場合は、テストの責務と配置の対応も見直す。
4. **ソース**：src 配下について、未使用コード、文書との整合性、ファイルサイズを点検する。コーディング基準は共通のコーディングガイドに従う。
5. **バックログ**：docs/planning/backlog.md について、オーナー検証が利用者が操作・確認できる単位で1件ずつ判定できることと、要望・バグ指摘の依存関係・優先順を確認する。

## 対象外

- 新規機能・仕様変更の実装（バックログ項目の実施は含まない）
- 見直しの範囲に入らない不具合の修正
- UIの見た目の調整
- 公開準備（2026年12月に別途実施する）

## 指摘の扱い

- バグ：修正せず、backlog.md の「要望・バグ指摘」へ記録する。
- 文書の不整合：修正案をチャットで提示し、オーナーの OK が出たら修正する。
- ソース構成の指摘：修正するかバックログへ記録するかを個別に提案し、オーナーの判断に従う。

## 実装・テスト方針

- 実装フェーズ開始時に、バージョン設定（package.json・package-lock.json）を 0.40.0 へ更新する。
- 点検範囲と修正内容は実装報告（phase_review_v0.40-periodic-review_implementation.md）へ記録する。
- 実装フェーズの承認草案を表示する前に、全テスト（`npm test`）と本番ビルド（`npm run build`）を実行し、コマンドと結果を実装報告へ記録する。
- 見直しブランチでは新規機能や仕様変更を混ぜない。

## 完了条件

- 5観点の点検と、合意した範囲内の修正が完了している。
- 全テストと本番ビルドの結果が実装報告に記録されている。
- レビューフェーズで未解決の指摘がないことが確認され、承認を得て master へマージし、push の反映（`git rev-parse master` と `git ls-remote origin refs/heads/master` の一致）を確認する。
