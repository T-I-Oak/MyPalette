# リロール権と操作の表示改善 計画

## 合意内容

- 開発ブランチ: `feature/v0.33-reroll-display`
- 予定バージョン: `0.33.0`。初回の実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- 解決する問題: 権利表示と操作の関連性が分かりづらい、操作による権利の消費に気づきづらい、達成可能な状況で誤ってリロールするリスクがある。

## 開発スコープ

1. リロール権の表示を2つのリロールボタンの左側へ移す。
2. 各ボタンに「リロール権＋斜線」のような消費を示すアイコンを付ける。
3. ボタン文言を「すべてリロール」「1つリロール」とする。選択状態による1ボタンへの統合はせず、2つの選択肢を常時表示する。
4. いずれかのカードが達成可能な状態で権利によるリロールを実行しようとした場合、「達成可能なカードがあります」という確認ダイアログを出す。「戻る」「リロールする」を選択でき、実行を選んだ後に権利を消費する。
5. 関連する実装仕様と検証を更新する。要求仕様は変更しない。

## 配置の仮決めと相談方針

権利表示、消費アイコン付きの「すべてリロール」「1つリロール」を横1行に配置する案を仮決めとする。特にレイアウトBは幅が厳しく、2段にする高さもない。実寸での配置調整は実装時に行う。

レイアウトBを重点確認し、幅・高さ・読みやすさ・押しやすさに問題がある場合は、具体的な問題と確認可能な状態を提示してオーナーへ相談する。独断で1ボタンへ統合したり、2段化したり、文言を「更新」へ戻したりしない。配置の成立を計画時点で保証した扱いにしない。

## 対象外

- リロールのゲームルール、対象条件、消費数の変更。
- 効果による即時リロールのUI変更・警告追加。
- 効果獲得演出の正式化、その他のバックログ項目。
- GameWorksOAK共通部の変更。

## 完了条件

- リロール権の残数がボタン左側で確認でき、獲得・消費・日末処理に追従する。
- 2つの操作が常時識別でき、消費アイコンを含めて権利と操作の関係を確認できる。
- 達成可能なカードがあると確認が出る。戻る場合はゲーム状態と権利を変更せず、実行を選んだ場合だけ既存のリロールを1回実行する。
- 達成可能なカードがない場合は従来どおり実行できる。無効条件や対象選択、権利消費数を維持する。
- 確認の連打やダイアログ開閉による二重実行を防ぐ。実行時も現在の操作可能条件を確認する。
- A/B、狭い画面、リサイズ、固定倍率変更で表示と操作を確認し、配置上の問題はオーナーと調整する。
- 実装途中で表示・消費アイコン・確認操作をオーナーへ提示し、判断と対応を記録する。
- 対象テスト、全テスト、本番ビルドの結果を実装報告へ記録する。

## 実装方針

- `src/game/palettePresentation.js`と`palette.css`を中心に、既存の固定倍率層の操作領域を改修する。リロール権の既存アイコン描画を再利用し、消費表示を追加する。
- `src/game/view.js`の権利リロール操作へ確認を接続する。達成可能判定は既存の手札・プレイエリア表示に使う判定を調査・再利用し、別のルールを作らない。
- ゲームエンジンの権利消費・ロール要求を再利用する。効果による即時リロールとは区別する。
- ダイアログは共通UI・フォーカス方針に従い、不要なフォーカス移動を追加しない。
- 関連仕様は`docs/spec/09.playable_game.md`、必要に応じて`14.screen_layout.md`等へ反映する。

## 検証方針

- 条件分岐と確認後の実行制御は、既存テストを調査し、複雑なロジックについて実装前にテストで挙動を定義する。
- 達成可能あり／なし、すべて／1つ、戻る／実行、無効条件、二重実行防止を検証する。確認待ちでは権利とダイスの状態を変更しないことを確認する。
- ブラウザーではA/B、特に縦長の狭いB、リサイズ・固定倍率変更で権利表示と2ボタンの実寸、文言・アイコン、押しやすさ、確認操作とロール再開を確認する。既存パレット検証を再利用・必要に応じて拡張する。
- オーナー検証は一意のID、確認理由、操作手順、期待結果、確認バージョンを付けて実装途中に提示する。未回答を保留と扱わない。
- 実装終了草案の前に`npm.cmd test`と`npm.cmd run build`を実行し、結果を記録する。
