# v0.27 実機検証用の GitHub Pages 公開

- 開発ブランチ: `feature/v0.27-device-test-pages`
- 予定バージョン: `0.27.0`。実装フェーズ開始時に `package.json` と `package-lock.json` を更新する。
- 対応項目: バックログ「実機検証用の GitHub Pages 公開」。

## 開発範囲

- `master` への push で起動する GitHub Actions を追加し、テストと本番ビルドに成功した `dist/` を GitHub Pages に配信する。
- GitHub のリポジトリで Pages の利用可否と公開元設定を確認する。公開元には GitHub Actions を使用する。設定変更に必要な権限がない場合は、必要な操作をオーナーに伝える。
- Vite の `/MyPalette/` と既存の本番ビルドを使用する。検証 URL と確認手順を開発文書に記載する。

## 対象外

正式リリース、ポータル登録、ゲームルールや UI の変更。

## 実装方針

- CI では MyPalette と公開済みの `T-I-Oak/GameWorksOAK` の `master` を checkout し、隣接リポジトリを参照する既存の相対 import が解決するように配置する。
- `package.json` の要件を満たす Node.js と npm を使い、`npm ci`、`npm test`、`npm run build` の順に実行する。成功したビルドの `dist/` を Pages アーティファクトとしてアップロードし、デプロイジョブで配信する。デプロイジョブに Pages 書き込み権限と OIDC トークン発行権限を付与する。
- ゲームは既存の静的設定 `data/cards.json` を使用する。公開先の起動や操作がローカル開発用の保存 API に依存しないことを確認する。

## 検証と完了条件

1. マージ前に全テストと本番ビルドを実行する。本番プレビューの `/MyPalette/` で既存の `scripts/checkProductionStartup.cjs` を実行し、静的設定・画像・スクリプトが読み込まれ、タイトルからゲームを開始できることを確認する。
2. レビューでマージと push の承認を得る。マージ着手前と push 直前に共通ライブラリの公開状態を確認する。push 後に対象コミットの Actions が自動起動し、テスト・ビルド・Pages デプロイに成功したことを確認する。
3. Actions が示した公開 URL を実機のブラウザーで開く。タイトルで `0.27.0` の表示を確認し、「ゲーム開始」から「今日の仕事を始める」へ進み、初日のドローとダイスロールの結果を確認する。実機とブラウザー、公開 URL、実行結果を記録する。手元で実機を操作できない場合はオーナーに手順を提示し、確認結果を受け取る。

自動配信と実機確認は `master` への push 後に成立する。マージ前のレビューで公開確認済みとは扱わず、実機確認が残る間はバックログを維持する。
