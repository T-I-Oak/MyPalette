# 評価用ゲームの開発計画

## 1. 目的と合意内容

カード＆ダイスゲームとしての成立性と、選択の面白さ・バランスを実プレイで評価できるようにする。
保存済み45枚のカード設定を使い、最小限のUIで開始から終了まで一局を遊べるものを作る。

- 対象バックログ: 「1. ゲームの評価」。本計画では遊べる評価用ゲームと評価記録を対象とする。
- ブランチ: `feature/v0.3-playable-evaluation`。
- 初回実装バージョン: `0.3.0`。計画では現在の `0.2.26` を変更しない。
- 開発範囲・対象外・完了条件・バージョン・ブランチ名はオーナー合意済み。

## 2. 現状と参照仕様

- 起動時は保存済み `public/data/cards.json` を読み、カード設定エディターを開く。
- 保存済み設定は45枚・135ステップすべてに目標があり、全15種類の効果を使用している。
- カード設定・検証・表示・目標のAND/OR分割・近似達成確率のコードがある。
- ゲーム進行、実ダイスによる達成判定、効果実行は未実装。
- 既存の仕様テストは設定保存・表示等を確認しており、ゲーム中の効果実行を保証するものではない。

ルールの正本は `docs/requirements/01.game_rules.md`、効果は同フォルダーの
`04.effect_conventions.md`、`06.dice_effects.md`、`07.other_effects.md`。
公開情報と操作は `03.information_and_interaction.md`、設定形式は `docs/spec/08.card_editor.md` に従う。
本計画の評価用UIでは情報・操作を優先し、視覚表現・アイコンの本格実装は後続バックログで扱う。
要求仕様はオーナー管理とし、独断で変更しない。仕様の未定義や矛盾が実装判断を左右する場合は確認する。

## 3. 開発範囲

### ゲーム進行

- 初期永続ダイス3個の生成、グレード別シャッフル、初期デッキ7枚、公開ストック、信用・チラシの初期化。
- ターン開始時の未使用化、リロール権獲得、ドロー、ロール、予約効果の解決。
- 手札のプレイ、プレイ時効果、未使用ダイスを選ぶ達成、達成時効果、ステップ更新、捨て札・出荷。
- 出荷による信用増加、3枚ごとの永続ダイス獲得。
- リロール権による1個または全未使用ダイスのリロール。
- 手札2枚以上・達成可能な場札がある場合のプレイフェーズ終了禁止。
- ターン終了時の特殊面予約、チラシ制作と自動発注、信用更新、終了判定、クリーンナップ、ストック更新。
- デッキ不足時の捨て札再シャッフル、ストック枯渇、一時ダイスの消去。

### 効果と選択

- 全15種類の効果と特殊面10種類を実行し、カード設定の配列順を保持する。
- 通常ダイス獲得の3候補生成・選択、色指定・画材指定ダイス、永続・一時の区別。
- 即時リロール、面変更、破棄、名声変更、ドロー、ストック取得、手札ステップ変更、手札交換、特殊面の即時適用。
- 選択が必要な効果では処理を一時停止し、有効な対象の選択後に続行する。
- 消費と破棄を区別し、消費済みダイスは達成・リロール・面変更・特殊面即時適用から除外する。
- 特殊面の即時適用は発動時の対象を固定し、規定順で処理する。新規獲得ダイスを追加対象にしない。
- 対象不足・対象なしの場合は各ルールに従って処理を完了し、選択待ちで停止しない。

### 評価用UIと設定

- ゲーム開始と既存エディターへの入口を用意する。保存済み設定を新規ゲームで利用する。
- 制作途中の目標・効果など、プレイに必要な設定の欠落は開始前にカードID・ステップ・理由を示す。
- 設定を自動補完せず、ゲーム中のカードステップ・面変更は設定の正本へ書き込まない。
- テキスト・ボタン中心で、日数、名声、信用、チラシ、リロール権、各カード領域と枚数を確認できるようにする。
- カードの現在ステップ・目標・効果、公開ストック、出荷済み作品、ダイスの現在面・6面・所持期間・消費状態を確認できるようにする。
- 達成可能な場札を示し、使用ダイスや効果対象をプレイヤーが選択できるようにする。
- 操作結果、チラシ処理、信用減少などを確認できる簡潔な進行記録を表示する。
- 終了時に日数・名声・出荷数を表示し、再プレイできるようにする。
- 既存エディターの保存・検証・確率表示を維持し、設定を調整して再評価できるようにする。

## 4. 対象外

- アトリエの本格的な見た目、正式な効果アイコン、物理ダイス演出、アニメーション。
- モバイル向け最適化、レスポンシブUIの本格設計。
- ランキング、アチーブメント、ギャラリー、過去の自己記録の永続保存・比較。
- プレイ途中の保存・復元、自動プレイによるバランス最適化。
- カード設定値やゲームルールの自動調整、公開・デプロイ設定。

面白さや適切な難易度そのものをテスト成功だけで確定しない。
実プレイで判明した調整課題は記録し、追加変更は合意した範囲と照合する。

## 5. 実装方針

- ゲーム状態・進行、ダイス、達成判定、効果解決、画面操作を責務ごとに分ける。1ファイル500行以内を守る。
- カード定義とプレイ中の状態を分離する。カード・ダイスの識別子により対象と移動を追跡する。
- 状態遷移と選択待ちを明示し、効果解決中に無関係な操作が割り込まないようにする。
- 同じ獲得・ドロー・ストック取得等は通常進行と効果実行で共有する。
- 乱数源を差し替え可能にし、シャッフル・面生成・ロールを再現して検証できるようにする。
- 実ゲームの達成判定は、現在面と未使用状態を使い、AND内は異なるダイスを割り当て、ORのいずれかを満たすか判定する。
- 既存の近似達成確率を実ゲームの判定として利用しない。既存の目標分割・ラベル等は適用可能な部分を再利用する。
- 状態管理・達成判定・効果連鎖はTDDで進める。
- 実装仕様を `docs/spec/` に記載し、開発案内とバックログを実態に合わせる。
- 共通リポジトリは参照専用とし、必要な共通変更はオーナーに報告する。

## 6. 検証方針

### 自動検証

- 初期ダイスの各色1面・各画材2面・全18組合せの網羅、および通常ダイス候補の全18組合せ配分を確認する。
- 初期配置、ドロー再構成、各領域のカード移動、ステップ・出荷・信用・獲得報酬を確認する。
- AND/OR、重複条件、特殊面、消費済み除外、ダイス選択の不正・重複を含めて達成判定を確認する。
- リロール権と即時リロールの対象・消費規則、面変更の永続性、破棄の対象範囲を確認する。
- 全15効果、複数効果の順序、選択待ちからの再開、対象不足、手札交換の空ストックを確認する。
- 特殊面の対象固定・予約・翌ターン解決、一時ダイス消去、発注必要枚数、チラシ進捗持越し、信用0終了を確認する。
- 固定した乱数と操作列で複数ターンから終了までの結合テストを行い、カードやダイスの重複・欠落を確認する。
- 仕様テストは要求仕様の章に対応して `tests/spec/`、実装単体テストは `tests/implementation/` に配置する。
- 変更対象のテストを随時実行し、終了草案前に `npm.cmd test` と `npm.cmd run build` を実行する。
- ブラウザで開始、主要選択、ターン終了、結果、再プレイ、エディターとの往復を確認し、表示と状態の一致・実行時エラーを確認する。

### オーナーによる実プレイ

確認可能な実装ができた時点で、以下の単位を基本に一意の検証ID・理由・操作手順・期待結果・確認バージョンを提示する。

- 一局を操作し、必要な情報を確認しながら終了・再プレイできること。
- 達成時の使用ダイスや効果の対象・獲得候補を意図どおり選択できること。
- プレイで感じた選択の意味、進行の停滞、信用減少や獲得報酬の分かりやすさについて評価を記録すること。
- 保存したカード設定をゲームへ反映し、調整後に再評価できること。

実装報告には各検証項目の判断・フィードバック・対応を記録する。
未回答や未対応の項目を残して終了草案を提示しない。保留はオーナーが明示した項目だけとする。

## 7. 完了条件と成果物

- 合意したゲーム進行と全効果を備え、保存済み設定で開始から終了まで実際に遊べる。
- 公開情報と選択・処理結果を確認でき、終了時の結果表示と再プレイができる。
- 制作途中の設定を開始前に説明し、既存エディターの機能を維持する。
- 主要ルールと全効果の対象テスト、全テスト、本番ビルドが成功する。
- オーナーの実プレイ判断と対応、調整課題が記録されている。
- 実装仕様・開発案内・バックログ、および実装報告に結果と検証根拠が記載されている。

実装報告は `phase_feature_v0.3-playable-evaluation_implementation.md`、レビュー報告は
`phase_feature_v0.3-playable-evaluation_review.md` とする。
引継ぎ書は `phase_handover.md` のみを正本とし、承認された草案だけを保存する。
